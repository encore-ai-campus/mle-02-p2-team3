- A는 제목이 "카드 상품의 비교·분석과 정확한 정보 제공을 위한 GraphRAG"로, 활용처를 ① 고객 안내 ② 상품 비교·분석 ③ 상품 품질 개선 ④ 조건 변경 영향으로 나눈다.

## 4. 현재 진행 상태 (발표 문구의 기준)

**범위 주의:** 아래 표는 **우리 `file_pipeline`(결과 A)** 기준이다. 팀의 `db_pipeline`(결과 B, 김병주)은 별도 구현이며 이 표에 상태를 적지 않았다(프로젝트 지도 방침, 요청 전 읽지 않음). B의 알려진 사실은 `main` 문서 한 건(구조·데이터 비교, 2026-11-03 스냅샷)에서만 확인했다: PostgreSQL→Neo4j `dp_` 그래프 적재, 공통 노드 200·관계 263 일치, 실제 Neo4j+Mock LLM 통합 테스트 7건 통과. 두 파이프라인 수치를 한 문장에 섞지 않는다.

**접근 한계:** 이 표가 인용하는 `프로젝트-지도.md`·`PPT지침.md`는 우리 브랜치에만 있고 `main`에 없다. `품질/챗봇-품질.md`·`결정/README.md`는 아직 커밋되지 않았다. 24문항 점수는 `/tmp` 결과 파일 재채점 값이라 팀원이 `main`에서 재현할 수 없다.

현황 장에 넣을 문구 예: "하나·우리 추출 전체 실행 완료(성공 998/1,032), 추출분은 Supabase에 적재. 이미지 문서 45개와 실패 청크는 미반영. 답변은 24문항 자동 시험을 진행했고 사람이 확정한 정확도는 아직 없음."

## 7. 팀에 먼저 확인할 질문

1. 발표 범위에 카드 비교·상품 품질 개선·조건 변경 영향을 포함할까, 고객 안내만 다룰까? (`PPT지침.md` 7절 미해결 항목과 동일)
2. 24문항 자동 시험과 골든셋 v1의 사람 검수 미완료 상태를 어느 수준의 결과로 발표할까?
3. 본문에서 Neo4j를 언급하면 "로컬 시각화용"이라고 밝힐까?
4. 발표 시점에 이미지 문서 45개(OCR)와 실패 청크 24개를 처리해 둘까, 한계로 둘까?
5. 발표의 "현재 구현"은 어느 파이프라인을 기준으로 말할까? 결과 A(file_pipeline, Supabase fp_*)와 결과 B(db_pipeline, PostgreSQL→Neo4j)는 8단계 비교 전이라 하나의 시스템으로 합쳐 말하면 안 된다.
6. 현황 슬라이드를 **코드 구현 / 개발 데이터 시험 / 원문 대조 / 운영 여부**로 나눠 표기할까? (외부 검토 제안, §9)

## 8. 확인하지 못한 것

- 슬라이드의 시각적 완성도, 5초 테스트, 발표 시간(둘 다 지침상 미측정).
- 골든셋 CSV의 실제 문항 수(품질 문서의 80문항 기록은 직접 확인하지 못함).
- B2 5쪽 이후 PDF 추출 성능이 달라졌는지.
- 신한 보도자료 두 건은 B 부록의 2026-10-30 재확인 기록과 Codex 확인에 의존한다. 이번 세션에서 원문 URL을 직접 열어 보지는 않았다.
- 프로젝트 지도 수치는 문서에 적힌 값이며 이번에 DB를 다시 조회하지 않았다.

## 9. 외부(GPT) 검토 반영 기록

작성 후 사용자가 GPT 검토 결과를 전달했다. 입력은 `main`의 문서·코드와 첨부 PPT이며, 아래는 직접 대조한 결과다.

| GPT 지적 | 확인 | 반영 |
|---|---|---|
| 2차 초안 뼈대 + 현황 최신화 방향은 합리적 | 동의 | 유지 |
| 첨부 PPT 현황 장이 낡음 | 동의(첫 초안 24장 확인) | 유지 |
| 인용 문서가 `main`에 없어 재현 불가 | **사실.** 지도·PPT지침은 브랜치만, 품질·결정은 미커밋 | §4 접근 한계 추가. 팀 공유 전 커밋 필요 |
| PostgreSQL/Neo4j를 한 시스템처럼 합치면 경계가 흐려짐 | **맞음. 초판의 A 6쪽 "과장" 판정은 오류** | 5.1 6쪽 정정, §4 범위 주의, §7 질문 5 |
| 24문항·8/12·6/12가 `main` 근거와 안 이어짐 | 사실. 로컬 결과 파일 기반 | 팀에 보이려면 결과 요약을 커밋하거나 "자동 판정, 로컬 시험"으로 한정 |
| GraphRAG 우위 입증 안 됨 | 동의. 지침 §4·B 9쪽도 단정하지 않음 | 변경 없음 |
| 현황 슬라이드를 코드/개발 데이터/원문 대조/운영으로 분리 | 타당한 제안 | §7 질문 6 |
| 카드 비교·품질·변경 영향은 검토 방향으로 | 본 문서 결론과 일치 | 변경 없음 |
| 아키텍처 문서(Neo4j 향후)와 후속 문서(적재·시험)가 엇갈림 | **미검증.** `architecture.md`, `db_pipeline/PROJECT_STATUS.md`는 이번에 열지 않음(`db_pipeline`은 요청 전 읽지 않는 원칙) | 발표 전 기준 시점 정리 필요, 열려 있음 |

확인하지 않은 GPT 주장: `test_results.md`의 REVIEW 판정 내용, 2차 초안 시각 디자인(GPT도 검토 못 했다고 밝힘).
