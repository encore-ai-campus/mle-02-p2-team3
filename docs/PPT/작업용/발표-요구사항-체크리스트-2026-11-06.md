## 2. 발표 순서(가이드 6단계)와 본문 12쪽 배치안

가이드 순서: 주제·데이터 → 스키마 → 추출 → 정규화 → 그래프 → 검증·회고. 전원이 자기 담당 구간과 앞뒤 연결을 설명하고, 문서·청크·개체 ID로 같은 정보가 단계별로 어떻게 바뀌는지 보여 준다.

| 가이드 단계 | 본문 쪽(배치안) | 현재 덱 근거 | 담당 |
|---|---|---|---|
| 1 주제·데이터 | 1~4쪽(표지, 사례, 적용 범위) + 문서 선정 이유·범위 | 기존 1~4쪽 유지, 제목에 하나·우리 반영 | 사용자 |
| 2 스키마 | 5·6쪽(PDF 추출 검증, 해결 구조) | 노드 허용 6종(일반 export 생성 5종)·관계 6종(`docs/설계/지식그래프.md`) | 사용자 |
| 3 추출 | 5쪽 보강 + 실제 프롬프트·입출력 예시(부록 또는 본문) | 프롬프트 포함 여부 미확인 | 사용자 |
| 4 정규화 | **신규 1쪽** | 엔티티 연결 56그룹·73매핑, 삭제 없이 연결(D5, 챗봇 적용은 기본 꺼짐), 챗봇 영향 질문 2.5%(80문항 **근사 시뮬레이션**, 실제 영향은 다를 수 있음) | 사용자 |
| 5 그래프 | 7쪽 사용 장면 + Neo4j·Cypher·시각화 화면 | 로컬 Neo4j(`Fp` 라벨 샘플). **현재 그래프를 올리는 작업이 먼저 필요**(7절) | 사용자 |
| 6 검증·회고 | 평가 결과 1쪽(10쪽 교체) + **신규 실패 분석 1쪽** + **신규 회고(KPT) 1쪽** + 결론 | 골든셋 v2 결과(작업표 3절) | 사용자 |

- 부록으로 이동: 변경 영향(8쪽), 기술 선택(9쪽), MCP(11쪽). 본문은 9쪽 + 신규 3쪽 = 12쪽, 발표 약 14분이면 쪽당 약 1.2분.
- 담당: **사용자 한 명 중심으로 진행**(2026-11-06 사용자 결정). 다른 팀원이 설명할 구간이 있으면 사용자가 나중에 알려 준다. 가이드의 '전원이 자기 구간을 설명' 요구와 어긋날 수 있어 리허설 때 다시 확인한다.

## 4. 수치 표기 규칙 (가이드 M8)

- 정답 라벨 없이 추출 정확도·성공률을 임의로 제시하지 않는다. 수치를 보고하면 **정답 기준·표본 수·계산 방법**을 함께 적는다.
- 78.0%(32/41) 병기 문구: 정답 기준 = 사람이 PDF 원문에서 작성한 골든셋 기대 사실, 표본 = dev 41문항 × 3회, 계산 = 문항 내 모든 사실 일치 비율, 판정 = AI(규칙 + LLM), 사람 확정 = SHOPPER 4개 혜택.
- 78.0%는 **챗봇 답변 정확도**이며 추출 정확도가 아니다. 74.8%(83/111)는 답변 가능 37문항 기준의 별도 값이라 합치지 않는다.
- 검증 기록에는 검토 대상 선정 기준과 검토 건수를 적고, 발견한 오류의 원인·조치·재확인 결과를 남긴다.

### 발표 6단계에서 비어 있는 곳 (Codex 지적, 직접 확인 포함)

1. **그래프**: 적재는 끝났다(노드 12,144·관계 15,697 일치). 남은 것은 시연 쿼리 실행 화면 캡처와 런북 6절 갱신.
2. **주제·데이터**: 카드 문서의 선정 이유·출처·버전·활용 범위를 한데 보이는 근거가 없다.
3. **검증·회고**: 정량 검증은 Supabase 챗봇 답변 평가뿐이다. 원문–트리플–정규화–그래프(Neo4j) 대조 결과는 없다. 가이드 M8 검증 기록(표본 선정 기준·검토 건수·오류 원인과 조치)을 SHOPPER 대조 등으로 채운다.
