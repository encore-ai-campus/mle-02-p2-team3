# 우리카드 Manifest 보완 계획

> **수행 안내:** 구현 시 작업을 순서대로 진행하고 각 단계의 체크 항목과 검증 결과를 기록한다. 하나카드 데이터와 원본 ZIP은 수정하지 않는다.

**목표:** 하나카드 manifest의 공통 필드·코드값을 기준으로 우리카드 ZIP의 PDF 108건을 출처와 검수 상태가 명확한 manifest 행으로 완성한다.

**접근:** 현재 통합 초안의 우리카드 108행만 보완한다. 기존 하나카드 217행과 우리카드 최소 manifest는 보존한다. PDF 목록·해시·페이지 수는 이미 검증되었으므로 재작업하지 않고, 상품명·문서 종류·공식 출처·날짜의 근거를 보강한다. 확인되지 않은 값은 추정하지 않고 미확인 상태로 남긴다.

**기술:** CSV, ZIP, SHA-256, PDF 텍스트 확인. 저장소의 Python 3.12 및 기존 PyMuPDF 사용. 새 패키지·DB 접속·Supabase 변경은 없다.

**기준 자료:** `src/card_benefit/data/metadata/manifest_hana_woori.csv`, `src/card_benefit/data/metadata/manifest_woori_minimal.csv`, `src/data/woori_all/woori_all-20261031T142529Z-1-001.zip`, 하나카드 manifest의 필드와 코드값.

## 현재 확인 결과와 병목

- 통합 초안은 하나카드 217행, 우리카드 108행이다. 우리카드 행은 모두 `CREDIT`이며 ZIP 내부 경로·SHA-256·페이지 수가 채워져 있다.
- ZIP과 manifest를 읽기 전용으로 대조한 결과 우리카드 108개 경로가 모두 존재하고, PDF 열기·해시·페이지 수 불일치는 0건이다.
- 우리카드 `PRODUCT_GUIDE_CANDIDATE` 87건은 문서 종류 확정이 남았고, `UNKNOWN` 21건은 문서 종류 자체를 분류해야 한다.
- 우리카드 108건 모두 상품명·공식 URL·효력일·수집일이 비어 있고, 공식성은 `UNKNOWN`, 검수 상태는 `NEEDS_REVIEW`다.
- 우리카드에서 같은 SHA-256을 가진 파일이 5개 해시 그룹(추가 파일 6건) 발견됐다. 파일명과 ZIP 위치가 다른 행은 삭제하지 않고 별도 원본 항목으로 보존해야 한다.
- 하나카드 기준 자체도 검토 상태지만, 이번 범위에서는 하나카드 행을 재검수하거나 수정하지 않는다. 기존 값은 형식 기준으로만 사용한다.

## 범위와 완료 상태

포함: 우리카드 108개 PDF의 분류·상품명·공식 출처 조사, 날짜 근거 확인, 공통 필드 정합성, 미확인 항목 보고.

제외: 하나카드 행 수정, ZIP·PDF 수정/압축 해제본 저장, DB 적재, 임베딩, 혜택 추출, 약관·웹 변환본 등 별도 데이터 수집.

완료는 모든 필드가 억지로 채워졌다는 뜻이 아니다. 확인 가능한 값은 근거와 함께 확정하고, 공개 출처나 문서 근거가 없는 값은 빈 값 또는 `UNKNOWN` 및 구체적인 `review_note`로 남긴 상태를 뜻한다.

## 공통 데이터 규칙

- 통합 초안의 19개 컬럼과 기존 Hana 코드값을 유지한다. 컬럼을 추가·삭제하거나 Hana 값을 다시 정규화하지 않는다.
- 문서 종류는 Hana에서 쓰는 `PRODUCT_GUIDE`, `WEB_CAPTURE`, `BRAND_GUIDE`, `TERMS`, `UNKNOWN` 중 근거가 있는 값만 사용한다. `PRODUCT_GUIDE_CANDIDATE`는 최종 분류 전 상태로만 사용한다.
- 공식 URL은 카드사 공식 페이지 또는 공식 PDF에서 확인한 주소만 기록한다. 파일명으로 URL을 조합한 값은 공식 확인 전까지 확정하지 않는다.
- `effective_date`는 문서에서 효력일로 명시한 날짜만 기록한다. 파일명에 포함된 날짜나 개정 표기는 효력일로 간주하지 않는다.
- `collected_at`은 실제 수집 시각의 근거가 있을 때만 기록한다. ZIP 파일 생성 시각을 개별 PDF 수집 시각으로 복사하지 않는다.
- 해시가 같더라도 서로 다른 ZIP 경로·파일명은 보존한다. 내용 중복은 `review_note` 또는 검수 결과로 표시한다.
- 공식 출처를 확인하지 못한 경우 `official_verification=UNKNOWN` 또는 기존 코드 중 의미가 맞는 미확정 상태를 유지하고 사유를 기록한다.

## 주요 위험과 검토 초점

1. PDF가 상품안내장 후보가 아니거나 공동·브랜드 안내 문서일 수 있다. 첫 페이지 제목과 본문으로 분류하고, 애매하면 `UNKNOWN`으로 둔다.
2. 파일명 날짜가 출시일·개정일·수집일·효력일 중 무엇인지 보장하지 않는다. 문서 내부 근거가 없으면 날짜를 채우지 않는다.
3. 공식 URL을 추정해 넣으면 출처 신뢰 상태가 왜곡된다. 공식 도메인과 문서 연결이 확인된 경우에만 검증 상태를 바꾼다.
4. 동일 해시 파일은 중복처럼 보여도 서로 다른 문서 출처·파일명을 가질 수 있다. 원본 항목을 합치거나 삭제하지 않는다.
5. 하나카드 행이 바뀌면 이번 작업 범위가 침범된 것이다. 수정 전후 하나카드 행을 비교해 변경이 0건인지 확인한다.

- [ ] 87개 상품설명서 후보를 문서 제목으로 확인해 `PRODUCT_GUIDE` 또는 근거 있는 다른 코드로 분류한다.

**완료 조건:** 108개 모두에 문서 제목 기반의 상품명 또는 미확인 사유가 있고, 문서 종류 미확인 행은 목록으로 별도 집계돼 있다.

### 작업 3: 공식 출처와 날짜 근거 확인

**파일:**
- 수정 대상(우리카드 행만): `src/card_benefit/data/metadata/manifest_hana_woori.csv`
- 검수 기록: `src/card_benefit/data/metadata/woori_manifest_review.md`

- [ ] 각 문서의 공식 URL을 우리카드 공식 페이지·공식 PDF 등 출처와 연결해 확인한다.
- [ ] 확인된 URL의 출처 유형에 맞춰 `source_kind`, `official_verification`, `source_url`을 Hana 기준과 일치하게 기록한다.
- [ ] 공식 출처를 찾지 못한 문서는 URL을 추측해 넣지 않고 미확인 상태와 다음 확인 방법을 기록한다.

**완료 조건:** 모든 기입된 공식 URL·효력일·수집일에 추적 가능한 근거가 있고, 미확인 값에는 상태와 사유가 남아 있다.
