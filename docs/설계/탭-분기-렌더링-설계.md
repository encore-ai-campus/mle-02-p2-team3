# 팀 화면 탭 분기·렌더링 설계 (file_pipeline 쪽)

- 상태: 초안 (2026-11-06). P1(render 추출)과 P2(키 접두어, 사이드바 이동)는 구현·테스트 완료(`chat/ui/app_v2.py`), P3~P5는 아직이다. 아래 3.2의 "줄 번호"는 폴더 정리 전 기준이라 파일 이름으로만 읽는다.
- 범위: 팀 Streamlit 앱의 탭(또는 좌우 분할)에서 `file_pipeline` 챗봇 화면을 부르는 방법. 로직(`rag`, `fp_chat_patch`, `answer/` 등)은 바꾸지 않고 화면 진입 방식만 바꾼다.
- 하지 않은 것: `db_pipeline`과 팀 탭 앱은 읽지 않았다(독립 작업). 호스트 쪽 사정은 아래 "호스트가 정할 것"으로 남긴다.
- 근거 표기: **확인** = 이 저장소 코드를 직접 읽음, **추정** = 읽은 코드에서 도출했으나 실행 검증 안 함.

## 1. 목표

호스트(팀 앱)가 아래 세 줄만으로 우리 화면을 탭 안에 띄운다.

```python
from payment_card.file_pipeline.chat.panel import prepare_backend, render

if prepare_backend():          # 키·DB 설정이 없으면 화면에 안내를 그리고 False
    render(key_prefix="fp")    # 호출마다 서로 다른 key_prefix
```

- 호스트는 우리 내부 모듈(`rag`, `ui_v2`, `fp_chat_patch` 등)을 직접 임포트하지 않는다.
- 단독 실행(`run_fp_chat_v2.py`)은 지금처럼 계속 된다.

## 2. 현재 구조 (확인)

| 위치 | 현재 동작 | 탭에 넣을 때의 문제 |
|---|---|---|
| `chat/ui/app_v2.py` 상단(sys.path 삽입과 `import rag`, `from ui import ui_v2`) | 임포트 시 `sys.path`에 `src/graphrag_chatbot`, `chat/`를 넣고 `import rag`, `import ui_v2` | 호스트 프로세스의 임포트 경로와 모듈 이름(`rag`)을 바꾼다 |
| `app_v2.py` 최상위 | `st.set_page_config(layout="centered")`를 최상위에서 호출 | 앱 전체 설정이라 호스트와 충돌, 한 앱에서 한 번만 의미 있음 |
| `app_v2.py` 최상위 | `st.session_state`에 `v2_conversations`, `v2_current`, `v2_developer_mode` 초기화 | 접두어가 `v2_`로 고정이라 두 번 렌더하면 상태 공유 |
| `app_v2.py` 하단 | `with st.sidebar:` 안에 "새 대화", "개발자 모드" | 사이드바는 앱 공용이라 탭 안에 들어가지 않음 |
| `app_v2.py` 하단 | 제목, 예시 버튼(`key=v2_example_i`), `st.chat_input`(키 없음), 턴 실행, `st.rerun()` 두 곳 | 입력·버튼 키 충돌, 전체 앱 재실행 |
| `run_fp_chat_v2.py` | `.env` 로드, `install()`, `apply()`로 OpenAI·GraphRAG 어댑터 적용 후 `runpy`로 `app_v2.py` 실행 | 호스트가 import할 접점이 아님. 키가 없으면 `st.stop()` |

- 화면에는 `render()` 같은 공개 함수가 없다(확인).
- `app_v2.py`의 제목은 인라인 스타일만 쓰고 전역 CSS를 주입하지 않는다(확인). 구버전 `src/graphrag_chatbot/app.py`는 전역 CSS를 주입하므로 탭 통합 대상에서 제외한다.

## 3. 설계

### 3.1 공개 접점 두 개 (Facade)

새 모듈 `chat/panel.py`가 아래 둘만 공개한다. 이름은 팀과 합의 대상이다.

| 함수 | 역할 |
|---|---|
| `prepare_backend() -> bool` | `.env` 로드, 키 확인, `install()`·`apply()`를 **프로세스당 한 번** 실행(멱등). 설정이 없으면 `st.error`로 안내하고 `False` |
| `render(*, key_prefix: str) -> None` | 화면 본문만 그린다. 페이지 설정과 사이드바를 건드리지 않는다 |

- `prepare_backend()`의 한 번 실행은 `st.cache_resource` 또는 모듈 플래그로 보장한다(구현 시 선택).
- 단독 실행 `run_fp_chat_v2.py`는 `set_page_config` → `prepare_backend()` → `render(key_prefix="standalone")`로 줄인다.

### 3.2 `app_v2.py`의 변경 범위

- 최상위 부수효과(`set_page_config`, 세션 초기화, 화면 그리기)를 `render()` 안으로 옮긴다. 헬퍼 함수(`_render_turn`, `_run_turn` 등)와 로직은 그대로 둔다.
- `render()` 안에서 `ss = st.session_state`를 얻고 키 헬퍼로 초기화한다.
- `app_v2.py`는 2026-11-06 폴더 정리 U 단계로 `chat/ui/`에 있다. 이 설계의 경로는 모두 그 위치 기준이다.

### 3.3 키 네임스페이스

모든 상태·위젯 키를 헬퍼 하나로 만든다. 문자열을 코드에 흩뿌리지 않는다.

```python
def _k(prefix: str, name: str) -> str:
    return f"{prefix}:{name}"
```

| 현재 키 | 변경 |
|---|---|
| `v2_conversations`, `v2_current`, `v2_developer_mode`, `v2_pending_question` | `_k(prefix, "conversations")` 등 |
| `v2_example_{i}` | `_k(prefix, f"example_{i}")` |
| "새 대화" 버튼, `st.chat_input` (키 없음) | `key=_k(prefix, "new_chat")`, `key=_k(prefix, "chat_input")` |

- 같은 화면에서 두 번 부를 때는 `key_prefix`가 서로 달라야 한다. 같은 접두어를 두 번 쓰면 헬퍼가 구분해 주지 못한다.

### 3.4 사이드바·전역 설정은 호스트 소유

- "새 대화"와 "개발자 모드"는 사이드바에서 `render()` 안의 `st.container`/`st.expander`(탭 상단)로 옮긴다.
- `set_page_config`와 레이아웃(`centered`/`wide`)은 호스트가 정한다. 단독 실행일 때만 우리가 호출한다.

### 3.5 재실행(`st.rerun`)

- 현재 두 곳의 `st.rerun()`은 `render()`를 부른 탭만이 아니라 **앱 전체 스크립트**를 다시 실행한다(추정, Streamlit 동작 기준). 호스트의 다른 탭도 재평가된다.
- 1차 설계는 그대로 두고 호스트에 알린다. 불편하면 `@st.fragment`로 범위를 좁히는 방법이 후보다(해당 버전에서의 동작은 **검증 필요**).

## 4. 부딪힐 위험과 대응

| 위험 | 근거 | 대응 |
|---|---|---|
| `sys.path`에 `src/graphrag_chatbot`이 들어가 `rag`, `llm`, `db` 같은 일반 이름이 호스트 프로세스에 생김 | 확인: `app_v2.py:15-22`, `run_fp_chat_v2.py` | 호스트가 같은 이름의 모듈을 쓰는지 확인해야 함. 쓰면 충돌 → 이름 변경 또는 별도 프로세스 검토 |
| `openai_llm_patch.install()`이 전역 `sys.modules["llm"]`를 교체 | Codex 읽기 전용 진단(보고서)에서 지적, 이 저장소 코드 줄 번호는 `openai_llm_patch.py` | 호스트의 다른 탭이 `llm`을 쓰면 영향. 호스트와 합의 필요 |
| 임포트 순서: 어댑터 적용 전에 `app_v2`를 임포트하면 팀 `rag`의 LLM 임포트 경로에 걸림 | Codex 진단 | `prepare_backend()`가 먼저 실행되고 `render()` 안에서 지연 임포트 |
| `.env`에만 둔 `LLM_MODEL`이 적용되지 않을 수 있음(`load_dotenv()`가 `llm` 임포트 뒤) | Codex 설계 검토, 코드 순서 해석이고 실행 검증 안 함 | 이번 범위 밖. 구버전 `rag.py` 관련. 알려만 둠 |
| `st.chat_input`의 탭 안 위치 | Streamlit 1.65 문서상 inline 배치 가능(Codex 확인), 실제 위치는 브라우저 확인 필요 | 브라우저 점검 항목 |
| 그래프 iframe(`components.html`/`st.iframe`)에 키가 없고 높이가 고정 | Codex 설계 검토(구버전 `graphrag-chatbot` 기준) | v2 화면의 그래프 렌더 방식은 구현 시 다시 확인 |
| 패키징: 루트 `pyproject.toml`의 wheel 목록에 `file_pipeline`이 없음 | Codex 진단 | 소스 경로를 `PYTHONPATH`로 쓰는 실행만 가정. wheel 배포가 필요하면 별도 작업 |

## 5. 검증 계획

Streamlit은 `uv.lock` 기준 1.65.0이라 `streamlit.testing.v1.AppTest`를 쓸 수 있다(Codex 보고, 이 PC에서 실행으로 확인하지 않음). 외부 호출(DB·LLM)은 스텁으로 막는다.

| 검증 | 방법 |
|---|---|
| 임포트 부수효과 없음 | 다른 폴더에서 `panel`을 임포트해도 화면이 그려지지 않고 `set_page_config`가 호출되지 않음 |
| 두 번 렌더 키 충돌 없음 | `AppTest.from_function`으로 `render(key_prefix="a")`, `render(key_prefix="b")`를 한 앱에서 호출, 예외 0건, 위젯 키가 서로 다름 |
| 같은 접두어 오용 감지 | 접두어 중복 시 Streamlit이 중복 키 예외를 내는지 확인(문서화용) |
| 단독 실행 유지 | `run_fp_chat_v2.py` 경로의 임포트와 기존 테스트(`test_file_pipeline_chat_ui_v2.py` 등) 통과 |
| 기존 테스트 | 정리 후 관련 테스트 세트(현재 391개 통과 기준) 유지 |
| 브라우저 확인(사람) | 탭 안에서 질문 입력 위치, 그래프 높이, 다른 탭 영향. 제가 화면을 실행하지 않으므로 사용자가 확인 |

| 단계 | 바꾸는 파일 | 검증 |
|---|---|---|
| P1 | `app_v2.py`: 화면 본문을 `render(*, key_prefix)`로 감싸고 최상위 부수효과 제거 | 임포트 시 화면 안 그려짐, 기존 테스트 |
| P2 | `app_v2.py`: 키 헬퍼 적용, 사이드바 내용을 본문 컨테이너로 이동 | 두 번 렌더 계약 테스트 |
| P3 | 새 `chat/panel.py`, `run_fp_chat_v2.py`: `prepare_backend()` 추출, 단독 실행을 두 함수 호출로 단순화 | 단독 실행 임포트, 키 없음 경로 |

## 7. 호스트(팀 앱)가 정할 것 / 팀원에게 알릴 것

1. 함수 이름과 인자: `prepare_backend()`, `render(*, key_prefix)`로 괜찮은지.
2. `set_page_config`와 레이아웃은 호스트가 소유한다는 점.
3. `rag`, `llm`, `db` 같은 최상위 모듈 이름을 호스트가 쓰는지, `sys.modules["llm"]` 교체가 괜찮은지.
4. 호스트가 우리 화면을 탭으로 넣는지 좌우 분할로 넣는지. 좌우 분할이면 `centered` 폭이 맞는지.
5. `file_pipeline` 안의 모듈을 직접 임포트하고 있다면 2026-11-06 폴더 정리로 경로가 바뀐 것(예: `chat.answer.*`, `chat.retrieval.*`, `doc_index.traceability`).

## 8. 하지 않을 것

- 로직 리팩터링, 폴더 대이동, 공통 베이스 클래스·플러그인 구조.
- `fp_chat_patch.py` 분해(검색·DB·로그 책임 혼재는 별도 과제).
- DB 연결 통합, 두 파이프라인 공통 계약 확정, 검색 안정성 작업(이 설계와 별개).
- 팀 앱과 `db_pipeline` 코드 읽기.

## 9. 한계

- 실제 Streamlit 화면과 `AppTest`는 이번에 실행하지 않았다. 설계는 코드 읽기와 Codex 읽기 전용 검토 두 건(설계 검토, 설계 문제 진단)에 근거한다.
- Codex 검토 중 `graphrag-chatbot/app.py`(구버전)를 기준으로 한 지적은 v2 화면에 그대로 적용된다고 단정하지 않고, 줄 번호는 v2 코드에서 다시 읽은 것만 확인으로 표시했다.
- 호스트 앱을 보지 않아 연결 비용과 충돌 여부는 확정하지 못했다.
