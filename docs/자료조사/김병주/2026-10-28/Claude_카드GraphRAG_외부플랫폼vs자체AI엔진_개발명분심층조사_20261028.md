## 0. 최종 질문에 대한 답

> **"신한카드는 카카오 같은 외부 플랫폼에 카드 서비스를 제공하면서도, 왜 금융상품 조건을 판단하는 자체 AI 기술을 개발하는가?"**

**신한카드가 공식적으로 밝힌 이유는 두 발표에 따로 있다. 두 발표를 서로 연결해서 설명한 공식 문장은 없다.**

| 구분 | 신한카드가 공식적으로 밝힌 목적 | 출처 |
|---|---|---|
| 외부 플랫폼 연동 (ChatGPT for Kakao, 2026-09-13) | "다양한 AI 플랫폼과 서비스 역량을 연결해 **고객이 원하는 채널에서** 금융 서비스를 쉽게 이용"하도록 **AI 접점을 넓힌다.** 메뉴를 찾아가는 방식에서 대화 속에서 상품을 접하는 경험으로 바꾼다 | [직접 확인] |
| 자체 AI 엔진 (중기부 R&D, 2026-09-09) | **"에이전트 커머스" 시대에 대비해 복잡한 의사결정을 정확하고 안정적으로 지원하는 AI 인프라**를 선제적으로 만든다. 기존 AI는 "확률적 판단에 의존"해 **일관성 부족, 복합 조건 누락, 환각, 정책·규정 미반영** 문제가 있다. 조건을 구조화해 두면 상품·정책·규정이 바뀌어도 "**조건만 수정하면 실시간으로 반영**"된다 | [직접 확인] |

**분석자의 해석 [분석]**: 두 목적은 층위가 다르다. 외부 연동은 **고객 접점(채널)**을 넓히는 일이고, 자체 엔진은 **상품 조건 판단의 정확성·일관성·변경 반영**을 확보하는 일이다. 엔진 발표가 "AI 에이전트가 고객을 대신해 상품을 탐색·비교·선택하는" 환경을 겨냥한다는 점은 **엔진이 여러 접점(외부 에이전트 포함) 뒤에서 판단을 맡는 구조**와 잘 맞는다. **그러나 신한카드가 이 엔진을 카카오 툴과 연결하겠다고 밝힌 자료는 없다.** 또 엔진이 고객용 챗봇인지, 내부 엔진인지, 어느 채널에 적용되는지도 공개되지 않았다.

> **"그 이유가 우리 팀의 카드 GraphRAG 기술검증 프로젝트를 추진할 근거가 될 수 있는가?"**

**문제 정의의 근거는 된다. 기술 선택(GraphRAG)의 근거는 되지 않는다.**
- 신한카드가 해결하려는 문제(카드 조건의 누락·환각·비일관성·규정 변경 반영)는 우리 프로젝트의 문제 정의와 같다 [직접 확인].
- 하지만 신한카드 발표에는 그래프·GraphRAG라는 기술명이 없다. GraphRAG를 명시한 자료는 2024년 TechBlaze 모집공고뿐이고, 대상은 **소비 추천용 고객·가맹점·결제내역 그래프**다.
- 따라서 GraphRAG의 필요성은 **우리 실험(D vs E 비교)으로 따로 증명해야 한다.**

**최종 판단: 조건부 추진** (11-E 참조)

## 3. 가설 검증

### 가설 1. 고객 접점과 판단 엔진의 역할이 다르다

| 항목 | 내용 |
|---|---|
| 실제 산업 사례 | 호주 CBA **Customer Engagement Engine**: 온라인·모바일·콜센터·ATM·지점의 모든 고객 접점이 하나의 엔진을 호출해 "next best conversation"을 받는다. CBA 분석 책임자는 "decision engine sitting on top of [the data layer], orchestrating all of the conversations … across all of the channels"라고 설명 |
| 자료 | Pega 사례 https://www.pega.com/node/65911 , diginomica https://diginomica.com/commonwealth-bank-australia-using-pega-aim-millions-personalized-experiences [검색 요약. 공급사 자료 중심이며 2018~2020년 내용] |
| 확인된 사실 | 신한카드: 외부 연동 목적 = 접점 확대, 엔진 목적 = 판단 정확성 (각각 [직접 확인]) |
| 가능한 기술적 이유 [분석] | 접점은 대화·UI를 맡고, 판단은 규칙과 데이터를 가진 쪽이 맡아야 결과가 일관된다 |
| 근거 없는 추정 | "신한카드 내부 구조가 `카카오 → 신한 API → 판단 엔진`이다" → **근거 없음** |
| 반례·한계 | CBA는 마케팅 대화 결정 엔진이지 약관 조건 판단 엔진이 아니다. 해외 사례이며 국내 제도와 신한카드 의사결정에 그대로 적용할 수 없다 |
| 프로젝트 관계 | "채널과 엔진의 분리"를 **제안 아키텍처**로 설명할 근거 |
| 판정 | **일부 확인** (역할 분리 목적은 신한 공식, 구조는 해외 사례로만 확인) |

### 가설 2. 여러 채널에서 동일한 판단 결과를 재사용한다

## 7. GraphRAG 기술 명분 — 비교 실험

| 방식 | 구성 | 비교 목적 |
|---|---|---|
| A. 일반 ChatGPT | 웹검색 포함, 카드명과 질문만 입력 | 범용 AI 기준선 |
| B. PDF RAG | 같은 PDF 청크 검색 + LLM | 원문 검색 방식 |
| C. SQL + 규칙 엔진 | 조건 테이블 + Python 판정 | 정형 계산 |
| D. SQL + 규칙 엔진 + PDF RAG | C + 원문 인용 | **그래프 없는 결합 (핵심 비교 대상)** |
| E. SQL + 규칙 엔진 + GraphRAG | C + Neo4j 관계 탐색 + 원문 인용 | **그래프를 추가한 결합** |

**공정성 조건 (D vs E)**: 같은 PDF, 같은 추출 결과, 같은 규칙 엔진, 같은 LLM과 프롬프트 골격을 쓴다. 차이는 **관계 탐색 계층 하나**만 둔다.

| 지표 | 정의 | 구분 |
|---|---|---|
| 조건 누락률 | 정답 조건 중 답변에서 빠진 비율 | 필수 |
| 근거 조항 정확도 | PDF 페이지·조항 일치율 | 필수 |
| 잘못된 단정 비율 | 판정할 수 없는데 단정한 비율 | 필수 |
| 복합 조건 정답률 | AND·OR·NOT, 공유 한도, 선택 제약 질문의 정답률 | 추가 |
| 변경 영향 탐색 정확도 | 조건(가상 개정) 하나 변경 시 영향받는 혜택의 재현율·정밀도 | 추가 |
| 잘못된 상품·혜택 연결 비율 | 다른 카드나 혜택의 규칙을 섞은 비율 | 추가 |
| 응답 시간 | 질문당 평균 | 추가 |
| 유지보수 부담 | 규칙 1건 변경 시 수정 지점 수 | 추가 |

**골든 질문**: 25~30개. 정답은 PDF 원문 페이지로만 작성. 유형은 단일 조회, 결제방식 제외, 공유 한도, 할인분 실적 제외, 선택 제약, 다중 카드 비교, 변경 영향.

**결과 해석 규칙 (사전 확정)**

| 결과 | 결론 |
|---|---|
| E > D (누락률·복합 조건·변경 영향에서 유의한 차이) | GraphRAG 실효성의 근거로 보고 |
| E ≈ D | "그래프는 정확도가 아니라 **탐색·설명 표시**에 기여"로 보고. 유지보수 지표만 비교 |
| E < D | 그래프 계층이 오류를 더한 원인(추출 오류, 경로 과잉 등)을 분석해 보고 |
| A가 대부분 정답 | 기술검증의 실익이 낮다는 점을 한계로 보고 |

### D. 강사님 설명 문안

**① 30초 — 카카오가 있는데 왜 개발하는지**

> 카카오 같은 플랫폼은 고객이 카드를 만나는 창구이고, 저희가 만드는 것은 그 뒤에서 카드 조건을 정확하게 판단하는 엔진입니다. 실제로 신한카드도 카카오에 카드 툴을 연동하면서, 별도로 복잡한 상품 조건을 구조화해 판단하는 AI 엔진 개발에 착수했습니다. 저희는 그 판단 엔진 부분을 공개 약관으로 구현하고 검증하려고 합니다.

**② 1분 — 신한카드 사례 포함**

> 신한카드는 올해 9월 13일에 ChatGPT for Kakao에 카드 추천과 혜택 조회 툴을 연동했습니다. 목적은 고객이 원하는 채널에서 서비스를 쓰게 하는 것이라고 밝혔습니다.
>
> 그보다 나흘 앞선 9월 9일에는 금융상품 조건을 판단하는 AI 엔진 개발에 착수했다고 발표했습니다. 이유로는 기존 AI가 확률적 판단에 의존해서 복합 조건을 빠뜨리고, 환각이 생기고, 규정을 반영하지 못한다는 점을 들었습니다. 예로 든 조건은 전월 실적, 이용처, 한도, 제외 업종, 그리고 AND·OR·NOT 같은 조건 관계였습니다.
>
> 두 발표를 신한카드가 하나로 연결해서 설명하지는 않았습니다. 다만 고객 접점을 넓히는 일과 조건 판단의 정확성을 확보하는 일은 목적이 다릅니다. 저희 프로젝트는 그중 판단 정확성 쪽을 다룹니다.

**③ 2분 — 산업적 명분 + GraphRAG 목표 + 검증 방식**

> 카드 혜택에는 전월 실적, 결제방식 제외, 통합 할인 한도, 선택 제약 같은 조건이 서로 얽혀 있습니다. 신한카드는 올해 9월, 기존 AI가 이런 복합 조건을 누락하거나 규정을 반영하지 못한다는 문제를 공식적으로 지적하고, 조건을 구조화해 탐색하는 AI 엔진 개발에 착수했습니다. 2024년에는 카드업 특화 언어모델 과제의 하나로 Graph RAG 구조를 기술검증 주제로 모집하기도 했습니다. 동시에 카카오 플랫폼에 카드 툴을 연동하고, AI 에이전트 결제 표준 사업에도 참여하고 있습니다. 고객 접점은 늘리고, 그 뒤에서 판단의 정확성은 따로 확보하려는 흐름으로 볼 수 있습니다.
>
> 저희는 카카오나 토스와 경쟁하는 추천 서비스를 만들지 않습니다. 공식 상품설명서 PDF에서 혜택, 조건, 제외 항목, 한도, 근거 조항을 추출하고, 계산은 규칙 엔진으로, 조건 사이의 연결과 변경 영향은 그래프로, 근거는 원문 조항으로 제시하는 판단 엔진을 만듭니다. 그리고 여러 채널이 이 엔진의 판단 결과를 같은 형식으로 받아 쓸 수 있도록 API 응답 구조를 설계합니다.
>
> 핵심은 검증입니다. 일반 ChatGPT, PDF RAG, SQL과 규칙 엔진, 그래프 없는 결합 방식, 그래프를 더한 결합 방식 다섯 가지를 같은 질문 30개로 비교합니다. 조건 누락률, 근거 조항 정확도, 판정할 수 없는데 단정한 비율을 측정합니다. 특히 그래프 없는 결합 방식과 그래프를 더한 방식을 같은 데이터로 비교해서, 그래프가 실제로 추가 가치를 만드는지 확인하겠습니다. 그래프가 이기지 못하면 그 결과와 이유를 그대로 보고하겠습니다.
>
> 한계도 분명합니다. 저희는 카드사 내부 거래 데이터와 운영 정책을 쓸 수 없고, 신한카드 엔진의 실제 구조도 공개되지 않았습니다. 그래서 이 프로젝트는 상용 서비스가 아니라, 공개 데이터로 재현할 수 있는 범위의 기술검증입니다.

### E. 최종 추진 의견

| 항목 | 판단 | 이유 |
|---|---|---|
| 산업적 개발 명분 | **확인** | 신한카드 2026-09-09 공식 발표 (조건 판단 문제의 공식화) |
| 외부 서비스와 자체 엔진의 역할 차이 | **일부 확인** | 두 활동의 공식 목적이 다름(접점 vs 정확성). **둘을 잇는 공식 설명은 없음.** 구조는 해외 사례로만 확인 |
| 카드사 자체 개발의 실제 필요성 | **일부 확인** | 정확성·신뢰성·규정 반영·카드사 책임은 공식. "반드시 자체 개발"은 근거 없음(외부 파트너와 공동 개발) |
| 교육용 GraphRAG 개발 가치 | **있음** | 산업 문제를 공개 데이터로 재현하고 측정 가능한 지표로 검증 |
| 공개 데이터 확보 가능성 | **확보** (기존 조사) | 상품설명서 PDF 4종. KB 1종은 OCR 필요 |
| GraphRAG 기술적 실효성 | **미검증** | 산업 자료 어디에도 "조건 판단에 그래프가 낫다"는 근거 없음. D vs E 실험이 유일한 증명 수단 |
| 최종 카드 주제 재검토 가능성 | **조건부 추진** | 아래 조건 충족 시 |

**조건**
1. 팀원과 강사님이 **평가 관점 전환**(상용 차별성 → 산업 문제의 기술검증)에 합의하고, 결정 이력을 규칙 문서에 남긴다(`Claude_카드GraphRAG_재검토제안_20261028.md` 6장 초안). 이 보고서는 규칙 파일을 수정하지 않았다.
2. **D vs E 비교 실험을 MVP 필수 산출물로 둔다.**
3. 착수 전 **A(일반 ChatGPT) 기준선을 먼저 측정**한다. A가 골든 질문 대부분을 맞히면 다시 논의한다.
4. 발표에서 "신한카드가 GraphRAG를 도입했다", "신한카드 엔진이 카카오 뒤에서 작동한다"는 표현을 쓰지 않는다.
