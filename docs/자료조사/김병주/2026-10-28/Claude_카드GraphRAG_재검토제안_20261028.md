## 1. 결론

**카드 주제를 "교육용 기술검증 프로젝트"로 재검토할 것을 제안한다.**

| 평가 관점 | 판단 |
|---|---|
| 카드 분야의 AI 기술 수요 | **확보** |
| 카드사가 직접 지목한 문제(조건 누락·환각)와 우리 문제 정의의 일치 | **확보** (2026-09 신한카드 발표) |
| 카드 데이터와 GraphRAG 결합을 기술검증 과제로 모집한 사례 | **모집 공고 1건 확보.** 검토 결과와 상용화는 미확인 |
| 금융사 자체 AI 서비스 개발 사례 | **확보** |
| 교육용 기술검증 프로젝트 명분 | **설명 가능** |
| 우리 GraphRAG가 다른 방식보다 낫다는 증거 | **아직 없음.** 실험으로 확인해야 함 |
| 공개 약관 데이터로 MVP 검증 | **PDF 4종은 확보.** 질문·정답표는 아직 없음 |
| 상용 서비스(카카오·토스 등) 대비 차별성 | **없음.** 기존 탈락 사유는 여전히 유효하다 |

산업적 명분과 기술적 타당성은 별개다. 이 제안은 명분을 근거로 **기술 타당성을 실험으로 검증할 기회**를 요청하는 것이다. 상용 서비스의 독창성을 주장하는 것이 아니다.

**근거를 묶는 방법**
- 1번: 산업이 **GraphRAG를 검토 대상으로 올렸다.**
- 4번: 산업이 **카드 조건 누락·환각 문제를 풀려고 한다.**
- 둘을 짝지어 쓴다. 1번만 쓰면 대상 데이터가 달라 반박당하고, 4번만 쓰면 그래프와의 연결이 없다.

**쓰면 안 되는 표현**
- "신한카드가 GraphRAG를 도입했다" → 도입 근거 없음
- "신한카드도 우리가 만들 서비스를 개발하고 있다" → 대상 데이터가 다름
- "카드업 특화 GraphRAG 과제" → 원문 구조는 "카드업 특화 sLLM" 과제 아래의 소비 추천용 Graph RAG 하위 항목
- "AI-SOLa에 RAG를 적용했다" → 신한카드 보도자료에서 확인하지 못함

## 3. 프로젝트 방향

### 프로젝트명 (가칭)

**카드 혜택 조건·제약 관계 분석 및 근거 설명 GraphRAG — 조건 누락 측정 기술검증**

추천이 아니라 **관계 분석과 검증**에 초점을 둔다.

### 구현 범위

1. 카드사 공식 상품설명서·약관 PDF 확보 (4종 확보 완료, 필요하면 1~2종 추가)
2. 혜택·전월 실적·제외 조건·통합 한도·결제방식·근거 조항의 관계를 Neo4j로 구성
3. 사용자가 소비계획(가상)을 입력하면 혜택별 **충족 / 미충족 / 판정 불가**를 분석
4. 조건 하나를 바꾸면 영향을 받는 혜택을 역추적
5. 모든 판정에 PDF 페이지와 조항 원문을 제시
6. **네 가지 방식을 같은 질문으로 비교** (4장)

### 역할 분담

| 구성 요소 | 담당 기능 |
|---|---|
| SQL·규칙 엔진 | 실적 합계, 구간 판정, 한도 계산 (결정적 계산) |
| Neo4j (GraphRAG) | 조건·제외·한도·조항 사이의 연결 탐색, 변경 영향 역추적, 근거 경로 |
| RAG | 조항 원문 인용, 그래프에 없는 질문의 대비책 |
| LangGraph | 질문 유형 분류 → 계산 / 그래프 탐색 / 원문 검색 라우팅 → 근거 결합 답변 |

### 하지 않는 것

실제 고객 거래 연동, 카드 추천 순위, 개인정보 수집, 카드사 실제 산정 결과를 재현했다는 주장.

## 4. 검증 실험 설계 (프로젝트 핵심 산출물)

기존 탈락 사유는 "SQL로 동일 구현 가능", "ChatGPT로 대체 가능"이었다. 일반 RAG와만 비교하면 이 두 반론에 답할 수 없다. 그래서 **네 방식**을 비교한다.

| 방식 | 구성 |
|---|---|
| ① 일반 ChatGPT | 웹검색 포함, 카드명과 질문만 입력 |
| ② PDF RAG | 같은 PDF를 청크 검색해 LLM이 답변 |
| ③ SQL + 규칙 엔진 | 조건 테이블 + Python 판정 (그래프 없음) |
| ④ 결합 구조 | ③ + Neo4j 관계 탐색 + 원문 인용 |

**지표** (신한카드가 지목한 문제를 그대로 지표로 씀)

| 지표 | 정의 |
|---|---|
| 조건 누락률 | 정답에 필요한 조건 중 답변에서 빠진 비율 |
| 근거 조항 정확도 | 제시한 PDF 페이지·조항이 정답과 일치한 비율 |
| 잘못된 단정 비율 | 원문으로 판정할 수 없는데 "된다/안 된다"로 단정한 비율 |
| 변경 영향 재현율 (보조) | 조건 변경 시 영향받는 혜택 중 찾아낸 비율 |

**골든 질문**: 20~30개. 정답은 **PDF 원문 페이지로만** 만든다. 질문 유형은 다음과 같이 나눈다.
- 단일 조건 조회 (기준선 확인용)
- 결제방식 제외
- 공유 한도
- 할인분 실적 제외
- 선택 제약
- 여러 카드 비교
- 조건 변경 영향

**판정 규칙 (미리 정함)**
- ④가 ②보다 낫지만 ③과 같다면 → "그래프는 계산 정확도가 아니라 **설명·탐색 표시에 기여**"로 보고한다.
- ④가 ③보다 누락률이나 변경 영향 재현율에서 낫다면 → GraphRAG 실효성 근거로 쓴다.
- ①이 대부분 맞힌다면 → 그 결과를 그대로 보고하고 프로젝트 한계로 적는다.

## 5. 강사님 설명 문안

> 신한카드는 2024년 카드업 특화 언어모델 과제의 하나로, 고객·가맹점·결제내역을 결합하는 Graph RAG 구조를 기술검증 주제로 모집했습니다. 그리고 올해 9월에는 기존 AI가 카드 상품의 복합 조건을 누락하거나 규정을 반영하지 못한다는 문제를 들어, 조건을 구조화해 탐색하는 AI 엔진 개발에 착수했습니다.
>
> 저희는 카카오나 토스와 경쟁하는 상용 카드 추천 서비스를 만들지 않습니다. 이런 금융권 사례를 바탕으로, 카드 상품의 혜택 조건과 제약 관계를 그래프로 구조화하고 근거를 설명하는 **기술검증 프로젝트**를 하려고 합니다.
>
> 공식 상품설명서 PDF와 가상 소비 시나리오로 관계 탐색, 조건 변경 영향 분석, 원문 근거 제시를 구현합니다. 그리고 일반 ChatGPT, PDF RAG, SQL·규칙 엔진, 그래프 결합 방식을 같은 질문으로 비교해, 조건 누락이 실제로 줄어드는지 수치로 보여 드리겠습니다. 그래프가 이기지 못하면 그 결과도 그대로 보고하겠습니다.

| 발표 문구 | "카드업 특화 GraphRAG 기술검증 과제를 모집" | "카드업 특화 언어모델 과제의 하나로 … Graph RAG 구조를 모집" | 원문 구조와 맞추고, 2장의 단서를 발표에서도 유지 |
| GraphRAG 산업 사례 | "확보" | "모집 공고 1건 확보, 검토 결과·상용화는 미확인" | 모집과 검토 완료는 다름 |
| 비교 실험 | 일반 RAG vs GraphRAG | ChatGPT / PDF RAG / SQL·규칙 엔진 / 결합 구조 4가지 + 지표 3개 | 탈락 사유("SQL로 가능", "ChatGPT로 대체")에 답하려면 필수 |
| 근거 구성 | 2024·2025 자료 3건 | **2026-09-09 신한카드 R&D 발표 추가** | 우리 문제 정의(조건 누락·환각)와 가장 가까운 공식 근거 |
