## 0. 최종 판단: **기존 탈락 결정 유지**

| 핵심 질문 | 답 | 근거 수준 |
|---|---|---|
| 1. 카카오가 은행·카드사로부터 받을 수 없는 정보가 있는가? | **있을 가능성이 높으나 항목 단위로는 미확인.** 2021년 금융위 가이드라인의 카드 정보 범위는 "월 이용정보(금액, 일시, 결제예정총액), 카드대출, 포인트 등"이다. **거래별 실적 인정 여부, 할인 적용 결과, 남은 할인 한도**는 이 문구에 없다. 2.0 개편(720개 항목)에 들어갔는지는 확인하지 못했다 | 공식(일부) + 미확인 |
| 2. 그 한계의 성격은? | **기술적 한계가 아니라 제도(표준 API 항목 범위)와 계약의 한계다.** 다만 카카오페이는 받은 결제정보로 실적 현황을 **스스로 추정**하는 서비스를 이미 내놓았다(2025-10 베타) | 공식설명(언론) |
| 3. 카드사가 직접 하면 더 정확한가? | **원리상 그렇다.** 실적 산정·할인 적용의 원장은 카드사에 있다. 하지만 카드사 AI 서비스가 이를 실제로 쓰는지는 **공식 자료로 확인하지 못했다** | 추정 |
| 4. 이미 카드사 앱이 그 기능을 제공하는가? | **일부 그렇다.** 신한카드 앱 '카드이용실적충족현황'(2차 자료), 롯데카드 '받은 혜택 내역'(2차 자료), 하나카드 챗봇의 이용내역 확인·한도 상향·분실신고(언론) | 2차 자료·언론 |
| 5. 자사 데이터가 카카오·토스 대비 지속 가능한 차별점인가? | **약하다.** ① 자사 카드만 본다(복수 카드 배분에서 오히려 불리) ② 플랫폼도 마이데이터로 추정치를 낸다 ③ 기존 앱에 실적 조회가 있다 | 일부 확인 |
| 6. 학생 팀이 구현할 만한가? | **차별성의 원천(카드사 원장 데이터)을 가질 수 없다.** 가상 거래로 만든 시제품은 "카드사가 이렇게 하면 된다"는 설계안일 뿐이다. 정확도 우위를 증명할 수 없다 | 판단 |
| 7. GraphRAG가 꼭 필요한 독자 기능이 있는가? | **찾지 못했다.** 적용 결과 설명은 원장 조회(SQL)와 약관 인용(RAG)으로 충분하다. 그래프가 더하는 것은 "제외 사유 → 약관 조항" 경로 표시 정도다 | 판단 |
| 8. 탈락 결정을 재검토할 새 근거가 있는가? | **없다.** 새로 확인된 사실(카카오페이 AI 혜택 찾기, KB 상품설명서 RAG 상담, 카드사 AI 에이전트 추진)은 오히려 **경쟁 서비스가 늘었다**는 근거다 | – |

| 고객 동의(전송요구)로 받을 수 있는 정보 | 월 이용정보, 승인내역, 결제예정액, 카드대출, 포인트 (N1) |
| 현재 서비스에서 실제 사용이 확인된 정보 | 카카오페이: 마이데이터 결제정보로 실적·혜택 분석 (N3, 언론) |
| 기술적으로 가능하지만 사용 여부 미확인 | 카드사 AI 상담의 개인 실적·적용 결과 사용, 카카오뱅크 AI의 카드 혜택 분석, ChatGPT for Kakao 카드사 툴의 개인 데이터 연동 |

> **"카카오는 해당 정보를 사용할 수 없다"고 단정하지 않는다.** 확인된 것은 2021년 공식 제공 범위 문구에 거래별 혜택 적용 결과가 없다는 점, 그리고 카카오페이가 결제정보로 실적을 분석한다는 기업 발표뿐이다.

## 6. 가설 판정

| 가설 | 판정 | 근거 |
|---|---|---|
| H1. 발급사가 직접 하면 실제 이용 데이터와 혜택 적용 결과로 더 정밀한 설명이 가능하다 | **일부 확인** | 원장은 카드사에 있고(당연한 구조), 앱에 실적 충족 현황 메뉴가 있다(N12, 2차). 그러나 **AI 상담이 거래별 적용 결과를 설명한다는 공식 자료는 없다.** KB AI 상담은 상품설명서·약관 RAG였다(N8) |
| H2. 승인·청구·실적 데이터를 쓰면 ChatGPT(공개 약관)보다 개인별 분석이 정확하다 | **일부 확인(원리) / 미확인(실측)** | ChatGPT는 개인 원장이 없으므로 원리상 맞다. 하지만 이것은 **"정보가 있는 쪽이 이긴다"는 자명한 명제**이고, 비교 실측은 없다 |
| H3. 직접 서비스는 후속 업무 처리까지 연결할 수 있다 | **공식설명으로 확인(언론)** | 하나카드 챗봇의 한도 상향·분실신고·재발급(N11), 신한 AI 컨택센터 후속 업무 자동화(N10), 신한 툴의 발급 페이지 연결(기존 조사). 단 **이미 하고 있다**는 뜻이므로 신규 차별점은 아님 |
| H4. 카카오·토스도 동의·제휴로 유사 데이터를 쓰므로 데이터 접근 자체는 차별점이 아니다 | **일부 확인** | 카카오페이 AI 혜택 찾기가 마이데이터로 실적·혜택을 분석(N3). 다만 **거래별 적용 결과·남은 한도**까지 받는지는 미확인이라 완전한 동등성은 확인 못 함 |
| H5. 카드사 앱에 이미 같은 기능이 있으면 신규 AI 개발 이유가 부족하다 | **일부 확인** | 실적 충족 현황(신한), 받은 혜택 내역(롯데)은 2차 자료로 확인. 카드사들이 AI 상담·에이전트를 이미 추진·운영 중(N7, N8, N10, N11) |

**자사 데이터 보유와 AI 사용 권한은 별개라는 점**
- 생성형 AI 서비스는 혁신금융서비스 지정, 보안성 평가를 통과한 CSP 모델 사용, 금감원 제출 등의 조건이 붙는다(N9).
- 고객 개인신용정보를 외부 LLM에 넘기는 범위와 조건은 이번 조사 자료에서 **직접 확인하지 못했다.** 따라서 "카드사는 자기 데이터를 AI에 자유롭게 쓸 수 있다"고 쓰면 틀린다. 조건부 허용(특례·보안 요건)으로 보는 것이 근거에 맞다.

## 8. 시나리오 검증

| 시나리오 | 필요한 데이터 | 카드사 직접 | 카카오·토스 | 기존 앱 중복 가능성 | 판단 |
|---|---|---|---|---|---|
| A. 30만 원 넘게 썼는데 왜 할인이 안 됐나 | 승인내역 + 실적 인정 여부 + 제외 업종 + 청구 결과 | **유리**: 원장에 거래별 인정·적용 플래그가 있음 [추정] | 승인내역은 받지만 거래별 적용 결과는 미확인 → 추정 설명만 가능 [추정] | 높음: 실적 충족 현황 메뉴(N12) | 카드사 강점은 있으나 **기존 조회 + 약관 인용으로 해결 가능** |
| B. 5만 원 더 쓰면 다음 달 혜택은? | 현재 실적 + 구간 규칙 | 유리 | **카카오페이가 "실적을 채웠을 때 받을 혜택"을 이미 제공**(N3) | 높음 | **차별성 낮음** |
| C. 남은 생활비 40만 원을 어느 카드에 나눌까 | 보유한 **모든** 카드의 실적·혜택 | **불리**: 자사 카드만 봄 | **유리**: 마이데이터로 여러 카드 보유. 카카오페이 결제수단 순위(N3) | 플랫폼이 이미 제공 | **카드사 직접 서비스의 반례** |
| D. 특정 결제가 적립 안 된 이유를 약관 조항까지 | 거래 → 가맹점 분류 → 혜택 → 실적·제외 조건 → 적용 결과 → 약관 | 원장 + 약관 둘 다 보유 → 구성 가능 [추정] | 적용 결과가 없어 추정 | 조항 인용까지 하는 서비스는 **미확인** | **유일하게 남는 후보.** 하지만 결과는 원장 플래그, 근거는 약관 RAG로 충분 |
| E. 다음 달 교통비가 늘면 카드 사용을 바꿔야 하나 | 미래 계획 + 보유 카드 규칙 | 자사 카드 안에서만 | 카카오페이 가맹점·금액 입력, 토스 관심 혜택 필터(기존) | 중간 | 기존 조사(REFINE) 결론과 같음. **차별성 낮음** |

## 10. GraphRAG 필요성

| 기능 | 가장 적합한 방식 | 이유 |
|---|---|---|
| 실적 합계, 남은 금액, 구간 판정 | **SQL·규칙 엔진** | 숫자 집계 |
| 개인 할인 계산 | **규칙 엔진** | 결정적 계산. LLM·그래프에 맡기면 오히려 위험 |
| "이 혜택의 조건이 뭐야" | **단순 RAG** | 상품설명서 1건에서 끝남 (KB가 이미 이 방식, N8) |
| 거래별 미적용 사유 | **원장 조회(SQL)** | 카드사는 사유 코드를 이미 가지고 있을 것[추정] |
| 미적용 사유 → 해당 약관 조항 연결 | 사유 코드 ↔ 조항 **매핑 테이블** + RAG | 1:1 또는 1:N 매핑. 다단계 탐색이 아님 |
| 여러 혜택이 공유 한도·선택 제약으로 얽힌 경우의 설명 | **관계 탐색이 의미 있음** (기존 조사 C4) | 유일하게 그래프가 자연스러운 부분. 하지만 기존 탈락 판단 때도 "SQL로 동일 구현 가능"으로 평가됨 |

**결론: GraphRAG가 없으면 같은 정확도·설명을 제공할 수 없는 기능을 찾지 못했다.** 카드사 원장 데이터라는 새 변수는 정확도를 높이지만, 그것은 **데이터의 힘이지 그래프의 힘이 아니다.**

## 14. 반례와 실패 가능성 (카드사 직접 서비스 가설에 대해)

1. **복수 카드 배분(시나리오 C)은 카드사가 오히려 불리하다.** 사용자의 핵심 고민인 "어느 카드로 낼까"는 여러 카드를 보는 플랫폼의 영역이다.
2. **실적 조회는 이미 앱 메뉴에 있다.** AI가 하는 일이 "메뉴 대신 대화로 보여 주기"라면 사용자 가치 증가가 작다.
3. **카드사들이 이미 AI를 추진·운영 중이다.** 학생 팀이 B2B 설계안을 내도 시장에 새로운 것이 아니다.
4. **정확도 우위는 데이터에서 나오고 그래프에서 나오지 않는다.** GraphRAG 프로젝트의 평가 축과 맞지 않는다.
5. **학생 팀은 원장 데이터를 가질 수 없다.** 가상 데이터로는 핵심 주장(정확한 개인별 설명)을 증명할 수 없다.
6. **마이데이터 2.0에 카드 혜택·실적 항목이 이미 들어갔다면** 플랫폼과 카드사 사이의 정보 격차 자체가 사라진다(미확인. 반대로 들어가지 않았다면 격차는 남지만 4번 문제는 그대로다).
