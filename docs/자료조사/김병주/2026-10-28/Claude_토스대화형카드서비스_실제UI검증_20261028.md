## 1. 최종 결론

**최우선 질문:** "2026-10-28 기준 토스 카드라운지에서 미래 생활계획을 자유로운 자연어로 질문하고, 카드 조건에 관한 답변을 대화형으로 주고받을 수 있는가?"

**답: 조사한 공개 UI에서는 찾지 못했다.**

- 카드라운지 메인, 검색, 비교함, 카드 상세 2건을 데스크톱과 모바일에서 렌더링했다.
- 다섯 화면 모두 **텍스트 입력 요소(input, textarea, contenteditable)가 0개**였다.
- 대화·AI·상담 진입점도 화면 텍스트와 버튼 목록에서 나오지 않았다.
- 카드 탐색은 **카테고리 칩 + 필터(카드사·연회비·전월실적·혜택 유형) + 카드 상세 + 비교함**으로만 이루어진다.
- 이것은 "공개 UI에서 못 찾음"이다. **토스 전체 서비스에서 미지원이라는 뜻이 아니다.** 토스 앱 로그인 화면은 확인하지 못했다.

| 판정 항목 | 결과 |
|---|---|
| 토스 카드라운지 공개 UI 대화형 카드 질문 | **찾지 못함** |
| 토스 앱 로그인 후 대화형 카드 질문 | **검증 불가** |
| 우리 프로젝트 자연어 UX 차별화 | **보통** |
| 우리 프로젝트 조건 분석 기능 차별화 | **보통** |

**자연어 UX 차별화가 '보통'인 이유**

- 공개 UI에 자유 질문 입력이 없다는 점은 사실이다.
- 그러나 칩 다중 선택이 실제로 조건을 결합한다. 통신비+온라인을 고르면 1,737개가 203개로 줄어든다. 그래서 질문의 상당 부분은 이미 클릭으로 처리된다.
- 토스 계열사는 이미 LLM 대화 기능을 운영하고 있어, 이 차이는 언제든 사라질 수 있다.
  - 토스뱅크: AI 채팅 에이전트
  - 토스증권: AI 채팅

**조건 분석 차별화가 '보통'인 이유**

- 카드 상세의 '자세히 보기'에는 혜택별 조건 원문이 표시된다. 예: "쇼핑 멤버십/OTT는 … 간편결제 및 인앱결제 등은 할인 제외".
- 그러나 다음은 공개 UI에서 찾지 못했다.
  - 여러 카드에 걸친 결합 판정
  - 결제방식을 바꿨을 때의 전후 비교
  - 전월실적 제외 항목

## 4. 연속 대화 및 맥락 유지 여부

- **카드라운지 공개 UI: 대화 기능을 찾지 못해 연속 대화는 해당 없음.** [못찾음]
- 대신 **URL 필터 상태**(`?filters=telecom,online`)로 조건을 이어 붙이거나 해제할 수 있다. 칩을 누를 때마다 결과가 좁혀진다(U4 → U5).
- "그중 체크카드만", "간편결제하면 제외되는 건?", "직접결제로 바꾸면?" 같은 후속 질문에 해당하는 조작은 공개 UI에 없다.
- 토스 앱 로그인 후: [검증불가]

## 5. 카드 혜택 조건의 자동 분석 여부

대화형 기능을 찾지 못했으므로 **대화형 분석은 미검증**이다. 공개 UI에서 관찰한 조건 표시 방식은 다음과 같다.

| 분석 항목 | 카드라운지 공개 UI | 수준 |
|---|---|---|
| 혜택별 조건 원문 표시 | **제공.** '자세히 보기'로 펼침(U8). 범위 문구("쇼핑 멤버십/OTT는 …") 포함 | [조작확인] |
| 서로 다른 혜택의 선택 충돌 자동 판단 | 찾지 못함. 택1 구조가 있는 Youth Club·NEED Pay 상세는 공개 목록에서 찾지 못해 표시 방식도 확인 못 함 | [못찾음] |
| 결제방식이 제외 사유인지 필수 조건인지 구분 | 문구로만 표시. 구분해 주는 판정·필터는 없음 | [조작확인](판정 없음 관찰) |
| 결제방식 변경 전후 비교 | 찾지 못함 | [못찾음] |
| 전월실적 제외 항목 | 카드 상세 화면 텍스트에서 찾지 못함(10309, 1818) | [못찾음] |
| 공식 상품설명서 근거 페이지 | PDF 링크 0개. "상품설명서와 약관을 읽어 보시기 바랍니다" 안내만 있음 | [조작확인] |

## 6. 토스 공개 UI vs 우리 GraphRAG

| 기능 | 토스 카드라운지 공개 UI(2026-10-28) | 우리 GraphRAG | 차별화 |
|---|---|---|---|
| 자유 자연어 질문 | 입력창 없음 [조작확인] | 제공 예정 | **있음.** 단 인터페이스 차이일 뿐 |
| 복수 관심사 결합 | **칩 다중 선택으로 제공**(통신비+온라인 → 203개) [조작확인] | 자연어에서 추출 | **약함** |
| 연속 대화·조건 좁히기 | 대화 없음. URL 필터 누적으로 대체 | LangGraph 상태로 이전 조건 유지 | 보통 |
| 신용·체크 통합 | `/search`는 신용만, 체크는 랭킹 분리 | 같은 그래프에서 함께 조회 | 보통 |
| 혜택 조건 원문 | **제공**(자세히 보기) | 제공 + PDF 쪽수 | **약함** |
| 선택 충돌 자동 판정 | 찾지 못함 | Choice 경로로 판정 | **있음(공개 UI 기준)** |
| 결제방식 기준 분류(제외·조건·대상) | 찾지 못함 | PaymentMethod 공유 노드 역조회 | **있음(공개 UI 기준)** |
| 행동 변경안("앱스토어 결제 → 공식 홈페이지 정기결제") | 찾지 못함 | REQUIRES/EXCLUDES 규칙으로 전후 비교 | **있음(공개 UI 기준)** |
| 전월실적 제외(할인분) 비교 | 찾지 못함 | 제공 | **있음(공개 UI 기준)** |
| PDF 근거 쪽수 | 없음 | 제공 | 있음(신뢰 보조) |

**행동 변경안이 PDF로 실제 근거를 갖는 예(이전 보고서의 원문 확인 사실)**

- WE:SH All+·KB ALL OTT: 인앱결제 제외 / 공식 홈페이지 정기결제만 해당 (p1)
- JADE Classic 디지털: 앱스토어(인앱) 제외 / 자동납부만 해당 (p4)
- Youth Club OTT: 인앱 제외 / 공식 홈페이지 정기결제만 해당 (p1)

"앱스토어 결제를 공식 홈페이지 정기결제로 바꾸면 혜택 조건에 들어간다"는 문서 조건을 카드별로 비교할 수 있다. 할인액은 계산하지 않는다.

## 7. 확인하지 못한 영역과 검증 한계

1. **토스 앱 로그인 화면**(카드홈, 소비 기반 추천, 앱 내 AI 상담). 우리 차별화를 무너뜨릴 수 있는 가장 큰 미확인 영역이다.
2. **Claude in Chrome 미사용.** 사용자 실제 Chrome이 아니라 헤드리스 Chromium이다. 로그인 상태, 쿠키, A/B 테스트에 따라 다른 화면이 노출될 가능성은 배제하지 못한다.
3. 화면 하단 고정 위젯 같은 진입점이 스크롤이나 시간 지연 뒤에 나타날 가능성은 있다. 다만 전체 페이지 캡처(full_page)와 DOM 전체 텍스트에서도 찾지 못했다.
4. Youth Club, NEED Pay, KB ALL, 첵첵의 카드라운지 상세 페이지를 찾지 못했다. 이 카드들의 택1·예외 조건을 토스가 어떻게 표시하는지는 미확인이다.
5. 비교함에 카드를 담았을 때의 실제 비교 화면은 확인하지 않았다(빈 비교함만 확인).
6. 토스뱅크 AI 상담이 앞으로 카드 상품 추천으로 확장될 가능성이 있다(2025-12 발표에 "상품 특화 에이전트 단계적 추가" 계획).

## 8. 강사님께 설명해도 되는 차별화 문장 3개

1. 2026년 10월 28일 토스 카드라운지 공개 화면(메인·검색·비교함·카드 상세, PC·모바일)을 직접 렌더링해 확인한 결과, 자유롭게 질문을 입력하는 창이나 대화형 카드 상담은 찾지 못했습니다. 카드 탐색은 카테고리 칩과 필터, 상세 조건 펼치기로 이루어집니다.
2. 토스는 칩을 여러 개 골라 혜택 조건을 결합하는 것과 카드별 조건 원문을 보여주는 것까지는 제공합니다. 그러나 선택형 혜택의 충돌, 간편결제·인앱결제가 제외 사유인지 필수 조건인지의 구분, 결제방식을 바꿨을 때의 조건 변화는 공개 화면에서 판정해 주지 않았습니다.
3. 우리 서비스의 차별점은 자연어 입력 그 자체가 아니라, 사용자가 계획한 결제방식과 관심 혜택을 기준으로 이 조건들을 여러 카드에 걸쳐 판정하고 공식 상품설명서 쪽수로 근거를 보여주는 것입니다. 다만 토스 앱 로그인 화면은 확인하지 못했다는 점을 함께 말씀드립니다.

## 9. 최종 권고

**현재 기획 유지 + 표현 수정**

- **유지:** '미래 생활계획 기반 대화형 사전진단 + 행동 변경안 분석'이라는 구성.
- **표현 수정 1:** "토스에는 대화형 카드 추천이 없다"고 말하지 않는다. "**토스 카드라운지 공개 화면에서는 자유 질문 입력을 찾지 못했다(2026-10-28)**"로 한정한다.
- **표현 수정 2:** 대화형 UX를 핵심 차별점으로 내세우지 않는다. 칩 다중 선택이 이미 조건 결합을 하고 있고, 토스 계열사에는 LLM 채팅 기술이 있다.
- **기능 강조:** 발표의 중심은 아래 세 가지 판정과 PDF 근거에 둔다.
  - ① 선택 충돌 판정
  - ② 결제방식 기준 분류(제외·조건·대상)
  - ③ 행동 변경 전후 조건 비교
- **기능 조정은 불필요하다.** 대화형 인터페이스는 이 판정 기능을 쓰기 쉽게 하는 수단으로 둔다. 연속 대화는 "조건 추가·변경 시 이전 조건 유지" 수준이면 충분하다.
