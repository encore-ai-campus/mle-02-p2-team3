# 카드 GraphRAG의 산업적 명분과 자체 서비스 개발 사례

## 1. 조사 개요와 핵심 결론

- 조사자 김병주 / 작성 도구 Codex / 기준일 2026-10-28
- **교육 목적의 평가: 조건부 추진.** 금융회사들이 자체 AI·RAG를 실제 구축하고 Graph RAG 기술검증을 모집한 근거가 있으며, 공개 상품 문서와 합성 시나리오로 제한된 기술 비교 실험을 설계할 수 있다. 다만 카드별 원문 검수·재사용 조건, 그래프와 대조군의 공정한 성능 비교는 남아 있다.
- **현행 팀 주제 선정 규칙의 결과: 기존 카드 주제 탈락 유지.** [선정 규칙](../../주제_선정_규칙.md)은 기존 카드 주제의 탈락을 확정하고 새 문제 영역과 실질 차별성을 요구한다. 본 조사에서 교육적 가치를 별도로 인정한 것은 이 규칙을 변경하거나 주제를 부활시킨 것이 아니다. 교육 중심 기준으로 재선정할지 여부는 팀·강사님의 판단 대상이다.
- **산업적 명분은 확인, 교육적 명분은 조건부, 상용 기능 차별성은 미입증.** 경쟁사가 있다는 사실만으로 교육·기술검증 가치가 사라지지는 않는다. 반대로 금융회사가 유사 기술을 검토했다는 것만으로 기존 서비스를 능가하거나 GraphRAG가 필수임을 증명할 수 없다.
- 웹 원문 직접 열람, 과거 조사 확인을 구분했다. TechBlaze PDF는 주최 기관의 명의가 있는 **제3자 재게시 PDF 사본**을 웹 도구로 직접 열어 1쪽을 추출했고, 정부 기업마당의 공식 공고 목록·본문 및 첨부 이름은 검색 결과로 확인했으나 공식 페이지의 후속 직접 열기와 공식 서버 첨부 다운로드는 실패했다. 사본과 공식 첨부의 바이너리 동일성은 미확인이다. 로컬 원본 파일을 이번 보고서와 함께 저장하지 않았다. 고객 계정·개인정보·실거래는 수집하지 않았다.

## 2. 기존 탈락 사유와 이번 재검토 목적

기존 확정 탈락은 경쟁 서비스·일반 ChatGPT에 대한 차별성과 관계 탐색의 필요성이 부족하다는 팀의 판단에 따른다. [이전 데이터 차별성 검증](Codex_카카오vs은행카드사_AI서비스_데이터차별성검증_20261028.md)은 발급사의 내부 데이터가 있으면 더 나은 설명이 가능할 수 있지만 팀이 실제 데이터를 이용할 권한이 없고 AI에서 이용한다는 증거도 없다고 결론냈다. 카카오페이의 일부 카드 실적·혜택 및 마이데이터는 외부 플랫폼이 데이터를 전혀 볼 수 없다는 가정의 반례다.

[기존 토스 UI 검증](Codex_토스대화형카드서비스_UI검증_20261028.md)은 공개 카드라운지의 검색 필터와 비교함을 직접 보았으나 앱 로그인 후 기능이나 개인화 결과, 자연어 서비스 부재를 증명하지 못했다. [신한·ChatGPT for Kakao 검증](Codex_신한카드ChatGPTforKakao_1to3Hop_실증검증_20261028.md)은 툴 활성화와 질문 실행에 실패했으므로 실측 점수가 없다. [기술 검토](Codex_카드GraphRAG_기술적용타당성_20261028.md)는 교육용 그래프 표현 가능성을 인정하면서 같은 답을 SQL로도 낼 수 있다고 보았다. [원본 PDF 조사](Codex_카드GraphRAG_PDF원천검증_20261028.md)는 일부 PDF와 텍스트를 확보했으나 이미지 대조와 신용·체크 간 교차 관계 검증을 마치지 못했다.

**이번에 달라진 관점:** 상용 우위 여부와 독립적으로, 실제 금융권의 검증 과제에 근거해 교육 실험의 가치를 평가한다. 이때도 명칭만 바꾼 기존 주제라는 사실, 팀의 확정 규칙, 출처 권리 및 원문 검수의 공백을 숨기지 않는다.

## 4. 신한카드 GraphRAG 공식 자료 검증

### 2024-11-01 모집 공고

정부 [기업마당 공고 페이지](https://www.bizinfo.go.kr/sii/siia/selectSIIA200Detail.do?pblancId=PBLN_000000000102615)의 검색 결과는 2024-11-04 게시, 수행기관 서울창조경제혁신센터, 모집·PoC 지원 및 모집공고 PDF 첨부를 표시한다. 도구에서 페이지 재열기는 `Cache miss`로 실패했다. [재게시 PDF 사본](https://www.k-smbda.or.kr/shop_contents/multi_file_download.php?col_num=6&data_idx=2428511&dir_name=support&type=myboard)은 이번 조사에서 실제 웹으로 열었고 5쪽 중 1쪽의 본문을 읽었다. 신한카드 대표이사·서울창조경제혁신센터장 명의와 2024-11-01 날짜가 보인다. **공식 발행 문서의 사본을 열람한 것이며, 원 발행 서버 PDF를 직접 다운로드하거나 파일 동일성을 검증했다고 주장하지 않는다.**

1. Graph RAG라는 용어는 사본 1쪽 모집주제에 명시돼 있다. 카드업 특화 sLLM 과제의 소비 추천 항목이다.
2. 연결 대상으로 고객·가맹점·결제내역이 명시되며 그 결합에 적합한 그래프 구조와 프롬프트 제안을 모집했다. 구체적 스키마·접근 권한·실제 운영 데이터는 명시된 범위로 확인되지 않았다.
3. 목적은 생성형 AI 사업 아이디어와 카드사 협업 **PoC를 통한 기술 검증 및 파트너 발굴**이다. 사업화 지향도 있으나 모집은 개발 완료나 상용 운영 증거가 아니다.
4. 문서가 밝힌 동기는 금융 특화 생성형 AI와 신한카드 데이터 역량의 시너지다. 경쟁 플랫폼을 배제하기 위한 내재화 또는 구체적인 정량적 성공 지표는 문서상 확인하지 못했다.
5. [신한금융 2025-03-19 발표](https://shinhangroup.com/kr/archive/press/detail/183)는 스마트마인드·사페레아우데·마인즈앤컴퍼니 **3팀 선정**과 각 협업 과제를 발표했고 최대 3개월 PoC 이후 검증된 서비스의 실환경 적용을 **계획**했다. [전자신문 2025-03-19](https://www.etnews.com/20250319000044)은 스마트마인드의 자연어 기반 데이터베이스 분석 검증 계획을 보도한다. **개별 Graph RAG 과제가 실제 착수·완료됐는지, SOL페이에 배포됐는지 또는 효과가 있었는지는 미확인**이다. AI-SOLa의 RAG와 동일 과제라는 근거도 없다.

이 공고의 대상은 고객·가맹점·거래를 이용한 **소비 추천**이고, 학생 프로젝트는 공개 상품 문서의 **조건·예외 설명**이다. 같은 Graph RAG라는 표현이 있더라도 문제와 데이터가 다르므로 학생 프로젝트의 기술 적합성·상용 차별성을 직접 증명하지 않는다.

## 5. 신한·토스·카카오: 자체 서비스와 외부 연계

- 신한 AI-SOLa는 상담사를 보조하고 내부 상담시스템을 검색하는 자사 업무형 서비스다. [공식 발표](https://www.shinhancard.com/pconts/company/html/promotion/press/1233240_3999.html)는 고객 편의와 상담 효율을 목적으로 명시한다. [기존 신한카드 도구 조사](Codex_신한카드ChatGPTforKakao_1to3Hop_실증검증_20261028.md)는 외부 ChatGPT for Kakao의 신한 도구 발표를 확인했으나 직접 호출하지 못했다. 각각의 채널이 병행되는 사실은 확인되지만 **회사가 병행하는 특정 사업 이유를 공식적으로 설명한 자료는 미확인**이다.
- 토스는 [카드 서비스 소개](https://i18n.toss.im/service/card)에서 이용자의 지난 소비와 혜택을 분석해 여러 카드사 상품을 비교하는 편익을 설명한다. 서비스 자체의 AI 모델과 고객 유지·전환 효과는 설명만으로 확정할 수 없다. [토스 삼성카드](https://toss.im/tossfeed/article/39673)는 토스 주요 서비스를 삼성카드 제휴 상품에 연결해 디지털 소비 혜택을 제공한다고 밝힌다. 상품 제휴와 토스의 자체 비교 화면은 다른 역할이다. 해당 제휴 발표일은 이번에 본문에서 독립 확인하지 못해 우선순위 근거 목록에는 넣지 않는다.
- 카카오페이는 [2025-11-26 Pay i 행사 소개](https://story.kakaopay.com/342-kakaopay-fintech/)에서 소비·카드 실적 및 상황별 혜택 기능을 설명한다. [카카오 2026-03-24](https://www.kakaocorp.com/page/detail/11971)는 카카오페이와 외부 파트너를 포함한 Kakao Tools 생태계 확대를 발표한다. 페이 내부 개인 데이터가 ChatGPT 도구에 자동 제공된다는 뜻이 아니다. 행사 시연, 회사의 앱 설명, 실제 질문 시험을 구분한다.

## 8. 산업적·교육적 명분과 상용 차별성

- **산업적 명분 — 확인:** 기업의 공식 PoC 모집과 실제 RAG 상담 지원, 다른 카드사의 개인화 플랫폼 및 규제기관의 금융 특화 RAG 수요 확인은 카드 업무의 AI·데이터 연결이 실제 산업 과제임을 보여준다. 경쟁이 있더라도 기업은 각자의 데이터·채널·업무·협력 목적에 맞게 개발할 수 있다. 특정 기업의 숨은 전략을 확인한 것은 아니다.
- **교육 명분 — 조건부:** 공식 문서에서 조건을 추출·검수하고 가상 거래와 결합해 정형 규칙과 RAG/그래프 검색의 결과·근거를 비교하는 과정은 문서 파싱, 데이터 모델링, 관계·버전 관리, 평가와 설명 역량을 보여줄 수 있다. Neo4j·LangGraph를 실제로 사용하는 것이 필수인지는 평가 목표에 달려 있다.
- **상용 차별성 — 미확인:** 카카오페이·토스·발급사들의 중복 기능과 실제 로그인 영역을 충분히 비교하지 못했다. 맞춤 추천이나 근거 설명의 우위가 확립되지 않았다. ‘기존에 없는 기능’, ‘더 정확함’, ‘실제 고객 혜택 확정’이라는 표현은 사용할 수 없다.

## 9. 조건·제약 분석 기술 구성과 실제 관계

상품·혜택·조건·실적 구간·제외 거래·공유한도·선택집합·문서 버전/쪽수와 가상의 시나리오를 구분한다. [기존 PDF 조사](Codex_카드GraphRAG_PDF원천검증_20261028.md)에서 확인한 KB NEED Pay 상품설명서 1쪽의 `디지털 혜택 → 인앱결제 제외`, `일반 간편결제 제외 → 명시된 일부 제휴 결제 예외` 및 2쪽의 `전월실적 → 할인 적용 매출 제외`는 **웹 PDF 텍스트 기준**이다. 표 행열 이미지 검수 전 최종 규칙으로 승인하면 안 된다. [기존 기술 검토](Codex_카드GraphRAG_기술적용타당성_20261028.md)는 KB Youth Club의 OTT A팩·통신 B팩 선택 제약을 텍스트로 확인했으나 이미지와 최신성은 미대조다. 다른 카드와의 연결은 동일한 뜻의 공통 조건을 **각 원문에서** 독립 확인해야 한다.

| 요청된 관계 | 검증 가능성 및 현 상태 |
|---|---|
| 카드 → 혜택 → 적용·제외 조건 | NEED Pay 1쪽 일부 텍스트 확인; 조건별 수식 범위 이미지 대조 필요 |
| 혜택 → 통합 할인한도; 조건 → 전월 실적 | 개별 상품 원문에서 검수 가능. 특정 혜택과 한도의 표 행열·시점은 이 조사에서 승인하지 않음 |
| 실적 → 제외 거래 유형 | NEED Pay 2쪽 텍스트 일부 확인. 실제 고객 거래의 제외 여부는 알 수 없음 |

가상 설계는 `PostgreSQL(가상 거래·시나리오) → 결정론적 규칙 엔진 → 검수된 조건·출처 관계(Neo4j) → 검색된 근거를 설명(LLM/LangGraph)`이다. 그래프는 필수 전제가 아닌 **실험 대상**이다. 예외는 적용 조건과 방향·우선순위·유효시점을 함께 보존한다.

## 10. SQL·일반 RAG·GraphRAG 비교

| 방식 | 적합한 역할 | 한계 및 동등성 |
|---|---|---|
| SQL + 규칙 엔진 | 금액·실적·한도·날짜·취소 계산과 정형 조건 판정 | 정확한 규칙과 출처 테이블을 설계하면 다단계 관계와 설명도 구현 가능. 계산을 LLM에 위임하지 않는다 |
| 일반 RAG | 관련 약관·예외·쪽수 검색과 문장 요약 | 복수 문서의 완전한 조건 집합은 별도 검증 필요하나, 소수 문서에는 충분할 수 있다 |
| GraphRAG | 혜택→조건→예외→문서의 유형이 다른 다단계 경로와 영향 후보의 탐색·표시 | SQL 조인/재귀도 동일 결과 가능. 그래프를 쓴다는 사실은 정확성·필요성의 증거가 아니다 |
| SQL + 규칙 + GraphRAG | 숫자는 결정론적으로 계산하고, 검수된 관계·원문 경로를 탐색·설명 | 복잡도가 커지고 중복 규칙·버전 불일치 위험. 작은 범위에선 과도할 수 있음 |

조건 변경의 영향 경로를 그래프로 표시하는 것은 유용할 **가설**이다. 설명 품질 향상은 **미실측**. 공정한 실험은 세 방식에 동일 원문·같은 검수 관계·같은 가상 입력·정답셋·시간 기준을 제공한다. 각각 정답률, 예외 누락/거짓 적용, 근거 쪽수 정확도, 조건 변경 후 영향 탐지, 응답 시간과 작업량을 비교하고 실제 결과를 발표한다. SQL과 그래프가 같거나 일반 RAG가 더 나아도 그대로 보고한다.

## 12. 학생 팀 MVP 제안: 승인된 경우의 기술검증 계획

- 범위: 실제 고객 없이 신용·체크 각 1개 이상을 **원문·이미지·권리 검증 후** 선택. 최초에는 상품 1개와 3~5개의 조건에 한정해 시스템 간 비교를 준비한다. 개인화 추천·발급·실제 청구 확인·거래 수집 제외. 일정은 측정하지 않았으며 2인 완성을 보장하지 않는다.
- 입력: 완전히 합성한 거래/시나리오의 가맹점 유형·결제 경로·금액·가상 기준일과 전월 실적. 출력: 검수된 상품 규칙의 충족·미충족·불명 및 문서명·쪽수·시점. 산정 결과는 가정된 규칙에 따른 시뮬레이션이다.
- 시험 질문과 현재 수동 기대: ① NEED Pay 디지털 대상 결제의 인앱 경로는? **기존 텍스트에서 제외**, 이미지 대조 필요. ② 일반 간편결제는? **제외 규칙과 열거된 예외를 함께 확인**, 전부 제외 단정 금지. ③ 할인 적용 매출이 다음 실적에 포함되는가? **기존 텍스트상 제외**, 적용 시점·표 대조 필요. ④ Youth Club의 두 선택팩을 같은 달 함께 쓸 수 있는가? **기존 텍스트상 선택 제한**, 최신 원문·예외 확인 필요. ⑤ 가상의 소비 경로를 인앱에서 공식 홈페이지 정기결제로 바꾸면 어떤 조건이 바뀌는가? **인앱 제외 요인만 해소 가능**, 다른 조건·기간·대상 확인 전 혜택 확정 금지.
- 성공은 수동으로 검수한 정답·출처 위치와 시스템의 판정이 일치하고, 빠진 입력에는 불명을 반환하는 것. 잘못된 예외 병합·연도 불일치·실제 혜택 보장 표현은 실패다. 실제 대조군 구현과 실험은 **수행하지 않았다**.

## 13. 강사님 예상 질문과 답변

1. **왜 카드 분야인가?** 원문에 상품별 적용·제외·실적 조건이 존재하고 실제 금융권에서도 카드 AI·RAG 기술을 검증하기 때문이다. 단 팀이 확정한 신규 주제 규칙과 충돌한다.
2. **이미 토스·카카오가 있는데 왜 만드나?** 상용 경쟁 제품을 새로 발명했다는 주장이 아니라, 동일 문서에서 규칙·검색·경로 설명을 비교하는 교육 실험이라는 목적이다. 현행 선정 규칙의 차별성 요건은 여전히 미충족이다.
3. **신한도 자체 AI를 개발하나?** 공식 2025 발표에 상담 지원 AI-SOLa와 RAG가 명시된다.
4. **GraphRAG를 검토한 회사가 있나?** 신한·서울센터 명의 2024 모집 PDF 사본에 Graph RAG가 명시된다. 수행·상용화 확인은 별개다.
5. **단순 추천과 다른가?** 실험 범위는 특정 규칙의 충족 여부와 조건 변경 전후, 출처 쪽수다. 이 조합이 상용 서비스에 없다는 뜻은 아니다.
6. **ChatGPT로 가능한데 왜 개발하나?** 정답셋·근거·조건의 누락과 불명 처리를 비교하기 위해서다. ChatGPT보다 우수함은 실제 실험 전 주장하지 않는다.
7. **왜 그래프인가?** 가변 길이 조건 경로와 역탐색을 실험하기 위해서다. SQL과 같은 결과가 가능하므로 실측에서 이점이 없으면 그 결론을 수용한다.
8. **내부 데이터 없이 가능한가?** 공개 문서와 가상 거래로 제한된 조건 실험은 가능하나 실제 고객의 할인 처리 결과를 확인하지 못한다.
9. **무엇을 배우나?** 공식 PDF 검수, 규칙 모델링, 데이터베이스·검색·근거 추적, 비교 실험과 실패 처리다.
10. **상용화 조건은?** 문서·데이터 이용권, 실제 금융사의 권한 있는 데이터·시점·정답, 개인정보·보안 및 업무 연계 검토, 경쟁 서비스와 유의미한 비교가 추가로 필요하다.

## 14. 발표용 선정 배경 초안 (1~2분)

“금융회사들은 이미 여러 AI 서비스를 개발하고 있습니다. 신한카드는 상담사를 돕는 AI-SOLa에 상담 정보 검색과 RAG를 적용한다고 발표했습니다. 또 2024년 신한카드와 서울창조경제혁신센터 명의 모집 공고에는 고객, 가맹점, 결제내역을 연결하는 Graph RAG 기술검증 과제가 제시됐습니다. 이는 업계의 검토 사례이지 해당 기술의 상용화를 뜻하지 않습니다.

카드 상품에는 할인 대상, 전월 실적, 결제 경로, 제외 조건처럼 함께 확인해야 할 규칙이 있습니다. 저희가 제안하는 교육 실험은 공식 상품 문서의 조건을 사람이 검수하고, 가상 거래를 이용해 조건 변경에 따른 결과와 원문 근거를 보여주는 것입니다. 금액 계산은 규칙 엔진으로 처리하고 관계 탐색과 설명에는 그래프를 실험적으로 적용합니다.

토스와 카카오페이에도 소비 기반 추천과 혜택 기능이 있으므로 새로운 상용 기능이라고 주장하지 않겠습니다. 같은 문서와 질문으로 SQL·일반 RAG·GraphRAG를 비교해 정확도와 근거를 평가하고, 차이가 없으면 그렇게 보고하겠습니다. 실제 고객 거래나 카드사 내부 데이터는 사용하지 않으며 상품 문서의 이용 조건과 최신성도 먼저 확인해야 합니다. 현재 팀 규칙상 카드 주제는 탈락 확정이므로 교육 중심 주제로 변경할지는 별도로 논의해야 합니다.”

## 15. 최종 추진 여부와 남은 과제

**조건부 추진(교육 실험 기준)**. 실제 산업의 기술검증 수요와 제한된 학습 가치는 확인됐다. **현행 팀 규칙 기준으로는 기존 탈락 유지**이며, 이번 보고서는 팀의 선정 기준을 변경하지 않는다. 상용 서비스의 독자적 가치나 GraphRAG의 필수성도 아직 증명되지 않았다.

재검토에 필요한 조건은 ① 강사·팀이 교육 실험 목적과 기존 규칙의 관계를 명확히 결정 ② 두 상품 이상의 공식 문서 확보·PDF 표 이미지 검수·조건/시점/이용권 확인 ③ 예외·공유한도·시나리오의 정답셋 마련 ④ 동일 입력의 SQL+규칙, RAG, GraphRAG 비교 ⑤ 기존 토스·카카오·카드사에 같은 질문을 실제 실행해 겹침을 기록하는 것이다. 실패 또는 차이가 없으면 그대로 보고하고, 차별성이 필수라면 현행 탈락 기준을 유지한다.
