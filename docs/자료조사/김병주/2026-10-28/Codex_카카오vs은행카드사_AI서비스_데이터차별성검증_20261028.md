# 카카오와 은행·카드사 직접 AI 서비스: 데이터 접근과 차별성 검증

- 조사자: 김병주 / 도구: Codex / 조사 기준일: 2026-10-28
- **최종 판단: 기존 탈락 결정 유지.** 실제 고객 데이터와 업무 처리 권한이 있는 발급사라면 거래별 설명을 더 충실하게 만들 가능성은 있다. 그러나 그 정보의 실제 AI 사용 권한·기존 서비스와의 차이·학생 팀의 데이터 접근·GraphRAG 필수성이 확인되지 않았다. 따라서 기존 탈락 결정을 변경할 근거는 없다.
- 주제 선정 규칙 전문 및 기존 카드 조사자료를 먼저 확인했다. 본 문서의 목적은 확정된 탈락 결정을 무효화하는 것이 아니라 새 근거가 재검토를 정당화하는지 평가하는 것이다.
- 증거 표시: **[공식]** 기관·사업자의 공개 설명 또는 공식 원문, **[기존 UI]** 이전 보고서의 공개 UI 직접 관찰, **[가설]** 구현 가능성, **[미확인]** 공개 증거가 없거나 실제 기능을 시험하지 못함. 이번 조사에서는 실제 금융계정·고객정보·인증정보를 이용하지 않았고 로그인 후 UI 또는 ChatGPT for Kakao 금융 툴을 직접 작동시키지 않았다. 기존 UI 관찰을 이번 실측으로 표시하지 않는다. 공개 소개에 기능이 없다는 이유로 미지원이라 단정하지 않는다.
- 공식 웹 자료는 2026-10-28 기준 확인 가능한 범위로 사용했다. 일부 페이지는 변경될 수 있으며 정책 내용은 자료별 발표일과 시행 범위를 명시한다. 개별 제휴계약, 정보항목의 기술 명세·실제 고객별 동의, AI 입출력의 비공개 흐름은 미확인이다.

## 7. 가설 판정

1. **발급사는 자사 거래·혜택 결과로 정밀 설명 가능 — 일부 확인.** 공식 앱의 실적과 적립 내역은 존재한다. 하지만 거래별 부적용 사유 코드·약관 버전을 AI에 제공하는 권한과 실제 설명 정확도는 미확인이다. 보유 데이터는 AI 활용 승인이 아니다.
2. **실거래·산정 결과가 공개 약관만 읽는 ChatGPT보다 정확할 수 있음 — 일부 확인.** 원문만으로는 사용자 실제 거래·정산 결과를 알 수 없다. 동일한 실제 데이터와 동일 규칙을 두 시스템에 제공한 비교는 없으므로 정확도 개선은 실험되지 않았다.
3. **자사 업무 후속 조치 연계 — 일부 확인.** 하나Pay의 혜택 조합 변경 등 앱의 후속 행동은 확인. AI가 해당 조치를 실행하는 구체 사례와 승인·권한은 미확인. 다른 플랫폼도 정당한 API를 통해 일부 업무를 수행할 수 있다.
4. **외부 플랫폼도 동의·제휴로 비슷한 정보를 이용 — 공식 자료로 확인(제한된 범위).** 카카오페이의 카드 실적·소비내역 및 금융결제원 청구 API가 반례다. 모든 내부 상세의 동등 접근을 입증하지는 않는다.
5. **자사 앱이 이미 같은 기능을 제공할 수 있음 — 일부 확인.** 현대의 실적, 신한의 달성 상태, KB의 특정 적립내역, 하나의 혜택 변경은 확인했다. 다섯 시나리오의 거래별 원인·정확한 조항·대안까지 같다는 증명은 없다.

## 9. 데이터 접근 및 학생 프로젝트 범위

- 공개 자료: 이전 조사에서 [KB NEED Pay 상품설명서](https://img2.kbcard.com/obj/card/download/09800__prdctOpmn_20260330.pdf) 일부 텍스트를 추출했고, 간편결제 예외·할인 적용 매출의 실적 제외를 확인했다. 표 이미지 대조와 다른 카드의 완결 연결은 미완료. 이번 조사에서도 공식 상품 원문과 [하나 상품안내](https://m.hanacard.co.kr/leaflet/11/11064_20260504.pdf)를 웹 열람했지만 신규 파일 다운로드·전체 표 독립 파싱이나 각 문서의 재배포·자동수집 라이선스를 검증하지 않았다.
- 비공개 데이터: 고객의 승인·매입·정산, 이용 실적 산정 및 처리내역은 공개 PDF로 얻을 수 없다. 마이데이터나 오픈뱅킹은 제도·계약·고객 동의 및 기관 자격이 필요한 실제 금융 서비스이며, 이 학생 팀이 이를 사용할 수 있다는 근거는 없다. 학생 팀이 카드사 내부 시스템에 접근할 수 있다는 증거도 없다.
- 합성 데이터: 실제 개인 또는 거래를 추출하지 않은 가상 거래와 정답을 직접 설계해 규칙의 작동·불명 처리·화면을 실험할 수 있다. 예컨대 가상 30만원 중 실적 제외 10만원, 인정 20만원으로 정해진 규칙을 검증할 수 있으나 실제 카드사의 매입 분류·시점·정산 결과 재현이나 서비스 우위는 증명하지 못한다.
- 공개 PDF와 합성 데이터로 **교육용 시연**은 가능할 수 있다. 다만 그것만으로 실고객의 할인 미적용 원인을 정확히 알거나 발급사 고유 권한을 가진 서비스라고 주장할 수 없다. 학생이 공개적으로 운영하는 실제 서비스는 차별성과 원천 권리 검증이 부족하다. 카드사 협약·적법한 내부 접근을 전제로 하는 **B2B 시제품은 별개의 가정**이며 현재 실현 가능성이 입증되지 않았다.

## 10. SQL·규칙 엔진·RAG·GraphRAG 구분

| 기능 | 적절한 1차 수단 | 그래프 필요성 |
|---|---|---|
| 승인·매입·취소 합계, 실적 산정·한도 잔액·할인액 | 거래 DB와 결정론적 SQL/규칙 엔진, 카드사의 확정 산정 결과 | 그래프가 필요하다는 근거 없음. LLM에 계산을 맡기지 않는다 |
| 상품설명서 한 조항의 검색·인용 | 일반 검색 또는 RAG, 시행일·상품 버전 필터 | 단일 문서라면 그래프가 필요하지 않을 수 있음 |
| 거래→혜택→적용조건→예외→상위 조건·문서 버전, 복수 경로 탐색 | 정형 관계와 출처 근거를 결합하는 그래프 가설 | 여러 예외·버전의 가변 길이 역탐색에는 편리할 수 있지만 SQL 재귀/조인과 규칙 엔진으로도 구현 가능. 반드시 필요하거나 정확도가 높다는 실험 없음 |
| 규칙 결과를 자연어로 설명 | 검증된 규칙 결과와 해당 원문을 전달하는 설명 생성 | LLM·GraphRAG 자체가 산정 진실을 보장하지 않음. 사실·미확인 분리 필요 |

가상의 구조는 `거래/실적 SQL → 규칙 엔진 → 상품·혜택·조건·예외·유효기간·원문 위치 그래프 → LLM 설명`이다. 하지만 **거래→산정 사유→당시 원문**의 실제 교차 데이터와 카드사 담당자의 검수 정답이 없으므로 경로의 실제 완결성·그래프를 제거했을 때 손실은 미입증이다. 동일 데이터와 질의에 대해 SQL+규칙+RAG와 GraphRAG의 정답률·출처 정확성·누락·시간을 비교해 우월성이 확인돼야 별도의 그래프 가치를 인정할 수 있다.

## 11. 금융 AI와 외부 LLM에 대한 정책 확인

- [금융위 2026-06-18 발표](https://www.fsc.go.kr/po010102/87142)는 금융분야 AI 가이드라인을 2026-06-22부터 시행하는 자율규제로 소개하고, 법적 의무가 별도로 발생하는 고영향 AI 등은 관련 법령을 확인하도록 한다. 거버넌스·합법성·신뢰성·보안 및 임직원 최종 책임 원칙을 제시한다. 모든 금융 AI가 동일한 법정 의무를 지닌다는 뜻이 아니다.
- [금융위 2024 안내](https://www.fsc.go.kr/po010101/83594?curPage=7&srchBeginDt=&srchCtgry=&srchEndDt=&srchKey=&srchText=)는 외부 상용 AI와 내부 오픈소스 AI를 구분하면서 당시 예시로 개인신용정보를 쓰지 않는 일반 상담 등을 설명했다. 이는 2026년 모든 외부 LLM 이용의 전면 금지라는 결론이 아니다.
- [금융위 2026-04-15 발표](https://www.fsc.go.kr/no010101/86712?srchEndDt=%2F)는 지정된 혁신금융서비스의 모델 변경 절차 간소화를 설명한다. [2026-09-03 보안 목적 망분리 테스트](https://fsc.go.kr/po010104/87646)는 선정 기관과 보안 목적의 제한된 사례다. 이를 일반 고객 금융 데이터의 외부 모델 전송 허용으로 확대 해석하지 않는다.
- 실제 설계 시 목적과 법적 근거, 고객 전송요구·동의의 범위, 제3자 제공과 위탁 구분, 국외 이전 여부, 목적 제한·보존 및 삭제, 계약·수탁자 통제, 망분리와 지정 조건, 최소 권한·감사 및 모델 학습·저장 설정을 개별 확인해야 한다. 이번에 각사 계약과 해당 서비스의 실제 적법성을 확인하지 못했다.

## 12. 핵심 질문에 대한 답

1. **카카오가 못 받는 정보가 있는가?** 특정 내부 필드의 전면적 제공 불가를 입증하지 못했다. 카드 목록, 청구정보, 소비내역과 일부 실적은 동의·계약·기관별 범위에서 외부 제공 가능하다는 반례가 있다. 상세 산정 로그와 잔여한도의 외부 제공은 미확인이다.
2. **제한의 종류는?** 항목별 법적 근거·동의·계약·참가 요건, 표준 API 명세, 기관 구현 범위가 각각 다를 수 있다. 이번 자료로 특정 필드의 기술적 불가능 또는 절대 법적 금지를 확정할 수 없다.
3. **발급사 직접 AI가 더 정확할 수 있는가?** 승인된 실제 산정 결과와 올바른 시점의 규칙을 쓰면 공개 약관만 보는 모델보다 정보가 풍부할 가능성이 있다. 실제 AI 접근 권한과 정답률 비교는 미확인이다.
4. **기존 앱이 제공하는가?** 실적 현황·일부 적립내역·혜택 변경은 공식 확인됐다. 거래별 미적용 이유와 조항을 한 번에 설명하는 기능의 제공 여부는 미확인이다.
5. **지속 가능한 차별점인가?** 데이터 보유만으로는 아니다. 카카오페이와 오픈뱅킹의 반례가 있으며, 발급사만 가진 특정 사유 데이터와 제공 권한·서비스 차이·유지 비용을 입증해야 한다.
6. **학생 팀이 내부 데이터 없이 만들 가치가 있는가?** 합성 데이터 시연은 가능하나 실제 개인 혜택 진단과 데이터 접근 차별성은 입증할 수 없다. 현 기준의 신규 주제로 채택할 근거는 부족하다.
7. **GraphRAG의 독자적 필요성이 있는가?** 미입증. 다중 예외·문서 버전의 경로 제시는 후보이나 SQL+규칙 엔진+일반 RAG 대비 동등 조건 비교가 없다.
8. **탈락 결정을 재검토할 근거가 확보됐는가?** 아니다. **기존 탈락 결정 유지.** 추후 카드사와의 적법한 접근 협약, 데이터 사전·익명 검증 정답, 동일 질문의 경쟁 제품 결과와 SQL/RAG 비교가 확보되면 그때 새로운 증거로 별도 평가할 수 있다.
