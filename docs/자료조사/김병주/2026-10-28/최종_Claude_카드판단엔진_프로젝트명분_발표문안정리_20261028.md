## 1. 핵심 포지셔닝

**카카오와 경쟁하는 추천 서비스가 아니다. 카카오 같은 창구 뒤에서 카드사가 운영하는 "판단 엔진"을 만든다.**

- 카카오 같은 외부 채널은 고객을 만나는 **창구**다. (상대 서비스를 깎아내리지 않는다)
- 우리 프로젝트는 그 창구들이 참조할 수 있는 **검증된 조건 원본과 판단 엔진**이다.
- 차별점은 추천 품질이 아니라 **근거, 일관성, 오답 원인 추적**이다.

## 3. 최종 발표 문안 (약 40초)

> 신한카드는 올해 9월 ChatGPT for Kakao에 카드 추천과 혜택 조회를 연결했습니다. 같은 달, 이와 별도로 금융상품의 복합 조건을 판단하는 AI 엔진 개발을 발표했습니다. 발표에서 밝힌 이유는 기존 AI의 정보 왜곡, 일관성 부족, 조건 누락, 규정 미반영이었습니다.
>
> 해외에서도 American Express는 외부 AI 플랫폼 연동과 함께 자사 앱의 AI 서비스를 개발하고 있고, Mastercard는 10월 은행용 카드 혜택 AI를 출시해 여러 은행이 도입을 추진 중입니다.
>
> 또 올해 6월 시행된 금융분야 AI 가이드라인은 최종 판단과 책임을 금융회사 임직원이 지도록 정했습니다.
>
> 저희는 카드 혜택을 정확하게 판단하고 그 근거를 설명할 수 있는 AI에 대한 수요가 커지고 있다고 보았습니다. 그래서 공개 약관으로 판단 엔진을 만들고, 실제 오답의 원인을 분류해 고친 과정까지 보여드리겠습니다.

## 4. 외부 AI 호출만 할 때 vs 자체 판단 엔진

"외부 서비스는 검증을 못 한다"가 아니라 **"누가 정답의 원본과 판단 기록을 쥐고 있느냐"**로 설명한다.

| 항목 | 외부 AI 호출만 할 때 | 자체 판단 엔진 |
| --- | --- | --- |
| 정답 원본 | AI가 매번 약관을 새로 해석 | 검수된 조건 데이터 한 곳 |
| 근거 | 문장 속에 있을 수도, 없을 수도 있음 | 판정 + 조항 + 판단 경로를 구조화해 반환 |
| 일관성 | 질문·시점·채널마다 달라질 수 있음 | 같은 입력이면 같은 판정 |
| 약관 변경 | 프롬프트·문서를 일일이 수정 | 조건 하나 수정 → 모든 채널에 반영 |
| 모니터링 | 답변 로그 정도 | 판정 로그, 틀린 판정 추적, 변경 전후 비교 |

## 5. 카드사가 직접 가져가야 할 것 (우리 주장)

| 가져갈 것 | 의미 | 프로젝트에서 보여줄 것 |
| --- | --- | --- |
| ① 판단 과정의 운영 경험 | 어떤 조건을 어떤 순서로 따져 답했는지 알고 통제함 | 판정 경로(조건 → 혜택 → 약관 조항) 화면 표시 |
| ② 판단 데이터 | 질문·판정·판정 불가가 기록으로 쌓임 | 판정 로그 저장, 질문·판정 유형 통계 |
| ③ 오답 원인 분석·해결 노하우 | 틀린 답의 원인을 찾아 고치고, 다른 답이 깨지지 않았는지 확인 | 오답 원인 분류 → 수정 → 회귀 테스트 |

> 프로젝트 기간에 운영 경험·데이터를 **양으로** 보여줄 수는 없다. 대신 **쌓이고 개선되는 구조**(로그, 원인 분류, 회귀 테스트)를 보여준다.

### 오답 원인 분류 기준

1. **약관 추출 오류:** PDF에서 조건을 잘못 뽑음
2. **조건 해석 오류:** 범위·택1·예외 관계를 잘못 연결함
3. **질문 해석 오류:** 사용자 질문을 잘못 이해함
4. **데이터 없음:** 약관에 근거가 없음. 이 경우 "판정 불가"가 정답

발표에서 실제 오답 사례 2~3개를 "원인 → 수정 → 회귀 테스트 통과" 순서로 보여준다.

## 6. 차별점 3가지와 시연 장면

| 차별점 | 시연 장면 | 근거 |
| --- | --- | --- |
| ① 근거와 "판정 불가" | 답마다 약관 조항을 붙이고, 약관으로 판단할 수 없으면 "판정 불가"로 답함 | 신한카드가 밝힌 환각 문제, 금융위 가이드라인의 신뢰성 원칙 |
| ② 변경 영향 추적 | "전월실적 제외 항목이 바뀌면 영향받는 카드·혜택은?"에 경로로 답함 | 신한카드 "조건 수정만으로 실시간 반영" |
| ③ 한 엔진, 여러 창구 | 같은 엔진을 MCP 서버와 웹 화면에 연결해 같은 질문에 같은 답이 나오는지 확인 | 신한카드의 PlayMCP 연동, BofA "AI 역량은 여러 영역에 재사용되도록 설계" |

| 신한카드가 그래서 엔진을 만든 건가요? | 신한카드가 밝힌 이유는 정확성·일관성·조건 누락 방지·규정 반영까지입니다. 운영과 오답 분석 관점은 저희 팀의 해석입니다. |
| ChatGPT에 약관을 넣으면 되지 않나요? | 같은 질문으로 일반 ChatGPT와 비교한 조건 누락률·근거 정확도·판정 불가 처리 결과를 보여드리겠습니다. |
| 직접 만들어야 하나요, 사서 쓰면 되지 않나요? | 둘 다 실제로 쓰이는 방식입니다. 사서 쓰더라도 카드사 고유의 혜택 조건과 근거는 카드사가 관리해야 하고, Mastercard도 발급사의 혜택 콘텐츠를 함께 쓴다고 밝혔습니다. 저희는 그 조건과 근거를 관리하는 부분을 만들었습니다. |
| 실제 고객 데이터가 없는데 가치가 있나요? | 가상 거래로 "미적용 사유" 판정을 시연하고, 실제 거래가 들어오면 같은 조건 기반을 그대로 쓰는 구조를 보여드립니다. 실데이터 성능은 주장하지 않습니다. |
| 왜 GraphRAG인가요? | 여러 카드가 공유하는 조건을 통한 변경 영향 추적과 근거 경로 제시 때문입니다. 필요성은 SQL+규칙 엔진+PDF RAG와 비교 실험으로 판정하고, 이기지 못하면 그대로 보고하겠습니다. |

## 8. 취업 어필 포인트

- **키워드:** 환각 통제와 판정 불가 처리, 규칙 버전 관리와 변경 영향 분석, 정량 평가 체계, MCP 기반 외부 에이전트 채널 제공(에이전틱 커머스), 금융 AI 가이드라인 대응
- **경력 연결 (김병주):** 기업신용평가 관련 시스템 개발 경험을 바탕으로 "금융 시스템에서는 결과를 내는 것만큼 그 판단을 검증하고 변경을 통제하는 것이 중요하다는 관점을 생성형 AI에 적용했다"고 설명한다. (개인신용평가 경험으로 표현하지 않는다)
- **면접 한 줄:** "외부 AI는 답을 주지만 그 답이 맞는지 확인할 기준은 주지 않습니다. 금융에서는 판단을 설명하고 책임져야 하니, 정답의 원본과 판단 기록을 직접 관리하는 엔진을 만들었습니다."
