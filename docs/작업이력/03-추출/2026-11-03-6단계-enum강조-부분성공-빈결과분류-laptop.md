## 한 일

- 프롬프트에 모든 스키마 Literal enum의 허용값과 뜻을 굵은 제목 아래 모아 보여 주고, 목록 밖의 값을 만들지 말며 확신이 없으면 `OTHER` 또는 항목 생략을 지시했다. 값 목록은 `schema.py`에서 읽고 설명 문구만 상수로 관리한다.
- 요약에 `partial`을 추가했다. 위치 실패만 있는 추출 청크는 기존 의미대로 `failed`에도 남기고 `partial`에도 포함한다.
- `diagnose-empty` 명령과 `diagnose.py`를 추가했다. 결과 JSON은 청크 id, 제목 필드, 길이, 키워드별 등장 횟수만 기록한다. 키워드 검사는 혜택 가능성을 보는 거친 신호다.
- 허용된 작업 이력 표에 새 행을 추가했다.

## 검증

- 추출 테스트: 첫 실행은 50 passed. 최종 재실행은 54 passed, 1 failed였다. 실패는 이 작업에서 추가하지 않은 `review_sheet` 테스트가 저장소 밖 `~/workspace/bad.md` 쓰기를 시도해 샌드박스에서 거부된 것이다.
- 로컬 진단 CLI는 하나카드 입력에서 빈 결과 4개를 분류했다. 저장 결과에는 청크 원문 필드가 없다.
- `hostname`과 `/etc/machine-id` 앞 8자를 확인해 문서 작성 조건을 통과했다.

## 직접 확인한 사실과 추정

- 직접 확인: 프롬프트 enum 값이 스키마 Literal에서 생성됨, 설명 상수와 스키마 enum 집합이 일치하는 테스트, 요약 카운트 동작, 테스트 통과, 입력 데이터에서 빈 결과 4개와 표의 길이·제목·키워드 수.
- 추정: 키워드 출현은 혜택 추출 누락 가능성을 살피는 거친 신호일 뿐, 혜택 존재나 누락을 판정하지 않는다. 제목은 청크 JSON의 제목/heading 필드 값을 그대로 사용했다.

## 못 한 것과 다음 단계

- 지정 경로 `~/pilot_work/diag3`에 쓰지 못했다. 현재 환경에서는 해당 홈 하위 경로가 읽기 전용이어서 `/tmp/diag3`를 사용했다. 결과를 사용자가 접근 가능한 위치로 옮기는 일은 이 환경에서 수행하지 못했다.

- PDF 원문 인용, LLM 호출, 네트워크 호출은 하지 않았다.

## 추가: 정확성 대조표 생성기 (`extraction/review_sheet.py`)
- 저장 결과(`*.result.json`)와 청크 폴더로 추출이 성공한 청크 N개(기본 5, 시드 고정, 길이 혼합)를 골라 사람이 원문과 대조하는 마크다운 대조표를 만든다. 청크 원문, 추출 항목 표, 인용문 위치로 잘라 본 원문 조각, 점검 체크박스(일치/값 오류/누락/환각)와 메모 칸을 담는다.
- PDF 원문이 들어가므로 저장소 안 출력 경로를 거부하고 파일 맨 위에 업로드 금지 경고를 넣는다. 보고서와 이력에는 원문을 옮기지 않았다.
- 실행: `python -m payment_card.file_pipeline.extraction.review_sheet --result-dir ... --chunk-dir ... --output ... --count 5`
- 시범 데이터(`out3`)로 생성해 `~/pilot_work/review/review_sheet.md`에 두었다(청크 5개: 항목 수 5~44). 사람의 점검은 아직 하지 않았다.
- 테스트: 새 테스트 5개. 전체 55개가 이 PC에서 통과(Claude가 직접 실행). Codex 환경에서는 저장소 밖 쓰기가 막혀 일부 실행이 실패해 보였으나 이 PC에서는 통과함.
- 빈 결과 진단 JSON은 Codex 환경이 `~/pilot_work/diag3`에 쓰지 못해 `/tmp/diag3`에 만들어졌고, Claude가 `~/pilot_work/diag3/`로 복사했다.
