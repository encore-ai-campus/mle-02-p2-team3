- 범위: 추출 호출의 제한된 동시 실행·재시도·토큰 보호, 결과 플래그 검증, 묶음 실행 계획, Woori 오프라인 준비

## 한 일

- 청크별 결과를 유지하면서 최대 16개까지 병렬 실행하고, 호출 예외는 지수 간격으로 최대 2회 재시도한다. 기본 worker는 1이다. 완료된 각 청크 결과를 즉시 저장하고 요약은 문서 처리가 끝난 뒤 한 번 쓴다.
- 기본 예상 토큰 한도 200000을 넘는 `run --execute`는 막고, `--allow-large`가 있을 때만 허용한다. 예상치는 프롬프트 문자 수/2이며 가격 또는 실제 토큰 수 보장은 아니다.
- `verify`는 숫자·단위가 항목 근거에 있는지, 관계에 연결되지 않은 항목이 있는지, 모호/누락 인용문 비율을 신호로 기록한다. 판정하지 않으며 관계 근거와 끝점 근거의 겹침은 검사하지 않는다. 출력 파일은 결과 폴더 밖에 두고 청크 ID·항목 ID·플래그 코드·비율만 기록한다.
- `pilot-run` 계획은 선택·추정만 하며 DB/LLM을 부르지 않는다. 실행 흐름은 선택·추정·run·summarize·verify·graph export 순서이며 graph load는 포함하지 않는다.
- Woori traceability와 chunking을 `/tmp/woori_trace`, `/tmp/woori_chunks`에 실행했다. OCR 필요 문서는 제외했다.

## 직접 확인한 사실과 가정

- 직접 확인: 기존 `run_batch`는 청크별 결과 파일과 재사용 가능한 결과 형식을 갖고 있었다. 병렬 변경은 각 청크 완료 때 저장하도록 했다.
- 직접 확인: 숫자 플래그 비교는 숫자와 만/천/억/콤마 표기를 정규화하는 거친 신호다. 의미상 동등성, 문맥, 모든 표기 변형을 보장하지 않는다.
- 가정: 동시성 기본값 1이 공유 파일 및 외부 호출 부하를 가장 보수적으로 제한한다. 파일 결과명은 청크 ID 기준으로 서로 다르다.
- 가정: Woori 추정 비용은 가격표 없이 토큰 수로만 보고한다. 통화 단위 비용은 산출하지 않았다.

## 하지 않은 일과 다음 단계

- 금지된 `--execute`는 실행하지 않았고 LLM·네트워크·DB 연결도 하지 않았다. `pilot-run`은 단위 테스트로 계획 모드만 검증했다.
- OCR 엔진은 설치하거나 실행하지 않았다. 그래프 적재도 하지 않았다.
- 다음 단계에서 팀이 OCR 정책, 권장 worker 수, 추정 토큰 한도를 정하고, 허용된 환경에서 소규모 실행과 결과 검토를 진행한다.
- 변경사항은 커밋하지 않았다.
