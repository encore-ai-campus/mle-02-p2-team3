# 작업 이력: 6단계 실제 LLM 시범 호출 결과 (laptop)

- 작업일: 2026-11-03
- PC: laptop (`hostname`과 machine-id 앞 8자를 개인 지침 값과 대조해 확인함)
- 역할 분담: 호출 실행과 키 설정은 사용자, 결과 집계·원인 분석은 Claude, 수정 구현은 Codex. Claude가 코드와 테스트를 다시 확인함.
- 범위: 하나카드 청크 5개, 모델 `gpt-6-luna`(사용자 선택), 저장소 밖 폴더 `~/pilot_work`. 결과 파일에는 PDF 원문 인용이 들어 있어 저장소에 올리지 않았다. 아래에는 숫자와 오류 종류만 적는다.
- 준비 과정: 하나카드 원문 추적 95개 문서(OCR 대상 2개 제외) → 청킹 543개 청크(4000자 초과 18, 200자 미만 44) → 시범 청크 5개 선정(프롬프트 약 18,338자, 추정 9,169토큰, 문자 수/2 근사치).

## 시범 호출 경과와 원인 (직접 확인)
| 회차 | 결과 | 원인 | 조치 |
|---|---|---|---|
| 1차 | 5/5 실패 `llm_call_failure` (`OpenAIConnectionError`) | 어댑터가 예외 종류만 남겨 원인을 알 수 없었다. 키가 원인으로 의심됨 | `llm_adapter.py`가 예외 연쇄 클래스명, HTTP 상태 코드, 오류 code/type을 남기도록 개선(메시지 원문과 키는 제외, 테스트로 보장) |
| 2차 | 5/5 실패, 연쇄 끝이 `LocalProtocolError` | `.env`가 CRLF(27줄 전부)여서 `source`하면 키 끝에 `\r`이 붙어 HTTP 헤더가 거부됨. curl은 관대해서 200이었음 | 어댑터가 키 앞뒤 공백·개행을 제거. `.env`는 수정하지 않음 |
| 3차 | 5/5 실패 `schema_validation_failure` | 모델이 `evidence`를 객체 목록이 아니라 문자열 또는 문자열 목록으로 냄. 프롬프트가 필드 이름만 알려 주고 모양을 보여 주지 않았음 | 프롬프트에 완전한 출력 JSON 예시와 evidence 형식 지침 추가. 예시가 `Extraction`을 통과하는지 테스트로 검증 |
| 4차 | 5개 중 4개 추출 성공(스키마 통과), 1개 스키마 실패 | 아래 참조 | 미조치 |

## 4차 결과 (프롬프트 수정 후, 5개 청크 1회 실행)
- 추출 성공 4개: 혜택 1~3, 조건 2~13, 한도 0~5, 대상 2~3, 관계 3~18개.
- 인용문 위치 부여: 87개 성공, 실패 0, 모호 4개(`quote_location_ambiguous`: 같은 인용문이 청크에서 여러 번 나타남. 청크 2개에서 각 2건).
- 스키마 실패 1개: `benefits[1].id`가 id 패턴(영문·숫자·_·-)에 맞지 않음. 청크 길이 2,660자.
- 요약 파일의 `failed`는 모호만 있는 청크도 실패로 센다. 그래서 요약상 성공 2, 실패 3이지만 실제 추출은 4개가 성공했다(요약 정의의 문제, 아래 위험 참조).

## 못 한 것과 남은 위험
- 표본이 청크 5개, 1회 실행이다. 비율(80%)은 참고일 뿐 통계가 아니다. 모델 출력은 매번 달라질 수 있다.
- 추출 내용의 정확성(원문과 의미가 맞는지)은 보지 않았다. 확인한 것은 스키마 통과와 인용문 위치 부여뿐이다. 표본 대조는 사람이 해야 한다.
- 모호 인용문은 위치를 하나로 정할 수 없다. 첫 위치를 쓰는지 등 정책이 없다(8단계 비교 기준에 영향).
- 요약 파일이 모호와 실패를 구분하지 않아 성공/실패 수가 실제보다 나쁘게 보인다.
- id 패턴 실패는 프롬프트가 id 규칙을 말했는데도 났다. 한국어나 공백이 섞인 id로 추정하지만 원인을 보지 않았다(결과 파일에 PDF 원문이 있어 열지 않음).
- `gpt-6-luna`의 접근 방식(기본 주소 사용)은 호출이 성공했으므로 지금 설정으로 충분하다.
- 열린 결정(표 한도 연결, 4000자 초과 청크, OCR)은 이번 표본으로 정하지 못했다. 4000자 초과 청크 1개(4,860자)는 추출에 성공했다.

## 다음에 할 일
1. 요약의 성공/실패 정의를 수정(모호는 별도 집계). 모호 인용문의 위치 정책 결정.
2. id 패턴 실패 원인 확인(실패 id 문자 종류만 보고), 프롬프트에 id 규칙 보강 또는 후처리 검토.
3. 청크 20개 안팎으로 확대해 오류 양상을 다시 집계. 추출 내용 정확성은 표본 대조.
4. 표의 한도 연결 등 열린 결정을 확대 표본 결과로 판단.
