# 작업 이력: 6단계 시범 호출 준비 (laptop)

- 작업일: 2026-11-03
- PC: laptop (작업 전 `hostname`과 machine-id 접두사를 개인 지침 값과 대조함)
- 범위: 배치 이어하기 보강, 시범 표본·크기 추정, LLM 어댑터와 CLI. 실제 호출·네트워크·DB는 쓰지 않음.

## 한 일

- `batch.py`: 읽기 불가·손상·객체가 아닌 기존 JSON 결과는 다시 처리하고 결과 `notes`에 재처리 사유를 남긴다. `max_chunks`는 이어하기에서 재사용한 청크를 제외하고 새 호출 수에만 적용한다.
- `pilot.py`: 인덱스의 하나카드 대표 상품 문서 중 OCR 필요가 아닌 문서의 청크를 짧음(<1000자)·중간(1000~4000자)·긴 청크(>4000자) 순환, 문서 분산, 고정 시드로 선택한다. 표식과 `택1`·`제외`·`통합 한도` 키워드는 거친 선정 신호다. 프롬프트 문자 수와 문자 수/2의 거친 토큰 추정치를 계산한다.
- `llm_adapter.py`: 저장소의 `langchain_openai.ChatOpenAI(model=..., api_key=...)`, `OPENAI_API_KEY` 관례를 채택했다. SDK는 함수 안에서 지연 import하며, 환경변수 이름을 인자로 받고 키 값이나 SDK 예외 원문을 오류에 노출하지 않는다. 모델명은 호출 인자다.
- `cli.py`: `select`, `estimate`, `run` 제공. `run --chunk-ids`로 선택 목록을 실행할 수 있다. 기본은 드라이런이고 `--execute`가 있어야 실제 호출 코드로 진입한다. 기본 최대 새 호출 수는 5이며 결과 경로가 저장소 안이면 거부한다.
- 추가 테스트는 배치 손상 결과·이어하기 수 제한, 결정적 표본·OCR 제외·크기 추정, 가짜 LLM 클라이언트·키 오류·오류 메시지 비노출·드라이런을 확인한다.

## 검증 (직접 실행)

명령:

```bash
UV_CACHE_DIR=/tmp/uv-cache PYTHONPATH=src:src/card_benefit uv run --locked --no-sync python -m pytest -q src/card_benefit/payment_card/tests/test_file_pipeline_extraction.py src/card_benefit/payment_card/tests/test_file_pipeline_extraction_runner.py src/card_benefit/payment_card/tests/test_file_pipeline_extraction_batch.py src/card_benefit/payment_card/tests/test_file_pipeline_extraction_pilot.py src/card_benefit/payment_card/tests/test_file_pipeline_extraction_cli.py
```

결과: 41 passed. 실제 하나카드 청크 폴더를 대상으로 표본을 만들거나 LLM을 호출하지 않았다.

## 직접 확인한 사실과 추측

- 직접 확인: PC 식별값 일치, 저장소의 기존 호출 예시가 `langchain_openai.ChatOpenAI`와 `OPENAI_API_KEY`를 쓴다는 점, 가짜 클라이언트 테스트와 추출 테스트 40개 통과.
- 직접 확인: 인덱스 열에는 `canonical`, `doc_role`, `ocr_needed`가 있고 `product_guide` 역할이 사용된다. 표본 로직은 이 열을 이용한다.
- 추측/근사: 표는 구분자·공백 패턴으로, 규칙은 세 키워드 부분문자열로만 표시한다. 토큰 수는 문자 수/2 근사치다. 실제 토크나이저와 의미 분석 결과가 아니다.
- 추측/미검증: 기본 분류 임계값(짧음 1000자 미만)은 시범 표본의 다양성을 위한 선택이며 최적값으로 확인되지 않았다.

## 못 한 것과 남은 위험

- 실제 PDF 청크로 선정 결과, 길이 분포, 표/규칙 사례가 적절한지 보지 않았다.
- `ChatOpenAI`가 설치된 환경에서 네트워크 연결 없이 SDK 생성 경로를 실행하지 않았다. SDK 누락 오류는 코드 경로상 한국어로 처리하지만 설치 상태는 이번 검증 범위 밖이다.
- 키 환경변수 이름은 `OPENAI_API_KEY` 기본값으로 정했지만 사용자 설정이나 키는 확인하지 않았다. 모델명·시범 수는 사용자 선택이 남았다.
- 요청 범위대로 `schema.py`, `evidence.py`, `prompt.py`, `runner.py`를 바꾸지 않았다. Git 커밋·원격 확인은 금지 범위라 하지 않았다.
