## 한 일

- 요약의 `succeeded`와 `failed`를 hard 실패 코드 집합 기준으로 다시 정의했다. `quote_location_ambiguous`는 경고로 분리했다.
- `with_warnings`, `warnings_by_code`를 추가했다. 기존 `failures_by_code`는 모든 코드의 집계로 유지했다. 기존 요약 키는 유지했다.
- 저장된 청크 결과를 다시 읽어 요약 파일을 만드는 `summarize --chunk-dir ... --output-dir ...` 명령을 추가했다. 이 경로는 LLM 호출을 하지 않는다.
- 프롬프트에서 `benefit-1` 등 순번형 id 예시를 강조하고 한글·공백 금지와 의미 기반 이름 회피를 명시했다.
- `locate_quote`는 중복 위치가 있어도 첫 번째 위치를 반환하며 발생 횟수를 함께 반환한다. 실행기는 그 위치를 결과에 기록하고 `quote_location_ambiguous`도 추가한다. 정책 선택은 미변경.

## 진단 (직접 확인)

- 요청된 로컬 결과 폴더에서 schema validation 실패 결과 파일 하나를 찾고 해당 실패 메시지만 검사했다.
- 실패 id 값 자체는 기록하지 않았다. 패턴 위반 문자 종류는 한글과 공백이었다.
- 개인 지침에서 요구한 호스트 환경 확인 조건은 충족했다. 호스트 식별 정보는 기록하지 않는다.

## 직접 확인과 추측

- 직접 확인: 기존 요약은 failure 배열이 비어 있지 않으면 청크를 실패로 셌다. `locate_quote`는 첫 일치 위치를 선택하며 중복 횟수를 세었다. 로컬 schema 오류 메시지에는 한글 및 공백이 id 패턴을 벗어난 문자 종류로 나타났다.
- 추측: 한글·공백을 포함한 id는 이번 스키마 실패를 설명하는 원인으로 보인다. 오류 메시지로 확인한 문자 종류를 넘어 구체적인 id 내용은 공개하지 않는다.

## 못 한 것과 다음 할 일

- 모호 인용문을 첫 번째 위치로 확정할지, 위치를 비워둘지, 주변 문맥을 더 요구할지는 미결정이다. 선택지는 첫 번째 채택, 모호 표시 유지, 주변 맥락 요구다.
- schema/runner에서 id 자동 정규화는 하지 않았다. 정규화하면 추출 엔티티 id와 관계 `source`/`target` 참조가 서로 다르게 변환되어 연결이 끊길 수 있다. 필요 시 엔티티와 모든 참조를 같은 매핑으로 변환하고 충돌·중복을 검증하는 원자적 설계를 먼저 정해야 한다.
- 확대 표본 시범과 추출 내용의 원문 대조는 별도 작업이다.
