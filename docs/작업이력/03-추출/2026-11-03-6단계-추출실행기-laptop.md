- PC: laptop (`hostname`과 machine-id 앞 8자를 CLAUDE.local.md 값과 대조해 확인함)
- 역할 분담: Claude가 지시문을 쓰고 검토, Codex가 구현. 구현 보고는 Claude가 diff를 읽고 테스트를 다시 돌려 확인함.
- 범위: `file_pipeline/extraction/`의 새 파일 2개와 테스트 1개. 실제 LLM 호출, DB, 네트워크는 쓰지 않음.

## 한 일
- `extraction/prompt.py`: 청크 1개용 프롬프트. 엔티티·관계의 필드 이름, 필수/선택, enum 허용값, 허용 관계쌍은 `schema.py`에서 읽어 만들어 스키마와 어긋나지 않는다. 온톨로지 규칙 검토에서 확정한 규칙(한도 연결, 공유 한도, 택1, 제외 목록, EXCLUDES 사용 조건)을 문장으로 넣었다. 표의 값/한도 라벨 연결은 미확정이라 "확실하지 않으면 연결하지 말 것"으로만 두었다.
- `extraction/runner.py`: `run_chunk(chunk, doc_sha256, llm_call)`. 응답 JSON 파싱 → `Extraction` 검증 → 인용문마다 `locate_quote`로 (`doc_sha256`, `page_no`, `start_pos`~`end_pos`) 부여. 실패는 `json_parse_failure`, `schema_validation_failure`, `quote_location_failure`, `quote_location_ambiguous`, `empty_result`로 구조화해 기록하고, 위치를 못 찾은 인용문은 버리지 않고 `location=None`으로 남긴다. 청크 길이를 결과에 기록한다(4000자 초과 특별 처리 없음). 응답 전체가 ` ```json ` 펜스이면 펜스만 벗기고 `notes`에 기록한다.
- 테스트: 정상, JSON 깨짐, 스키마 위반, 인용문 미발견, 인용문 중복, 프롬프트의 스키마 대조, 펜스 성공·혼합 실패.

결과: 25 passed (기존 17 + 새 8). `run_offline_tests.py`는 card_benefit 테스트를 포함하지 않아 쓰지 않았다. `UV_CACHE_DIR`는 Codex 샌드박스의 캐시 쓰기 제한 때문에 붙인 것이다.

## 못 한 것과 남은 위험
- 실제 LLM 응답으로 프롬프트 효과를 확인하지 않았다(직접 확인한 사실). 필드 이름 오류가 줄었는지는 시범 호출 후에 알 수 있다.
- 프롬프트의 의미 설명 문장은 손으로 쓴 것이라 스키마 의미가 바뀌면 따로 고쳐야 한다.
- `llm_call`이 던지는 예외는 잡지 않고 호출자에게 전파한다. 문서 순회 단위에서 청크별로 잡아 기록해야 한다.
- 코드 펜스 처리는 응답 전체가 펜스일 때만 한다. 설명문이 섞이면 실패로 센다.
- 열린 결정은 그대로다: 표의 한도 라벨 연결(시범 결과 후), 4000자 초과 청크 29개, OCR 여부.
