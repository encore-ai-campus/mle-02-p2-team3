# 작업 이력: 6단계 out9 재실행 비교 (laptop)

- PC: laptop
- 상태: 커밋 전
- 입력: `~/pilot_work/out8_hana50`과 `~/pilot_work/out9_hana50`의 동일 하나카드 50청크 결과, 저장소의 하나카드 chunks JSON
- 비용 / 소요시간: 사용자 대시보드 수치 미수신

## 직접 확인한 사실

- 두 결과 폴더 모두 50개 청크를 포함한다. `empty_result` 실패 코드는 각각 19건이며, 교집합 19건, out8만 0건, out9만 0건이다.
- out9의 유일한 `schema_validation_failure`: `targets.1.kind`, `literal_error`, enum 입력 `PAYMENT`, chunk `13a894c055fd6895-p0006-c01`.
- out8/out9의 네 엔티티 그룹 항목 수는 527/607개이며, 관계 수는 477/535개다. 기존 `variance.py`의 다섯 그룹 키(name/text/kind) 방식으로 청크 ID를 포함해 비교하면 전체 키 집합 Jaccard는 0.2521이며, out8에만 있는 키 310개, out9에만 있는 키 396개다. 청크별 Jaccard 평균은 0.5709다.
- 빈 결과 19개에 대해 길이, `table_density_report` 방식 상대 밀도 구간, 키워드별 문자열 출현 횟수와 페이지 번호를 따로 제시했다. 출현 횟수는 합계 신호 지표이며 정확성 판정이 아니다.
- `extraction/prompt.py`의 169행은 Target.kind 허용값을 제한하고 Condition 전용 값을 금지한다. 이 규칙이 `PAYMENT` 위반을 막는 직접적인 후보 규칙이다. 168행의 Limit.amount 규칙은 이번 남은 위반 경로와 직접 관련이 없다.
- 신규 비교 노트북은 출력이 비어 있으며, 네 셀에서 지표 비교, 양쪽 빈 결과의 신호 집계, 선택 청크의 화면 표시, 선택 청크별 항목 수 비교를 제공한다.

## 추정

- 키워드 출현 횟수가 많은 빈 결과가 사람 검토 우선순위가 높을 수 있다. 휴리스틱 기반 정렬이며 누락 혜택의 증거가 아니다.
- 두 실행의 키 변화는 프롬프트 규칙 효과와 실행 변동이 함께 반영될 수 있어 단일 원인으로 분리할 수 없다.

## 하지 않은 것 / 한계

- PDF 본문, 청크 본문, 인용문 본문은 이력에 기록하지 않았다.
- 사람의 원문 대조, 항목 정답 판정, 원인 확정은 하지 않았다. 비용과 시간은 대시보드 수치가 없어 기록하지 못했다.
- `extraction/prompt.py`는 분석만 했고 수정하지 않았다. LLM 호출, 네트워크 접근, 커밋은 하지 않았다.
