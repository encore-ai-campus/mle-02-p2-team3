## 확인한 내용

**소스를 직접 읽어 확인:** `file_pipeline/extraction/accuracy_review.py`의 `prepare`는 결과와 청크 JSON을 연결하고, 혜택 항목이 있는 청크만 길이 구간(`<=999`, `1000-1999`, `2000-3999`, `>=4000`)으로 나눈다. 구간별 모집단에 비례해 표본 수를 배분하되 표본이 가능한 비어 있지 않은 구간에는 최소 2개를 배정하고, 전체 수가 목표보다 작으면 전체를 사용한다. 구간 안에서는 chunk_id 정렬 후 `random.Random(seed).sample`을 쓰므로 같은 입력·시드면 재현된다. 표본 수가 구간별 최소치에 못 미치면 오류를 낸다.

출력 경로가 저장소 안이면 거부한다. 기존 판정표나 번호 형식 열람 파일이 있으면 `--overwrite` 없이는 중단한다. 덮어쓰기를 명시하면 기존 번호 형식 열람 파일을 지운 뒤 새 표본 파일을 쓴다. chunk_id는 파일명에서 영문자·숫자·밑줄·하이픈 외 문자를 `_`로 치환한다. 판정표에는 원문을 넣지 않지만 `accuracy_view/`의 열람 파일에는 청크 원문 전체를 기록한다.

`tally`는 마크다운 표의 verdict 셀만 읽고 메모는 무시한다. 체크 표시는 대소문자 무관 `x`, `✓`, `v`로 처리하며, 판정 체크가 정확히 하나면 해당 분류, 둘 이상이면 중복, 없으면 미판정이다. 정밀도는 `맞음 / (맞음 + 틀림 + 일부 누락)`이며, 미판정·중복은 분모에서 제외한다. 판정된 행이 없으면 정밀도를 계산하지 않는다. JSON 내보내기는 행별 chunk_id와 판정만 담는다.

`tests/test_file_pipeline_extraction_accuracy_review.py`를 직접 읽어 재현성·시드 변경, 빈 구간과 모집단 상한, 저장소 내 출력 거부, 기존 파일 보호 및 덮어쓰기, 파일명 치환, verdict 셀만 집계·정밀도·JSON에서 메모 제외를 합성 입력으로 점검하는 것을 확인했다. `notebooks/accuracy_review_check.ipynb`는 합성 입력으로 prepare 후 판정표 체크와 tally 호출을 보여 준다. `notebooks/모듈-점검-목록.md`에는 `accuracy_review | 있음 | accuracy_review_check.ipynb | prepare와 tally`가 이미 등록돼 있다.

## 표본 준비 실행

다음 실행 결과는 사용자가 전달한 **Claude 직접 실행 확인**이다. 실행 중인 `~/pilot_work/full_hana`와 결과 폴더는 이 작업에서 열거나 읽지 않았다.

- 입력: 하나카드 전체 결과, seed `20261104`, 표본 크기 `30`
- 출력으로 확인됐다고 전달된 경로: `~/pilot_work/review/accuracy_verdicts.md`, `~/pilot_work/review/accuracy_view/` 아래 열람 파일 30개
- 길이 구간별 수: `<=999: 14`, `1000-1999: 7`, `2000-3999: 7`, `>=4000: 2` (합계 30)
- 사용자 판정은 아직 없어 전부 미판정이며 정밀도 수치는 미확보다.

판정자는 각 열람 파일에서 추출 요약과 원문을 비교해 판정표에 `맞음`, `틀림`, `일부 누락` 중 하나를 체크한다. `일부 누락`은 청크 요약만으로 결정하지 말고 사람이 원문 전체를 확인해야 한다. 집계는 다음처럼 실행한다.

```bash
PYTHONPATH=src:src/card_benefit uv run --locked --no-sync python -m payment_card.file_pipeline.extraction.accuracy_review tally --sheet ~/pilot_work/review/accuracy_verdicts.md
```
