## 직접 확인한 사실

### 전체 실행 집계

`extraction/full_run_report.py`를 읽어 확인했다. `build_report`는 기존 실행 결과와 청크 메타데이터에서 청크 성공/실패, 빈/부분 결과, 실패 코드, 위치 근거 성공·실패·모호, 스키마 경로·enum, 그룹별 항목·근거, 길이 구간, 긴 청크 ID, 표 밀도 high 빈 청크 ID를 집계한다. 출력 키는 `chunks`, `success_chunks`, `failure_chunks`, `empty_chunks`, `partial_chunks`, `failures_by_code`, `location_evidence`, `schema_violations`, `groups`, `long_chunks`, `empty_high_density_chunk_ids`, `length_buckets`, `ambiguity_evidence_count`, `diagnosed_empty_count`다. 출력은 수치·식별자 메타데이터이며 원문 본문을 기록하지 않는다.

```bash
UV_CACHE_DIR=/tmp/uv-cache PYTHONPATH=src:src/card_benefit uv run --locked --no-sync python -m payment_card.file_pipeline.extraction.full_run_report --result-dir <결과 폴더> --chunk-dir <청크 폴더> --output-json <저장소 밖 JSON 경로>
```

실행 결과 JSON은 저장소 안에 쓰지 않도록 검사한다.

### 값 정규화

`graph/normalize_values.py`, 변경 diff, 테스트 및 `normalize_check.ipynb`를 확인했다. 보수적 파서가 다음을 처리하도록 확장된 것이 확인된다.

- 정확한 금액 뒤 할인·보상·교환권 표기.
- 역방향 단위 표기(금액당 적립 단위)와 마일리지 계열 단위.
- 문장 안에 숫자 조건이 하나만 있는 경우의 이상/이하 경계.
- 금액 구간의 이상~미만 형태.
- 모호한 표기나 여러 숫자 경계는 계속 미해석으로 남기는 동작.

노트북에는 합성 입력 예시 네 가지가 있고 실행 출력은 비어 있다. 개선 전후 성공률은 노트북·테스트·diff에서 확인되지 않아 **미확인**이다. 이전 기록의 수치를 현행 성공률로 취급하지 않았다.

## 추정 및 못 한 것

- **추정**: 정규화 확장은 지원 가능한 표기 범위를 좁은 규칙으로 넓히면서 모호 입력은 미해석으로 유지하려는 목적이다.
- 못 한 것: 전체 회귀 테스트는 이 문서 작성 시점에 실행하지 않았다. 실데이터 성공률·정확도 비교도 하지 않았다.
