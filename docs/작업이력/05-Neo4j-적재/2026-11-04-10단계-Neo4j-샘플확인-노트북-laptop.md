# 10단계 Neo4j 샘플 확인 노트북

## 정적 검토에서 확인한 문제와 수정

1. 근거 ID가 파일 내 순번이어서 샘플 간 충돌 가능성이 있었다. `node_id`, `edge_id`, `doc_sha256`, 페이지·위치, `quote_status` 기반 SHA-256 앞 20자리로 변경하고 중복 근거는 한 건으로 합친다.
2. 카드·발행사·세부 항목·근거의 화면 캡션 `name`이 없었다. 요청한 기준으로 캡션을 추가한다.
3. 관계 및 근거 연결에서 라벨 없는 `MATCH`가 사용됐다. 관계 타입별 양 끝 라벨을 고정하고 근거 연결도 노드 라벨별로 생성한다.
4. `SET n += row`와 `MERGE`의 덮어쓰기 조건 설명이 없었다. 같은 라벨+id의 동일 데이터 재적재만을 전제로 한다는 주석을 추가한다.

## 노트북 구성

`neo4j_sample_check.ipynb`는 설정, 연결, 기존 Fp 라벨, 샘플 정적 검사, 적재, 확인 질의, 그래프 그림, Fp 데이터 정리, 연결 종료 순서다. 출력은 비워 둔다.

## 안전장치 및 한계

`WRITE`, `ALLOW_REMOTE`, `CONFIRM_DELETE` 기본값은 False다. 접속 정보 값은 출력하지 않고, 적재·정리는 로컬 연결 또는 명시적 원격 허용과 각 확인 옵션이 있어야 진행한다. 샘플은 Fp 라벨·FP_ 관계만 사용하며 정적 검사 실패 시 적재하지 않는다. 그래프 질의는 최대 두 단계와 80개 제한을 둔다.

Codex는 Neo4j에 접속하지 않아 실제 연결·적재·조회 결과는 미확인이다. 노트북 코드 셀의 compile 검사 및 로컬 테스트만 확인하며 커밋 전 상태다.
