# 작업 이력: 10단계 적재 배치화·run 삭제 (PC: laptop)

- 적재 전 코드는 `pf_load_runs → pf_nodes → pf_edges → pf_evidence` 순으로 각 행마다 `cursor.execute`를 호출하는 것을 확인했다.
- 테이블별 최대 1,000행 `executemany` 배치 적재를 적용했다. COPY 대신 행 값 변환과 psycopg 드라이버 어댑테이션을 그대로 활용하는 경로를 택했다. 한 트랜잭션, 중복 run 거부, evidence identity id 컬럼 제외, 안전한 오류 메시지를 유지했다.
- `--delete-run <run_id>`의 건수 드라이런과 `--execute` 삭제를 추가했다. evidence → edges → nodes → load_runs 순서이며, 삭제 전 COUNT를 반환하고 모든 run 값은 바인드 파라미터로 전달한다.
- 합성 CSV 적재 테스트, 배치 크기(2,500행 → 1,000·1,000·500), 삭제 dry-run/순서/파라미터/미존재 run, 롤백·중복·오류 비노출 테스트를 추가했다.
- 실제 DB에는 접속하지 않았고 가짜 연결 검증만 했다. 처리 속도 개선 폭은 미측정이다. 기존 약 12~35분에서 1분 안팎이라는 값은 실행 환경을 반영하지 않은 가정이다.
- 다음 할 일: 사용자 환경 변수 설정 후 드라이런, 사용자 승인 후 실제 적재, 커밋 전.
