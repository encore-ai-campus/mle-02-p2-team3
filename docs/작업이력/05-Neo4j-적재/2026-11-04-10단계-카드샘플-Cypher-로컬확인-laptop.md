# 카드 샘플 Cypher 로컬 확인

- PC: laptop
- 목적: 사용자가 카드 1~2개 분량을 Neo4j Browser에 붙여 넣어 혜택·조건·한도·대상과 근거 연결을 확인하도록 샘플 옵션을 추가했다.
- 옵션: `--list-cards N`, 반복 가능한 `--card-id`, `--max-benefits`(기본 15). 목록은 혜택 수와 카드 ID로 결정적으로 정렬하며, 샘플은 선택 카드의 연결만 남기고 잘린 혜택 수를 표시한다.
- 선택 카드:
  - 하나카드: `#tag1카드 Orange`, `card:hana:101803300941916`, 연결 혜택 15개(조건 21, 한도 10, 대상 16).
  - 우리카드: `카드의정석2`, `card:woori:102997`, 연결 혜택 20개(조건 32, 한도 16, 대상 13).
  - 공유 혜택 확인용 우리카드: `the OPUS silver Biz`, `card:woori:500007`, 연결 혜택 20개. CSV에서 6개 혜택이 다른 카드와 공유되며, 샘플에는 공유 혜택 1개가 포함되고 다른 카드의 OFFERS 엣지는 제외된다.
- 생성 파일(저장소 밖):
  - `/tmp/fp-sample-hana.cypher`: 305줄, 55,391바이트, 노드 54, 엣지 61, 근거 127, 잘린 혜택 5, MERGE 구문 12개.
  - `/tmp/fp-sample-woori.cypher`: 272줄, 47,591바이트, 노드 54, 엣지 52, 근거 103, 잘린 혜택 36, MERGE 구문 12개.
- Neo4j 사용 방식: 새 컨테이너를 만들지 않고 사용자가 이미 쓰는 Neo4j(`graphrag-neo4j`, 7474/7687)를 쓴다(사용자 결정). 샘플은 `Fp` 라벨과 `FP_` 관계만 만들어 기존 데이터와 섞이지 않고, 정리도 `Fp` 라벨 한정 문장만 쓴다. 비밀번호는 문서에 쓰지 않는다(`.env`의 `NEO4J_*`). 처음 작성 때 별도 컨테이너(`fp-neo4j`, 17474)를 안내했으나 사용자 결정과 달라 README와 이 이력을 정정했다(Claude).
