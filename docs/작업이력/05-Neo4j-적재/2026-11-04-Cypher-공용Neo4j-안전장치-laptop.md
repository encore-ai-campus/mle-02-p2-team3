# Cypher 변환과 공용 Neo4j 안전장치

- PC: laptop
- 날짜: 2026-11-04
- 상태: 커밋 전

## 직접 확인한 사실

- `graph/cypher_export.py`는 CSV의 노드·관계·근거를 Neo4j Browser용 스크립트로 변환한다. 허용된 노드 유형·관계 유형을 검증하고, 문자열 이스케이프와 속성 변환을 수행하며, 일괄 처리에 `UNWIND`와 재실행 가능한 `MERGE`를 사용한다.
- `graph/cypher/README.md`에는 실행 중인 공용 Neo4j를 사용하고 새 인스턴스를 시작하지 않는 안내, 브라우저에서 로그인하도록 하는 절차, `Pf` 라벨 사전 점검, 프로젝트 범위 초기화 방법이 있다. 비밀번호는 문서에 없다.
- 그래프 분리는 `Pf` 노드 라벨과 `PF_` 관계 접두사로 제한한다. 유형 값 검증으로 라벨/관계 이름 주입을 거부하며, 초기화는 `Pf` 라벨이 붙은 노드로 한정하고 공용 DB 전체 삭제를 금지한다.
- `queries.cypher`에는 라벨별 개수, 카드 혜택, 조건·한도·대상, 모호 근거, 상호 배타 관계를 살펴보는 질의 예시가 있다.
- Cypher export 테스트 파일이 존재한다. 테스트 63개 통과 및 `/tmp/pf-graph-out7/load.cypher` 보고값은 사용자 제공: 921줄, 노드 208, 관계 251, 근거 394. 생성물은 저장소 밖이다.
- 점검 목록에서 `cypher_export`, `full_run_report`, `empty_review`, `normalize_values`의 노트북 등록을 확인했다.

## 추정 및 미확인

- 사용자가 로컬에 신규 컨테이너를 띄우지 않고 다른 프로젝트 데이터가 있을 수 있는 기존 Neo4j를 쓰기로 한 결정은 사용자 제공 정보다.
- 사용자가 브라우저에 직접 자격 정보를 입력하는 것으로 안내되어 있다. 암호는 기록하지 않았다.
- 실제 Neo4j 적재 실행 여부와 결과는 미확인이다. 생성 스크립트의 적재 성공을 의미하지 않는다.

- 못 한 것: Neo4j 연결·적재를 실행하지 않았고 기존 DB 상태를 조회하지 않았다. 비밀번호를 받거나 저장하지 않았다.
- 다음 할 일: 사용자가 브라우저에서 사전 점검 후 직접 적재하고, 적재 결과를 확인한다.
