# 11단계 OCR 상태 점검

PC: laptop

## 목적
우리카드 이미지 문서 45개의 OCR이 어디까지 됐는지 확인하고 사람 대조를 시작할 수 있게 한다.

## 직접 확인한 사실
- `/tmp/ocr-woori2`에 문서 45개, 126쪽의 쪽별 텍스트와 `.ocr.json`이 있다(`/tmp`는 임시 폴더라 보존이 보장되지 않는다).
- 쪽 통계 집계: 평균 신뢰도 82.5, 최저 18.2. 3단어 미만이라 텍스트가 빈 쪽 7개. 낮은 신뢰도 단어 비율은 쪽 평균 17%, 최대 100%.
- 대조 시트를 같은 명령으로 다시 생성했다: `/tmp/ocr-review-priority.html`(우선순위 20쪽, 3,603,953바이트). 시트 안의 판정은 하지 않았다.
- 사람 판정 CSV는 아직 없다.

## 신뢰도 분포와 우선 대조 후보 (직접 집계, tesseract 자체 신뢰도)
- 3단어 이상 119쪽 기준: 신뢰도 80 이상 94쪽, 60~80 19쪽, 60 미만 6쪽. 빈 쪽 7개는 5개 문서에 걸쳐 있다.
- 낮은 쪽(doc_id 앞 8자, 쪽): `14c88336` 6·1쪽, `717df424` 3·1쪽(신뢰도 36~46, 낮은 단어 비율 83~84%). 두 문서의 값이 쌍으로 같아 중복 문서일 가능성(추정, 미확인). `0f958948` 3쪽은 단어 6개로 거의 읽히지 않음. `17c32eb4` 1쪽, `746eafb8` 1쪽은 단어 1,300개 이상이지만 신뢰도 59~65.
- 이 쪽들이 현재 우선순위 20쪽 시트에 모두 들어 있는지는 확인하지 않았다.
- 사람이 대조할 때 위 쪽을 먼저 보면 효율적이다.

## 하지 않은 것
- 추출 재실행(OpenAI 비용 발생), 통합 export, DB 교체는 하지 않았다.
- 쪽 이미지를 직접 열어 OCR 정확성을 확인하지 않았다. 신뢰도는 tesseract 자체 값이다.

## 남은 위험
- OCR 오류가 금액·조건을 바꿀 수 있다. 빈 쪽 7개와 신뢰도 낮은 쪽의 실제 내용 손실은 미확인.
- 신뢰도 100% 낮음 쪽은 OCR 설정(dpi 등) 변경 여부를 판단해야 한다.

## 다음 할 일
1. 사람이 우선순위 20쪽을 대조하고 판정 CSV를 내려받는다.
2. 결과로 OCR 설정 변경 여부를 정한다.
3. 통합 추출(비용 승인)과 기존 run 교체(DB 쓰기는 사용자 실행).
