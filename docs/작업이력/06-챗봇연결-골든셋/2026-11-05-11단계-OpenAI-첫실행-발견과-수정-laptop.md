# 2026-11-05 11단계 OpenAI 답변 시험 첫 실행의 발견과 수정

PC: laptop

## 목적
`gpt-6-luna` 로 실제 챗봇 흐름(LLM 이 이름을 고르고 답변)을 하나카드 사람형 질문으로 시험했다. 3문항 소량 실행을 세 번 하며 원인을 좁혔다. 실행은 사용자가 했고(DB 읽기 전용, 비용 상한 $0.04), 비용은 3문항당 약 $0.002~0.003 이다.

## 발견 (직접 확인한 사실)
1. 팀 `llm.py` 가 `anthropic` 을 import 하는데 이 PC 에 없어 `rag` import 가 실패했다. 래퍼가 `sys.modules["llm"]` 대체 모듈을 먼저 주입해 해결했다. 검색 시험(retrieval_eval)의 DB 모드는 `db` 모듈만 쓰도록 고쳤다.
2. 적재 버그: CSV 빈 칸이 `''` 로 들어가 `fp_evidence_exactly_one_target` 위반(적재 롤백, DB 0건 확인). `load.py` 가 `node_id`·`edge_id`·`chunk_id` 빈 값을 NULL 로 바꾸도록 수정하고 회귀 테스트를 추가했다.
3. 첫 실행 3문항 모두 검색 실패(시드 0). 호출 로그(`FP_LLM_CALL_LOG`)로 원인 확인: LLM 은 이름을 제대로 골랐지만 후보 목록 형식 `이름(라벨)` 을 따라 `대명아임레디 플러스 하나카드(Card)` 처럼 라벨을 붙여 답했고, 팀 `rag.analyze` 는 라벨 없는 이름과 정확히 일치해야 인정해 전부 버렸다. 래퍼가 entities 항목 끝의 라벨 단어를 떼도록 수정(`normalize_entities`).
4. 종료 사유는 모두 `stop` 이었고 추론 토큰은 208~400 이었다. 토큰 상한 400 이 부족할 수 있어(추정) 최소 예산 2,000 을 두었다.
5. 두 번째 원인: 후보 목록이 `order by name limit 300` 이라 흔한 단어가 많이 걸리면 정답 엔티티가 잘린다(CSV 재현: 하나카드 12문항 중 3개). 단어 중요도(흔한 단어는 낮게) 순 정렬로 바꾸면 CSV 재현에서 12/12 였다(표본 작음, 아직 DB 실측 전).
6. 수정 후 3문항 결과: hana-01 은 정답 3개를 모두 설명했지만 자동 판정은 오답으로 분류(기대값이 노드 이름이라 표현이 다르면 놓침). hana-02 정답. hana-03 은 후보에서 정답 혜택이 빠져 엉뚱한 한도를 답했다(5번 수정 전 실행). hana-03 의 정답 '12000' 은 전월 실적 구간별 한도(12,000/19,000) 중 하나라 질문이 모호하다.

## 수정한 파일
`graph/load.py`, `chat/retrieval_eval.py`, `chat/openai_llm_patch.py`(라벨 제거, 최소 토큰 예산, 호출 진단 로그), `chat/fp_chat_patch.py`(후보 정렬), `chat/review_sheet.py`(PDF 경로 후보에 `src/data` 추가). 새 테스트 파일 `test_file_pipeline_openai_patch_budget.py`.

## 한계
