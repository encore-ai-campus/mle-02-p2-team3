# 11단계 골든셋 양식과 원문 확인 시트

- PC: laptop
- 목적: 사람이 PDF 근거를 확인해 만든 하나·우리 카드 질문을 기존 답변 평가 하네스에 넣고, 검색된 그래프 근거와 원문 위치를 빠르게 검수한다.
- 장비 확인: 작업 지침의 PC_ID `laptop`, hostname 및 machine-id 접두사를 대조했다.
- 작업 전 이력 확인: 최근 작업이력 몇 건을 읽었다. 사용자의 네트워크 금지 및 git 쓰기 금지에 따라 `git fetch`는 실행하지 않았다. 작업이력 인덱스는 사용자 지시대로 수정하지 않았다.

## 변경

- `chat/golden_set_template.csv`: UTF-8 BOM 한글 헤더와 합성 예시 2행. 실제 카드 혜택·수치는 넣지 않았다.
- `chat/golden_set.py`: 필수값·enum·정답없음 사실 규칙·중복 ID·쪽 번호를 검사하고 모든 행 오류를 모은다. 검수자 누락은 경고다. CSV 유형은 `혜택조회→card_benefits`, `조건→benefit_condition`, `한도→benefit_limit`, `제외→benefit_excludes`, `숫자정확도→benefit_limit`, `비교→comparison`, `정답없음→no_answer`로 변환한다. 카드사는 `하나→hana`, `우리→woori`로 변환한다. 층화 분할 키는 카드사×유형이며 출력은 `/tmp`만 허용한다.
- `chat/review_sheet.py`: 답변 결과·질문·그래프 CSV 및 문서 인덱스를 연결한 자체 포함 HTML과 CSV를 만든다. 검색된 뷰 노드 UUID를 `md5(fp id)::uuid` 규칙으로 원래 CSV ID에 대응시키며 의미 노드의 직접 근거와 끝점 엣지 근거를 병합·중복 제거한다. HTML 문자는 이스케이프한다. PDF 링크는 로컬 `file:///...#page=N` 형식이다. 근거 최대 개수 초과분은 별도 건수로 표시한다.
- `chat/answer_eval.py`: 결과에 `retrieved_node_ids`(최대 200)를 포함하고, `no_answer: true`는 답변 포함 대신 거절 여부로 성공을 판정하며 요약에 정답없음 거절률을 추가했다. 파일은 현재 git 기준 untracked여서 기존 기준 파일과의 diff를 산출할 수 없다(현재 파일 전체 199줄).
- `tests/test_file_pipeline_golden_set.py`, `tests/test_file_pipeline_review_sheet.py`, 기존 `tests/test_file_pipeline_answer_eval.py`에 합성 자료 검사를 추가했다.
- `notebooks/chat_eval_check.ipynb`: 합성 골든셋 변환 및 검수 시트 셀을 추가했다. 코드 셀 출력은 모두 비우고 execution count는 null이다.

## 사용

```bash
UV_CACHE_DIR=/tmp/uv-cache PYTHONPATH=src:src/card_benefit uv run --locked --no-sync python src/card_benefit/payment_card/file_pipeline/chat/golden_set.py /path/to/golden.csv --output /tmp/golden.json
UV_CACHE_DIR=/tmp/uv-cache PYTHONPATH=src:src/card_benefit uv run --locked --no-sync python src/card_benefit/payment_card/file_pipeline/chat/golden_set.py /path/to/golden.csv --output /tmp/golden.json --split-dev-ratio 0.5 --seed 7
UV_CACHE_DIR=/tmp/uv-cache PYTHONPATH=src:src/card_benefit uv run --locked --no-sync python -m card_benefit.payment_card.file_pipeline.chat.review_sheet --results /tmp/answers.jsonl --questions /tmp/questions.json --csv-dir /tmp/fp-check-hana --csv-dir /tmp/fp-check-woori --documents src/card_benefit/data/index/hana/documents.csv --documents src/card_benefit/data/index/woori/documents.csv --output /tmp/review.html --with-excerpt
```

HTML에서 질문, 기대 사실, 답변, 자동 분류, 선택 시드, 근거 위치와 PDF 페이지 링크를 확인한다. 버튼으로 실패/놓친 문항만 걸러볼 수 있다. `--with-excerpt`는 PyMuPDF의 페이지 텍스트에 trace 위치의 1-based 포함 끝 인덱스를 적용한다. traceability는 `DocumentReader`로 페이지 텍스트를 만든다. PDF가 없으면 `PDF 없음`, 슬라이스가 비거나 범위를 벗어나면 `위치 불일치`로 표시한다.

## 검증 결과와 한계

- 지정 표준 테스트: `241 passed in 3.73s`.
- 별도 notebook coverage: 실패 1, 통과 3. 실패 테스트는 새 `chat/golden_set`, `chat/review_sheet`와 동시 작업 중인 `ocr_pages`가 점검 목록 집합에 없어 모듈 목록과 불일치한다고 보고했다. 점검 목록은 수정하지 않았다.
- 실데이터 연결은 로컬 파일만 사용하고 질문 4개에 합성 답변 `테스트 답변`과 seed 이웃 노드 ID를 만들었다. `/tmp/fp-review-sample.html` 및 `.csv` 생성 완료. 근거 위치 48건 중 46건이 `located`, 2건이 `ambiguous`였다. 연결된 PDF 원본 파일은 로컬 경로에 없어 46건이 `PDF 없음`으로 표시됐다. 텍스트 발췌 성공률은 평가 가능한 PDF 0건으로 미산출이다. 이는 trace와 PyMuPDF 위치 체계가 다르다는 증거가 아니다.
- trace의 페이지 텍스트 위치는 1-based, 끝 포함이다. PyMuPDF 추출 텍스트가 `DocumentReader`의 페이지 텍스트와 동일하게 처리된다는 보장은 확인하지 못했다. PDF 접근 가능한 환경에서 다시 비교해야 한다.
- 테스트 데이터는 합성이다. PDF 원문 텍스트를 이력에 기록하지 않았다. DB·LLM 연결은 실행하지 않았다.
