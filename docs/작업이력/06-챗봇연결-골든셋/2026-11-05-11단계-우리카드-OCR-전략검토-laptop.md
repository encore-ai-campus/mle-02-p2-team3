# 2026-11-05 11단계 우리카드 적재·OCR 전략 검토

PC: laptop

## 목적
우리카드는 텍스트 문서 111개(청크 489개)만 추출·변환했고, 이미지(스캔) 문서는 OCR 미설치로 제외됐다. 우리카드를 언제 어떻게 적재하고 OCR을 어떻게 할지 정하기 위해 인덱스를 직접 집계하고 Codex 읽기 전용 검토와 대조했다.

## 직접 확인한 사실 (documents.csv, product_docs.csv)
- 대표 문서(canonical) 163개 중 텍스트 118개(488쪽), 이미지 45개(126쪽). 이미지 문서의 38개는 2쪽짜리다.
- 이미지 45개의 종류: 상품 안내서 25, 공통 브랜드 서비스 19, 미분류 1. 공통 브랜드 서비스는 전체 21개 중 19개가 이미지다.
- 이미지 상품 안내서 25개가 연결된 상품 25개 중 24개는 텍스트 상품 안내서가 없다(상품명 기준). 즉 이 상품들은 현재 그래프에 혜택 정보가 없다. 예: 카드의정석2 계열, the WON, 그린카드, 스타트래블 우리카드.
- 주의: `doc_id`는 중복 문서가 공유하므로 대표 문서(canonical=Y)만 골라 합쳐야 한다. 처음 계산은 중복 행이 섞여 틀렸고 다시 계산했다.

## Codex 검토와의 대조
- Codex는 이미지 문서를 44개(124쪽: 상품 안내 25개 74쪽, 브랜드 서비스 19개 50쪽)로 집계했다. 차이 1개는 미분류 1건이다(추정, 분류 기준 차이).
- 상품 연결은 단위가 달라(코드 46개 vs 상품명 25개) 직접 비교할 수 없다. 이미지 문서에만 의존하는 상품이 여럿이라는 결론은 같다.
- 제외 지점: `doc_index/batch.py` 의 `select_documents()`, `extraction/pilot_run.py`. 쪽별 OCR 텍스트를 같은 형식으로 넣으면 청킹과 위치 계산(1-based 끝 포함)은 그대로 쓸 수 있다.
- 근거 체계에는 OCR 엔진·버전과 OCR 유래 표시가 없다. OCR 텍스트 기준 `located` 와 원본 PDF 대조를 구분할 표시가 필요하다.
- OCR 환경: `tesseract` 실행 파일 없음(확인). `kor` 언어 데이터와 PyMuPDF OCR 실행 가능 여부는 확인하지 못했다. `pyproject.toml`·`uv.lock` 에서 pytesseract, easyocr, paddleocr, ocrmypdf 는 찾지 못했다(설치 상태 확정은 아님).
- 비용(추정, 청크당 토큰은 가정 입력 1,000~3,000 출력 300~1,200): 이미지 44개 추출 재실행 약 $0.03~$0.17, 실패 청크 24개 재시도 약 $0.006~$0.022. OCR 자체 비용은 제외. 실제 청구액은 미측정.

## 적재 전략 결정
- 노드 id 는 `chunk_id:item_id`, 카드 id 는 `card:{issuer}:{product_key}` 형식이고 run 이 달라도 같은 값이 나올 수 있다. `fp_nodes.id` 가 기본키라서 OCR 결과를 별도 run 으로 추가 적재하면 같은 카드 노드가 중복 삽입되어 오류가 날 가능성이 있다(코드로 확인하지 않은 추정, 적재 전 드라이런으로 확인).
- 따라서 현재분 + OCR 결과를 합친 통합 export 를 만들고, 기존 우리카드 run 을 `--delete-run`(드라이런 먼저)으로 교체하는 쪽을 택한다.
- 우리카드 현재분의 적재 시점은 OpenAI 답변 시험(하나카드 기준) 뒤로 미룬다. 두 카드사가 섞이면 같은 이름 노드가 늘어 기준 수치가 흐려지기 때문이다.
