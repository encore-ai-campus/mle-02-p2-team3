# 11단계 자동 판정 개선

PC: laptop

## 목적

저장된 챗봇 답변 결과를 DB나 LLM 호출 없이 재판정하고, 숫자·단위·이름·해시 판정의 근거를 기록한다.

## 판정 규칙

| 항목 | 규칙 |
|---|---|
| 숫자 변환 | 쉼표와 공백을 처리하고 천·만·억을 수치로 환산한다. |
| 단위 구분 | 원·점·회·%·개월·일을 구분한다. 질문 유형에 따라 기대값에 단위가 없는 경우 환산 숫자도 허용하며, 서로 다른 단위는 일치시키지 않는다. |
| 날짜 | YYYY년 M월 D일 형태의 날짜 내부 숫자는 독립 기대 숫자와 일치한 것으로 세지 않는다. |
| 해시 | 8자 이상 hex 해시는 토큰 경계에서 앞 8자 기준으로 확인하며, 더 긴 해시도 앞부분으로 판정할 수 있다. 숫자만으로 된 값은 해시 취급하지 않는다. |
| 이름 핵심 토큰 | 일반 조사·일반어를 뺀 핵심 토큰이 80% 이상 겹칠 때 `name_partial`로 판정한다. |
| 짧은 이름 예외 | 핵심 토큰이 하나뿐이거나 정규화 길이가 짧은 이름에는 부분 일치를 적용하지 않는다. |
| 정확 일치 | 원문 부분 문자열이면 `exact`, 공백·기호 정규화가 필요한 문자열이면 `exact_normalized`를 기록한다. |
| 엄격 수치 보존 | 기존 `expected_values_in_answer_strict`는 정규화 전 문자열 비교 결과를 유지한다. 새 판정 결과는 `expected_values_in_answer` 및 `value_matches`에 기록한다. |

## 재판정 결과

입력 `/tmp/fp-answer-24.jsonl` 24건을 `/tmp/fp-answer-24-rejudged.jsonl`로 저장했다. 엄격 규칙과 새 규칙의 문항별 모든 기대값 포함 수는 다음과 같다.

| 발급사 | 엄격 규칙 | 새 규칙 | 기대값 전체 |
|---|---:|---:|---:|
| Hana | 7/12 | 10/12 | 12문항 |
| Woori | 2/12 | 7/12 | 12문항 |

엄격 규칙에서 모든 기대값이 포함되지 않았던 문항 중 `number_unitless` 또는 `name_partial`만으로 모든 기대값을 채운 경우는 Hana `hana-09`, `hana-10`; Woori `woori-01`, `woori-02`, `woori-03`, `woori-09`, `woori-10`이다. (`hana-05`는 새로 인정된 이름 부분 일치 외에 엄격 일치도 포함한다.)

참고 수기 점검의 실제 정답 규모(Hana 약 11건, Woori 약 8~9건)와 새 규칙의 모든 기대값 포함 수(10건, 7건)는 크게 벗어나지 않는다. 다만 부분 일치가 늘어난 Woori 결과는 검수 시트에서 개별 확인이 필요하다.

## 제한

문자열 규칙은 답변에 기대 숫자가 있어도 그 숫자가 질문의 올바른 맥락에서 쓰였는지 판별할 수 없다. 골든셋과 검수 시트 기반의 사람 판단이 필요하다.
