# 11단계 챗봇 화면 실행 경로 정리

PC: laptop

## 목적
`chat/run_fp_chat.py`로 우리 카드 데이터(fp_chat) 챗봇 화면이 뜨는지 확인하고, 막힌 곳을 고친다.

## 직접 확인한 사실 (수정 전)
- 화면 로딩 시 DB·LLM을 부르지 않는다. 질문을 보낼 때만 DB와 LLM을 쓴다(`app.py` 확인).
- 그대로 실행하면 두 곳에서 실패했다.
  1. `anthropic` 없음: 팀 `llm.py`가 Anthropic을 import한다. `run_fp_chat.py`가 OpenAI 어댑터(`openai_llm_patch.install()`)를 적용하지 않았다(D2).
  2. `pyvis` 없음: `graphrag_chatbot/requirements.txt`에는 있지만 `pyproject.toml`에는 없었다.

## 한 일
- `run_fp_chat.py`: `OPENAI_API_KEY`가 환경 변수에 없으면 안내 문구를 보이고 멈춘다. 있으면 팀 코드가 import되기 전에 `install()`을 적용한다.
- `pyproject.toml`, `uv.lock`: `pyvis>=0.3.2` 추가(설치된 것은 pyvis 0.3.2, jsonpickle 4.1.4).
- 시험 `test_file_pipeline_chat_run_entry.py` 2개: 키 없음 안내, 키 있음 → "우리 카드 데이터(fp_chat) 모드". 각각 별도 프로세스, DB·OpenAI 호출 없음.
- 같은 날 `.git/info/exclude`에 `ocr-review-priority.html`과 `notebooks/학습용/`을 등록(개인 설정, 커밋 대상 아님). `학습용`의 두 파일은 `git rm --cached`로 추적만 해제(로컬 파일은 남음).

## 검증
- 새 시험 2개 통과(2.55초).
- 서버를 띄워 `/_stcore/health`와 `/`가 200인 것을 확인했다(임시 실행기, 키는 더미).

## 하지 않은 것·남은 위험
- DB 접속과 실제 질문·답변은 시험하지 못했다. 이 셸에 `DB_URL`, `OPENAI_API_KEY`가 없었고 `.env`는 열지 않는다(D4). 질문을 보내면 OpenAI 비용이 든다(추정, 미측정).
- Supabase에 `fp_chat` 읽기 뷰가 실제로 적용돼 있는지 확인하지 못했다.
- `학습용` 두 파일은 이전 커밋(`d1748f7`)으로 원격 브랜치 기록에 이미 남아 있다. 최신 트리에서만 빠진다.
