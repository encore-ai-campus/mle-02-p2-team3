## 한 일

- 골든셋 v1 80문항(하나 40·우리 40, 정답 없음 9, 변형 20 포함)을 PDF 쪽 원문에서만 작성했다(Codex 4개 파트 작성, Claude 검증·병합). 모호한 질문 10개 중 카드명이 없던 7개(+변형 1)를 카드명 포함으로 고쳤고, 변형 1개는 질문과 정답 없음 키워드가 어긋나 있어 고쳤다.
- 변형 그룹 단위로 dev 39·final 41로 나눴다(시드 7). final 은 개발에 쓰지 않는다.
- dev 를 `run_eval --mode answer --source db --limit 100` 로 3회 실행(회당 약 $0.07, 합계 약 $0.21).
- `chat/fact_judge.py`(규칙 매칭 실패 시 gpt-6-luna 판정, 정답 없음은 거절 판정)를 추가하고 3회를 채점.

- 로컬 Neo4j 적재용 Cypher 파일(하나·우리 전체, 한국어)을 생성했다. 적재는 사용자 로컬 비밀번호 문제로 미완.

- dev 3회 판정: 평균 82.9%(97/117), 질문 그룹 30개 기준 95% 구간 70~94%. 3회 모두 맞음 30, 모두 틀림 5, 들쭉날쭉 4. 정답 없음 4문항 3회 모두 거절 4/4.
- 모두 틀린 5문항 원인: 판정기 오판 1(G-W-B-02), 추출 실패 청크 1(G-W-B-06: Welfare+ 문서 두 청크가 empty_result·json_parse_failure 로 실패, 질문에 카드명도 없어 수정), 연회비 노드 미추출 1(G-W-A-11), 구간 한도 연결·추출 구멍 가능성 2(G-H-A-07 외; 원문 쪽 확인 전).

## 추가 확인(같은 날 저녁)

- 골든셋 근거 PDF 80문항 중 4문항(G-W-B-06·G-W-B-11 각 그룹)의 문서가 그래프에 없다. W_SCHOOL체크는 체크카드라 추출 범위 밖(D11, 청크·trace 파일 없음), Welfare+ 대한체육회는 추출 실패(청크 2개: empty_result, json_parse_failure). 이 4문항을 빼면 dev 평균 83.8%(88/105), 그룹 28개 기준 95% 구간 71~95%.
- 추출 자체가 실패한 청크는 하나 10개·우리 24개, 합 34개(1,032−998과 일치). 기존 문서의 "실패 청크 24개"는 우리카드만 센 값이다.
- 추출 정답 라벨 채점(`extraction/label_eval.py`, 겹침 any, 전체 라벨 기준) 재현율: Benefit 22/38, Condition 15/33, Limit 13/24, Target 13/29. 제가 독립 계산으로 같은 값을 확인했다. 정밀도 아님(라벨은 표본). 놓친 라벨 원인: 같은 쪽에 노드는 있으나 구간 안 겹침 31, 그 쪽에 같은 종류 노드 없음 18, 문서가 그래프에 없음 10, 근거 위치 미확정 2.

## 못 한 것과 남은 위험

- 모든 점수가 자동·AI 판정이다. 사람 확정 정답률은 0건. 판정기가 짧은 기대값("없음", "1%")을 놓칠 수 있다.
- 첫 실행에서 `--limit` 기본값 5 때문에 5문항만 돌았고(약 $0.03 소모), `DB_URL` 설정 누락으로 한 번 실패했다. 명령 안내가 불충분했다.
- dev 의 G-W-B-06 은 카드명을 넣어 고쳤으나 3회 결과는 수정 전 질문으로 돌았다.
- 구간 한도 추출·연결 구멍과 연회비 미추출이 데이터 문제인지 원문 쪽 확인으로 가려야 한다. 연회비를 추출 범위에 넣을지는 미결.
- 정답 라벨은 표본이라 정밀도는 계산할 수 없다. 의미(종류) 정확성은 사람 확인 전이다.
