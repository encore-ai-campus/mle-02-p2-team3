# 답변 형식 v2 프롬프트와 질의응답 로그 기록

- 날짜: 2026-11-05
- PC: laptop
- 상태: 코드·테스트 완료, 실제 화면·DB 적재는 미실행. 커밋 시점에 함께 올림

## 배경

답변이 한 덩어리 문단으로 나왔다. 직접 원인은 팀 `rag.py` 의 `ANSWER_SYSTEM` 이 "한국어로 3~4문장 안에 답하세요"라고 시키는 것이다. 팀 코드를 고치지 않고 우리 래퍼(`chat/fp_chat_patch.py`)에서 이 상수를 교체한다(결정 D3 유지).

## 한 일 (Codex 구현, Claude 검증)

- `chat/answer_format.py`: 프롬프트 `ANSWER_SYSTEM_V2`(한 줄 요약, `**[적립]**` 같은 굵은 대괄호 소제목, 혜택마다 글머리표와 조건·한도 하위 항목, 확인되지 않은 항목 한 줄, 단일 사실 질문은 2~3줄)와 후처리 검사 `check_answer_format`(LLM 호출 없음). 환경변수 `FP_ANSWER_FORMAT=legacy` 로 원래 프롬프트 복원.
- `chat/qa_log.py`: 질문 1건을 JSONL 한 줄로 기록(`FP_QA_LOG` 설정 시에만, `/tmp` 아래만 허용). 필드: 질문, 답변, 모델, 토큰·비용, 구간별 지연, 선택된 엔티티, 검색된 노드 id, 출처 목록(문서 해시·쪽·시작/끝 위치·근거 상태), 거절 여부, 근거에 없는 숫자, 형식 검사 결과. 접속 정보·키는 기록하지 않는다. 기록 실패는 응답을 막지 않는다.
- `graph/chat_logs.sql`: `public.fp_chat_logs` 테이블과 검토용 읽기 뷰 `fp_chat.log_review` DDL **초안**(실행 안 함). RLS 켬, 정책은 자리표시자 주석(앱 역할 INSERT 전용, 검토자 SELECT 전용).
- `chat/fp_chat_patch.py`: 프롬프트 교체·복원, 구간별 지연 측정, 로그 기록 연동(`apply()` 와 answer 래퍼 안).

## 검증한 사실

- 표준 테스트와 새 테스트 포함 239개 통과(직접 재실행). 팀 코드(`src/graphrag_chatbot`, `src/common`) 변경 0건.
- `qa_log.py` 에 DB 주소·키를 읽거나 쓰는 코드 없음(직접 grep).
- **고친 문제**: 출처 조회가 검색된 Document 노드의 문서 전체 근거(최대 1,000건)를 끌어와 답변과 무관한 위치가 섞였다. 노드에 직접 붙은 근거와 양 끝이 모두 검색된 엣지의 근거만 쓰도록 수정(`edge_id` 도 기록).
- 초안 SQL 에 `fp_chat.log_review` 읽기 권한 부여가 빠져 있어 `grant select ... to service_role` 을 추가.

## 못 한 것과 남은 위험

- 실제 챗봇 화면과 새 프롬프트의 답변 품질은 아직 보지 못했다. 골든셋 dev 에서 새 형식이 정답률을 떨어뜨리지 않는지 다시 재야 한다(회당 약 $0.07, 사용자 실행).
- SQL 은 실행하지 않았다. 적용하려면 앱 DB 역할에 INSERT 권한을 주는 보안 결정과, 질문 원문의 개인정보·보관기간 정책이 먼저 필요하다.
- 사람이 읽을 문서명은 아직 없다(`fp_documents` 미도입). 지금은 해시 앞 8자리다.
