## 추가: DB 접속 오류('database "postgres\r" does not exist') 재발 방지

- 증상: 챗봇·스크립트 실행 시 `connection failed ... FATAL: database "postgres` 다음에 메시지가 겹쳐 보임(터미널에서 캐리지 리턴이 앞 글자를 덮어씀). 서버 주소와 포트는 정상이고 DB 이름 뒤에 `\r` 이 붙은 것으로 추정(어느 명령에서 난 오류인지는 확인하지 못함, 같은 증상이 두 번 보고됨).
- 추정 원인: `.env` 는 윈도우 줄 끝(CRLF)이고, 셸 `source` 로 읽은 터미널에는 값 끝에 `\r` 이 붙은 환경 변수가 남는다. 챗봇 실행 파일과 래퍼는 이미 있는 환경 변수를 우선(`override=False`)하고 값을 그대로 쓴다. 같은 시각 다른 터미널의 적재(`--execute`)·H1 실행은 성공했으므로 시스템 전체 문제는 아니다.
- 수정: `chat/run_fp_chat.py`, `chat/run_fp_chat_v2.py`, 사용자 래퍼 `with_env.py` 가 `DB_URL`·`FP_DATABASE_URL`·`DB_URI`·`OPENAI_API_KEY` 의 앞뒤 공백·줄바꿈을 제거하도록 했다. 회귀 테스트 추가(`DB_URI` 끝에 `\r` 이 있어도 `DB_URL` 이 `postgres` 로 끝남); 수정 전 코드에서는 이 테스트가 실패하고 수정 후에는 통과함을 확인(실행 파일 테스트 8개 통과, 표준 243·챗봇·채점 79 통과).
- 남은 일: `graph/load.py` 는 `FP_DATABASE_URL` 을 직접 읽는다(래퍼를 쓰면 정리됨; 직접 호출 시에는 오염된 터미널에서 같은 오류 가능). 오염된 터미널은 새 터미널을 열거나 `unset DB_URL DB_URI FP_DATABASE_URL OPENAI_API_KEY` 로 정리한다.
