# 답변 규칙 v3, 수치 충돌 탐지기, 검색 재현성 도구, OCR 문서 근거 구절 대체 입력

- 앞선 이력: [엔티티 효과 측정·OCR 청킹](2026-11-06-엔티티효과측정-OCR청킹-laptop.md)

## 계기

사용자가 챗봇에서 같은 질문(CLUB1카드 200의 인터컨티넨탈 호텔 객실 할인)을 켜기/끄기로 두 번 했을 때 답의 수치가 달랐다(파르나스 15%·코엑스 20% 대 10%·15%). 로그와 그래프, 원문을 확인한 사실:

- 한 카드 문서에 서로 다른 두 프로그램이 있다(31쪽 멤버십 특전 15%/20%, 47쪽 특급호텔 객실 할인 10%/15%). 둘 다 정확히 추출돼 있다.
- LLM 이 고르는 시작 엔티티가 실행마다 달라 서브그래프(상한 40노드)에 47쪽 노드가 들어오거나 빠졌다. 챗봇은 프로그램을 구분하지 않고 한쪽만 답했고 수치 검증은 둘 다 통과했다(`scope_unknown`: 그래프 안 어딘가에 있는 숫자인지만 봄).
- 연결표(엔티티 중복 처리)는 이 질문에서 검색된 노드 중 멤버가 0개라 영향이 없었다.

## 한 일

1. **답변 프롬프트 v3**(`chat/answer_format.py`): v2 전체에 "같은 대상에 서로 다른 수치가 둘 이상이면 모두 나열하고 혜택 이름과 근거 쪽(p.N)을 붙여 구분" 규칙을 덧붙였다. `FP_ANSWER_FORMAT=v3` 일 때만 적용, 기본은 v2. v2 문자열 불변을 이전 커밋과 비교해 확인했다.
2. **로그 버전 기록 수정**(`chat/app_v2.py`): v3 실행에서도 로그의 `answer_format_version` 이 상수 `v2` 로 찍히던 문제를 `get_answer_format_version()` 으로 고쳤다.
3. **수치 충돌 탐지기**(`chat/value_conflicts.py`, 순수 함수): 같은 카드 안에서 정규화한 이름이 같고 서로 다른 쪽에 서로 다른 값이 있는 혜택 묶음을 찾는다. 숫자 표기(1.0% = 1%, 금액 단위)를 정규화하고 같은 쪽 안의 여러 값은 구간별 수치로 보고 충돌로 치지 않는다. 처음 기준(이름 유사도 0.6)은 오탐이 많아(호텔 대 항공, 가맹점 다른 쪽 등) 정규화 완전 일치로 좁혔고, 그 결과 남은 7개 그룹도 직접 열어 보니 모두 표기 차이이거나 같은 쪽 구간 값이라 쪽 조건과 숫자 정규화를 추가했다.
4. **검색 재현성 측정 도구**(`chat/retrieval_stability.py`): 같은 질문을 N회 반복해 답변 생성 없이 검색 단계(analyze + explore)만 실행하고 엔티티 선택 조합 수, 노드 집합 Jaccard, 일부 반복에만 들어간 노드 수, 수치 조합 변동을 집계한다. 실제 실행은 아직 하지 않았다(사용자 키·DB 필요).
5. **`graph/source_text.py` 의 `--trace-dir` 옵션**: 우리카드 OCR 문서는 PDF 126쪽 중 111쪽에 텍스트 층이 없어 근거 구절이 전부 `pdf_unreadable` 로 부착 0건이었다. PDF 텍스트를 읽을 수 없을 때 OCR 추적 JSON 의 같은 쪽 텍스트를 쓰도록 했다. 옵션이 없으면 동작은 기존과 같다.
6. **재처리 대상 식별**(저장소 밖 산출물): 실패한 청크 34개(하나 10, 우리 24)의 id 와 실행 스크립트를 준비했고 사용자가 실행했다.

## 못 한 것과 남은 위험

- v3 규칙을 LLM 이 실제로 지키는지는 한 번의 로그(v3 실행 1건)로만 봤다: 쪽 번호와 "자료 간 차이" 문구가 생겼으나 그 실행의 서브그래프에 47쪽 노드가 없어 두 프로그램을 나열하지는 못했다. 프롬프트로는 서브그래프에 없는 값을 나열할 수 없으므로 근본 원인은 검색 불안정이다.
- 검색 재현성은 도구만 만들었고 측정 전이다. 엔티티 선택 호출에 temperature 0 을 줄 수 있는지는 모델 지원 여부를 확인하지 못했다.
- 충돌 탐지기와 골든셋 80문항 시뮬레이션은 시작 노드를 결정적 매처로 근사했다. 감지 재현율은 합성 테스트와 실제 사례 1건으로만 확인했다.
- 골든셋에 "같은 대상 서로 다른 쪽 다른 값" 문항이 없어 v3 의 효과를 측정할 수 없다.
- OCR 추출(117청크)과 재처리는 사용자가 진행 중이며 이 이력 작성 시점에 완료 전이다. OCR 그래프 적재에는 새 run 의 Card 노드 2개(`card:woori:104139`, `104149`)가 기존 그래프와 id 가 겹치는 문제가 남아 있다.
