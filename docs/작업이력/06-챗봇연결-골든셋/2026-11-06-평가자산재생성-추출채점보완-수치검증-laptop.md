## 배경

2026-11-05 저녁에 `/tmp` 의 평가 산출물(골든셋, 정답 라벨, dev 결과, 그래프 CSV)이 사라졌다. 저장소 코드와 `~/pilot_work`, Supabase 적재 데이터는 그대로였다. 평가 자산을 `~/pilot_work/eval-assets/` 에 다시 만들었다(저장소 밖, 이 폴더 자체는 커밋하지 않음).

## 한 일

- 골든셋 v2 80문항(하나 40·우리 40, 정답 없음 8, dev 41·final 39)을 쪽 원문에서 다시 작성. 그래프에 결과가 있는 상품설명서 쪽만 사용, 모든 질문에 카드 상품명, 지시어 금지. 검증 도구에 지시어 오류와 상품명 경고 검사를 추가.
- 추출 정답 라벨 v2 132개(25쪽)를 final 에 쓴 쪽을 제외하고 작성.
- 그래프 CSV 를 다시 내보냄(하나 5,748/7,956/11,287, 우리 4,561/5,173/9,266: 이전 DB 적재와 같음). 처음 우리카드를 비어 있는 청크 폴더로 지정해 Card 노드가 0개로 나왔다가, 저장소 안 `src/card_benefit/data/chunks/woori` 로 바로잡음.
- `extraction/label_eval.py`: 놓친 라벨을 자동 분류(`boundary_near`, `wrong_kind_nearby`, `true_missing_candidate`)하고 30자 이내 근접 일치를 별도 집계(hit 로는 세지 않음). 실제 자산 결과: wrong_kind_nearby 11, boundary_near 5, true_missing_candidate 4, 구분 없음 2.
- `chat/answer_check.py`: 답변 숫자를 질문의 시작 혜택에 연결된 노드 범위로 검사(scoped_grounded / elsewhere_only / ungrounded). `qa_log.py` 에 `number_check` 필드를 추가하고 `fp_chat_patch.py` 가 연결(기존 `ungrounded_numbers` 는 유지). 실패는 `check_failed` 로 기록하고 답변은 계속.

## 검증한 사실

- 전체 file_pipeline 테스트 378개, 표준 묶음 231개 통과(직접 재실행). 팀 코드·docs 변경 0건.
- 추출 재현율(정답 라벨 132개, 표본이고 정밀도 아님): Benefit 35/37, Condition 27/34, Limit 21/28, Target 27/33. 관계: HAS_CONDITION 24/34, HAS_LIMIT 20/28, APPLIES_TO 27/33. 이전 값(58·45·54·45%)은 라벨이 달라 직접 비교할 수 없음.
- 엔티티 노드 10,088개 중 같은 이름이 반복되는 비율 31.8%(정규화 후 서로 다른 이름 6,881). 엔티티 해소 코드는 없음.
- 엔티티 해소 후보 보고서(저장소 밖): 강한 후보 병합 시 줄어드는 노드 상한 2,046 중 같은 카드 안 181, 카드 사이 1,865. 카드 사이 묶음은 병합이 아니라 연결(SAME_AS 류)로 다뤄야 함(결정 D5).
