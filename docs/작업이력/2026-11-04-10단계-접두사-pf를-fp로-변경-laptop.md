# 10단계 지식그래프 접두사 `pf_`에서 `fp_`로 변경

- PC: laptop
- 변경 이유: 사용자 결정: 지식그래프 도구 이름을 `fp_`로 변경(file_pipeline 약자).
- 변경 목록:

| 구분 | 변경 |
|---|---|
| DB 객체 | PostgreSQL 테이블·인덱스·제약·함수·트리거 `pf_` → `fp_` |
| 환경 변수 | `PF_DATABASE_URL` → `FP_DATABASE_URL` (구 이름 호환 없음) |
| Cypher | `Pf*` 라벨 → `Fp*`, `PF_*` 관계 및 `pf_*` 제약 → `FP_*` 및 `fp_*` |

과거 이력은 당시 사실이므로 `pf_`로 남긴다. 팀원 `NEO4J_DF_PF_DESIGN.md`가 `pf_` 이름을 예약했으므로 `fp_`로 바뀐 사실을 팀원에게 알려야 한다.

Supabase에 이미 실행된 `pf_` 테이블 4개는 0행이다. 사용자가 `migrate_pf_to_fp.sql`을 실행해야 이름이 바뀌며, 아직 미실행이다. Codex는 실행하지 않았다.

검증 결과: 표준 테스트 `203 passed in 3.11s`. 하나 드라이런 노드 5,748/엣지 7,956/근거 11,287, 우리 드라이런 노드 4,561/엣지 5,173/근거 9,266. schema.sql과 이전 SQL 객체명 대조: 테이블 4, 인덱스 9, 함수 1, 트리거 1, 제약 9 모두 일치. Supabase 이전 미실행; 커밋 전.
