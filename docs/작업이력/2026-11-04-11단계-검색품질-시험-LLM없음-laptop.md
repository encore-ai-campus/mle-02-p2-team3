# 11단계 검색 품질 시험 (LLM 없음)

PC: laptop

## 목적

Anthropic API 유료 사용을 피하기로 한 결정에 따라, 답변 생성 없이 검색 단계만 평가하도록 했다.

## 모드와 지표

`chat/retrieval_eval.py`는 CSV 기본 모드와 opt-in DB 모드를 제공한다. `contains`는 질문에 포함된 길이 2 이상의 비문서 노드명을 긴 순으로 최대 3개 선택한다. `oracle`은 질문 레코드의 `seed_entities`를 사용한다. 이름 일치 시 중복 노드를 모두 seed로 취급하고 무방향 hop 탐색을 한다.

seed hit rate는 기대 `seed_entities` 중 선택 seed 이름에 포함된 비율이다. 기대값 recall은 기대 문자열이 subgraph 노드의 name 또는 스칼라 props 문자열 안에 부분 문자열로 포함된 비율이며, full recall은 질문별 기대 문자열을 모두 포함한 질문 비율이다. 추가 집계는 노드·엣지 수, 40개 제한 여부, Document 표시율, 처리 시간, 중복 이름 seed 노드가 있는 질문의 비율과 recall 차이다. CSV 원본 노드/엣지 순서를 재현 정렬로 사용한다.

`rag.py`의 REACH_SQL은 `(id, depth)`에 대한 재귀 `UNION`으로 seed에서 무방향 탐색하고 depth가 hops보다 작은 경우만 확장한다. 쿼리는 `LIMIT 40` 앞에 `ORDER BY`가 없어 DB의 선택 행 순서는 보장되지 않는다. `_explore`는 exact-name seed 조회 결과를 먼저 저장한 후 reach 조회 결과를 추가하고 최종 노드 배열을 다시 40개로 자른다. CSV 결과는 파일 순서에 따른 결정적 추정이며 DB 모드 대조가 필요하다.

## 한계와 후속 확인

- LLM 답변 품질은 측정하지 않았다.
- CSV 모드는 SQL의 무정렬 LIMIT 결과 순서를 재현할 수 없으므로 DB 모드로 확인해야 한다.
- 추출 정밀도 약 70%가 평가 기대값과 결과에 영향을 준다.
- 결과 JSONL 및 요약 JSON은 `/tmp/fp-retrieval-*.json*`에 두었다.
- 표준 테스트에서 Neo4j 노트북 정적 검사 1개가 실패했다. 원인: `-[]->` 처럼 대괄호가 빈 관계에서 `group(1) or group(2)` 가 None 이 되어 `.split` 오류. `is not None` 판정으로 고쳐 11-05에 직접 확인했고, 관련 테스트 포함 226개가 통과했다.
