# 양쪽 실행 빈 결과 판정표 도구

PC: laptop

## 직접 확인

- 두 결과에 공통으로 존재하고 양쪽 extraction이 비어 있는 청크를 신호 수 내림차순, 청크 ID 오름차순으로 고르는 모듈과 `prepare`/`tally` CLI를 추가했다.
- 판정표에는 원문이 없고, 열람 파일은 출력 디렉터리의 `empty_view/`에 기록하도록 했다. 저장소 내부 출력은 거부하고 기존 판정표는 `--overwrite` 없이는 보호한다.
- 합성 테스트 4개와 점검 노트북을 추가했다. 새 모듈 점검 및 노트북의 빈 출력 검사는 통과했다.
- 지정한 테스트 전체 명령은 156 passed, 1 failed였다. 실패는 수정 금지 대상 `out_compare_check.ipynb`에 기존 출력이 남아 있다는 노트북 커버리지 검사였다.
- 실데이터 입력은 읽혔고 상위 8개를 계산했으나 `/home/lee/pilot_work/review` 생성은 실행 환경의 읽기 전용 파일시스템 제약으로 실패했다.

## 추정

- 신호 단순 개수는 의미상 혜택 누락 여부를 확정하지 않으며, 사람이 열람 파일을 보고 판정해야 한다. 표 밀도는 전체 청크 사이의 상대 구간이다.

## 못 한 것

- `~/pilot_work/review/empty_verdicts.md` 및 `empty_view/` 8개 파일 생성. 현재 쓰기 가능 경로가 저장소와 `/tmp`로 제한되어 지정 위치에 쓸 수 없다.
- 전체 노트북 출력 실패는 기존 노트북 변경 금지 조건 때문에 정리하지 않았다.
