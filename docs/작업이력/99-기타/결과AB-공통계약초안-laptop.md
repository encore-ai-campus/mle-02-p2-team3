## 목적

파일 기반 결과 A와 DB 기반 결과 B를 같은 원문 위치와 항목 의미 기준으로 비교한다. 각 파이프라인은 독립적으로 구현하고, 어느 한쪽의 결과나 ID를 다른 쪽 입력으로 사용하지 않는다.

## 초안 제안

### 비교 단위와 원문 위치

- 비교 단위는 근거가 연결된 추출 항목 1건이다. 항목에 근거가 여러 개면 근거별 행을 만든다.
- 문서·위치 키는 `(doc_sha256, page_no, start_pos, end_pos)`로 제안한다.
- `start_pos`와 `end_pos`는 쪽 원문 기준 1부터 시작하고 끝 위치를 포함한다.
- 청크 ID, AI 실행 ID, 파이프라인 내부 항목 ID는 양쪽 구현에서 독립적으로 생성될 수 있으므로 직접 조인 키로 쓰지 않는다.
- 위치를 찾지 못했거나 여러 번 일치하는 근거도 버리지 않고 `quote_status`와 nullable 위치로 보존한다. 상태 이름과 적재 가능 규칙은 합의가 필요하다.

### 공통 레코드 필드 후보

| 필드 | 의미 | 상태 |
|---|---|---|
| `doc_sha256` | 원천 문서 해시 | 비교 키로 제안 |
| `page_no` | 쪽 번호 | 비교 키로 제안 |
| `start_pos`, `end_pos` | 쪽 원문 기준 인용 위치 | 1-based inclusive 제안 |
| `quote_status` | 근거 위치 판정 (`located`, `ambiguous`, `missing` 후보) | 허용값 합의 필요 |
| `entity_type` | 혜택·조건·한도·대상·관계 등의 분류 | 공통 enum 합의 필요 |
| `entity_key` | 동일 결과 안의 항목 및 관계 끝점을 잇는 로컬 참조 | 생성·안정성 합의 필요; 파이프라인 간 직접 동등성은 보장하지 않음 |
| `values` | 이름, 유형, 수치·조건 원문값 등 비교 대상 값 | 스키마 매핑 합의 필요 |
| `source_entity_key`, `target_entity_key` | 관계의 양 끝점 | 관계 행에 필요; 양쪽 내부 키를 공통 키로 오인하지 않도록 매핑 규칙 필요 |

원문 인용문 자체는 비교 파일에 기본 포함하지 않는 안을 제안한다. 원문 재확인이 필요한 경우, 위치와 문서 해시로 원본을 찾아 확인한다. 다만 각 파이프라인의 보존·감사 요구가 있으면 별도 비공개 보조 산출물 여부를 결정한다.

### 상태와 비교 규칙 후보

- 추출 실패, 빈 결과, 스키마 위반, 위치 미확인을 서로 다른 상태로 보존한다. 실패·빈 결과를 정상적으로 항목이 없는 경우와 합치지 않는다.
- 결과 A의 현재 JSONL은 located와 unlocated를 별도 파일로 내보낸다. 공통 비교용 변환에서는 상태별 행을 한 계약으로 모을지, 파일 분리를 유지할지 합의가 필요하다.
- 관계는 양 끝점 유형·참조와 관계 유형을 함께 비교한다. 끝점이 없거나 매핑되지 않은 관계는 정상 관계처럼 비교하지 않고 별도 오류로 센다.
- 추출값 비교와 원문 정확성 판정을 분리한다. 위치가 같다는 이유만으로 의미가 맞다고 판정하지 않는다.
- `chunk_id`, 호출 순번, AI 실행 ID는 추적 메타데이터로만 유지하고 공통 비교 키에서는 제외한다.

## 합의가 필요한 질문

1. 이 공통 레코드의 기준 스키마로 DB의 `EXTRACT_SCHEMA_V1`, file_pipeline의 온톨로지 v1, 또는 두 스키마의 매핑 레이어 중 무엇을 채택할까?
2. 비교할 최소 필드와 선택 필드는 무엇이며, 조건·한도·대상의 코드값과 원문값을 어떤 규칙으로 매핑할까?
3. 결과를 항목 단위로 낼지 근거 단위로 낼지, 다중 근거 항목을 어떤 방식으로 표현할까?
4. 관계 끝점의 공통 참조 키를 만들 수 있는가? 만들 수 없다면 값·유형 기준 매핑을 누가 승인할까?
5. `located`, `ambiguous`, `missing`, 호출 실패, 빈 결과, 스키마 오류의 공통 상태명과 포함 규칙은 무엇인가?
6. 위치 없는 근거도 비교 산출물에 포함할까? 포함한다면 비교 결과에서 별도 집계할까?
7. OCR 필요·제외 문서와 카드사 범위를 어디까지 비교할까? 기존 조사에서는 결과 B가 하나카드만 대상으로 한 것으로 기록돼 있다.
8. 공통 계약의 소유자, 버전 변경 절차, 샘플 검증 책임자는 누구인가?
