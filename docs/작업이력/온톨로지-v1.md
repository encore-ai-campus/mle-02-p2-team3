# 온톨로지 v1 — file_pipeline 5단계 (초안, 2026-11-03)

담당: 이현근 (file_pipeline). 상태: **초안**. 6단계 LLM 추출 전에 스키마 모양을 고정하기 위한 문서다.
범위: 카드 혜택 관계를 표현하는 얇은 v1. 카드 상품·카드사 엔티티는 넣지 않는다(공통 계약 소관).

## 1. 근거 표본
- 우리카드 상품설명서 청크 JSON 10개 (T1~T10, 쪽 2개씩, 쪽 원문 기준 위치 있음). 저장소 밖 임시 폴더에만 있다.
- 우리카드 PDF 5개(`src/data/woori_all/credit`)의 청크 JSON. 이 표본은 청크 생성 모듈로 만들었다.
- 하나카드: **표본 없음.** 파일럿 PDF를 찾지 못했다. 하나 표현이 추가되면 이 문서를 고친다.
- 4000자 초과 청크: 표본 40개 중 1개. 전체 문제 규모(지도 기준 29개)는 이 표본으로 판단하지 않는다.

## 2. 실제로 보이는 표현 (표본에서 도출)
| 종류 | 표현 예 (원문) | 비고 |
|---|---|---|
| 혜택 | "국내외 가맹점 1% 청구할인", "정기결제 50% 청구할인", "식비 5% 청구할인", "리터당 50원 청구할인", "포인트 적립" | 이름과 율·금액이 한 줄에 같이 나온다 |
| 조건 | "전월 실적 50만원 이상 시", "최근 3개월간 국내 신용구매 실적 30만원 이상", "매출 건당 3만원 이상 결제 시", "공식 홈페이지 또는 앱에서 정기결제 등록 시" | 실적 기준, 금액 기준, 결제 수단 |
| 제외 조건 | "무이자할부금액, 정부지원금 … 은 전월 실적에서 제외", "간편결제 및 인앱결제 결제 시 할인 제외", "LPG 이용금액은 할인 제외" | 제외는 조건(EXCLUDE)으로 둔다 |
| 한도 | "월 할인한도 5천원", "통합 할인한도" 표(실적 구간별 금액), "1회 10만원, 1일 2회, 월 6회" | 한도 표는 열 이름이 혜택과 떨어져 있다 |
| 대상 | 가맹점명(넷플릭스, 유튜브 프리미엄, 티빙), 업종(음식점/주점, 미용실), 서비스(통신요금 자동납부) | 표 안에 대상과 율이 같이 있다 |

## 3. 엔티티 (스키마 `extraction/schema.py`)
| 엔티티 | 뜻 | 필드 (원문 표기 그대로) | 종류 값 |
|---|---|---|---|
| Benefit | 혜택 한 건 | name, rate, amount | — |
| Condition | 혜택에 걸린 조건 | text, kind, min_amount(원, 정수) | SPEND_REQ(실적), EXCLUDE(제외), USAGE(이용 방식), PAYMENT(결제 수단), MERCHANT(가맹점 범위), OTHER |
| Limit | 할인 한도 | text, period, amount(정수), unlimited, shared | TXN, DAY, MONTH, YEAR, UNKNOWN |
| Target | 적용 대상 | text, kind | MERCHANT, INDUSTRY, CHANNEL, SERVICE, OTHER |

모든 엔티티와 관계는 원문 인용문(evidence)을 1개 이상 가진다. 위치 숫자는 받지 않는다.

## 4. 관계
| 관계 | 방향 | 뜻 |
|---|---|---|
| HAS_CONDITION | Benefit → Condition | 이 혜택의 조건(제외 조건 포함) |
| HAS_LIMIT | Benefit → Limit | 이 혜택의 한도 |
| APPLIES_TO | Benefit → Target | 이 혜택이 적용되는 대상 |
| EXCLUDES | Benefit → Target | 이 혜택에서 빠지는 대상(가맹점·업종이 명시된 경우만) |
| MUTUALLY_EXCLUSIVE | Benefit → Benefit | 함께 받을 수 없는 혜택("장기할부 청구할인과 중복 제공 안됨"). 자기 자신은 안 된다 |

규칙: 제외 "조건"은 Condition(kind=EXCLUDE)으로 두고, 제외된 "대상"이 가맹점·업종으로 명확할 때만 EXCLUDES를 쓴다. 같은 내용을 두 곳에 중복으로 넣지 않는다.

## 5. 범위 밖 (넣지 않은 것과 이유)
- **카드 상품, 카드사**: 공통 계약(card_product 등) 소관. file_pipeline v1은 참조하지 않는다.
- **수수료 계산식**(해외 이용 청구금액 산식 등): 조건식 트리를 만들지 않는다는 규칙. 원문 문장으로만 보관한다.
- **연회비, 발급 조건, 발급 방법**: 혜택이 아니다.
- **이벤트·기간 한정 혜택**: 표본에서 명확하게 분리되지 않아 v1에서 뺀다.
- **약관 조항 번호(Clause)**: 위치 정보로 대체한다.

## 6. 열린 문제
- 하나카드 표본 없음 → 하나 고유 표현(예: 하나머니 단위)이 빠졌을 수 있다.
- 한도 표는 혜택과 연결하는 규칙이 필요하다. 표 연결은 6단계 추출 프롬프트에서 다루고, v1 스키마는 연결 결과만 받는다.
- 제외 조건이 여러 혜택에 공통으로 붙는 경우(예: "무이자할부 제외")의 중복 처리는 정규화 단계(9단계)로 미룬다.

## 8. 부록: 두 번째 PC에서 전체 청크로 잰 값 (2026-11-03)

앞 절들의 표본은 청크 40개 규모다. 아래는 대표 문서 전체를 청킹해(하나 95문서 543청크, 우리 111문서 489청크) 센 값이다. 저장소 밖 임시 폴더에서 계산했고 코드는 올리지 않았다.

**무시 문자가 든 청크** (`evidence.py`가 무시하는 문자)

| 카드사 | 해당 청크 | 많은 문자 |
|---|---|---|
| 하나 | 34 / 543 (6%) | U+00A0 1,641개, U+0007 235개, U+0001 65개 |
| 우리 | 282 / 489 (58%) | U+0007 4,245개, U+200C 2,060개, U+0001 184개, U+00A0 115개 |

- 제어 문자(U+0000~U+001F)는 벨(U+0007) 말고도 많다. 우리카드 글머리표 뒤에 U+0001·U+0003이 붙은 문장이 125줄 있어서(예: `• \x01결제계좌 개설기관의 …`) 인용문이 글머리표부터 시작하면 벨·공백만 무시해서는 못 찾는다. 그래서 `evidence.py`는 U+0000~U+001F 전체를 무시하고, 위 실제 문장으로 테스트한다.
- 같은 청크 1,919곳에서 40자 구간을 뽑아 비교했을 때(보이지 않는 문자를 뺀 인용문으로 가정), 벨까지만 무시하던 때는 99.7%를 찾았다. 놓친 6곳은 모두 글꼴이 깨진 줄이었다. 실제 LLM 인용문으로 잰 값은 아니다.

**4000자 넘는 청크**: 30개(하나 18, 우리 12). 제목이 없는 것은 14개. 가장 긴 것은 우리 카드의정석2 8쪽 9,540자. 판단: v1에서는 청킹을 고치지 않고 6단계에서 정확도를 잰 뒤 문단 규칙 추가 여부를 정한다. (앞 절의 "표본 40개 중 1개"와 지도의 29개는 다른 기준이다.)

**하나카드 파일럿 PDF**: 1절의 "찾지 못했다"는 이 PC에서는 찾았다. `src/data/hana_all/credit/신용_하나더넥스트멤버스_상품설명서(공식PDF)_15299_20250703.pdf`의 sha256(`4a8995350682…`)이 파일럿 `traceability.json`과 일치한다. 하나카드 표본을 늘릴 때 쓸 수 있다.

**스키마 보강 (반영함, 2026-11-03).** 다른 PC에서 같은 자료로 만든 스키마 초안(커밋 `c64773d`, 브랜치 `feat/file-pipeline-extraction-schema`)에 있던 것 중 현재 스키마에 없던 세 가지를 넣었다. 모두 선택 필드라 기존 추출 결과는 그대로 통과한다.
- `Condition.min_amount`(정수 원): "전월 30만원 이상"을 숫자로 비교할 때 쓴다. 음수는 거부한다.
- `Limit.amount` / `unlimited` / `shared`: "할인한도 제한 없음", "통합 월 2회"류 표현이 많다(대표 문서 청크 중 "통합"·"월 N회"·"연 N회"가 든 청크: 하나 149, 우리 175. 약관 문장도 포함한 단어 빈도다). `unlimited`이면 `amount`를 가질 수 없다.
- `MUTUALLY_EXCLUSIVE`(Benefit → Benefit): "중복 제공 안됨"("중복"이 든 청크: 하나 70, 우리 50. 단어 빈도). 혜택-조건 연결이나 자기 자신 연결은 거부한다. 한도 공유는 같은 `Limit`에 두 혜택을 `HAS_LIMIT`로 잇고 `shared=true`로 표현하므로 관계를 따로 두지 않았다.
