# 챗봇 품질 평가

## 1. 범위와 평가 대상

품질은 질문에서 올바른 그래프 노드를 찾는 **검색**과, 검색된 그래프에서 사실에 맞는 문장을 만드는 **답변**으로 나누어 평가한다. 대상은 팀 `src/graphrag_chatbot/rag.py`와 file-pipeline의 `fp_chat` 어댑터다. OpenAI 어댑터는 gpt-6-luna 기본 모델을 지정하며 Claude 사용은 이 흐름의 코드에서 확인되지 않는다. 실제 API 호출은 이 문서 작성 과정에서 하지 않았다.

## 2. 평가 세트

| 세트 | 구성 및 해석 |
|---|---|
| 자동 생성 질문 | 추출 CSV에서 카드 혜택·한도·조건·대상·문서 질문을 생성한다. 이력의 60문항 결과는 원래 코드 생성 기본값/유형별 표본과 일치하는지 결과 파일로 재확인하지 못해 미확인이다. 추출 데이터로 만든 질문이므로 실제 이용자 질문보다 낙관적일 수 있다(추정). |
| 사람형 24문항 | `/tmp/fp-human-questions.json`은 하나 12, 우리 12로 구성(2026-11-05 직접 확인: 유형 6종 × 카드사별 2~3문항). Codex가 그래프 데이터에서 질문을 만들었으므로 추출이 이미 찾은 것만 묻는 순환·표현 편향이 있고, 표본이 작아 독립 문항 24개 기준 95% 신뢰구간 폭이 ±20%p 안팎이다. |

| 사람 작성 골든셋 | PDF 페이지 층화 표집기, CSV 양식·변환기, PDF 위치 검수 시트가 코드/이력에 있다. 2026-11-05 골든셋 v1 80문항을 작성했다(하나 40·우리 40, 정답 없음 9, 변형 20 포함). 질문과 기대 사실은 PDF 쪽 원문에서만 만들었고(그래프·추출 결과·답변 파일은 읽지 않음) 기대 사실이 쪽 원문의 기록된 위치와 일치하는지, 정답 없음 키워드가 코퍼스에 없는지를 스크립트로 대조해 통과했다. 변형 그룹 단위로 dev 39·final 41로 나눴다. 사람 검수는 아직 없다. |

## 3. 판정 규칙

자동 답변 판정은 `answer_eval.py` 기준이다. 엄격 포함(strict)은 정규화 문자열 포함을 센다. 새 판정은 숫자 단위 환산, 단위 없는 숫자 비교(질문 유형에 따라), 해시 앞 8자리, 이름 핵심 토큰 일치율 80% 이상 등을 지원한다. 각 정답의 `match_kind`는 `exact`, `number_unit`, `number_unitless`, `hash`, `name_partial` 등으로 기록된다. 숫자가 맞아도 잘못된 문맥에 답한 경우 자동 판정이 이를 거부하지 못할 수 있으므로 실제 답변 정확도의 대리값이다.

사람 판정은 검수 시트에서 질문·답변과 문서, 쪽, 글자 위치, PDF 페이지 링크 및 선택 발췌를 대조한다. PDF 발췌는 현지 원본에 접근할 때만 확인 가능하다. 자동 판정과 사람 판정은 분모·기준이 다르므로 같은 표의 단일 점수로 합치지 않는다. 이번에 열람한 자료로는 사람 검수가 완료된 24문항 정답표를 확인하지 못했다.

## 4. 평가 방법과 재현성

기본 흐름은 질문 → 후보 이름 목록 → LLM 엔티티 선택 → 선택 이름을 seed로 그래프 순회 → 답변 생성이다. 팀 `rag.py`는 기본 1 hop(최대 3), 하위 그래프 최대 40노드를 사용한다. 재귀 SQL의 결과 순서는 별도 정렬되지 않아 같은 이름이 여러 노드이거나 한도에 걸리는 질문에서 비결정성이 생길 수 있다.

실행기는 기본 dry-run이고, 실제 평가에는 `--execute`가 필요하다. `--limit`은 기본 5, 기본 비용 상한은 $0.10이며 OpenAI 어댑터는 최소 completion token 예산을 적용한다. 같은 세트를 3회 실행해 평균과 범위를 함께 기록하는 절차가 바람직하다. ±2 문항 변동은 이력에서 주장된 값이나 이번에 원 결과 반복 실행 자료를 대조하지 못해 미확인이다.

## 5. 기준 결과

아래 자동 점수는 이력 파일에 기록된 문항별 재판정 집계다. 사람 확정 정답률이 아니다. 각 칸은 전체 기대값을 모두 포함한 문항 수이며 분모를 표기했다.

| 날짜·조건 | 하나 | 우리 | 판정 규칙·해석 |
|---|---:|---:|---|
| 2026-11-05, source attach 전 | 7/12 (58.3%) | 2/12 (16.7%) | strict, 자동 판정 |
| 2026-11-05, source attach 전 | 10/12 (83.3%) | 7/12 (58.3%) | 개선 규칙, 자동 판정 |
| 수기 확인 추정 | 약 11/12 | 약 8–9/12 | 사람 검증 완료 수치가 아니므로 추정 |
| source attach 후 `-st2` 재실행 | 8/12 (66.7%) | 6/12 (50%) | 개선 규칙, 자동 판정; 변동이 커 원인 귀속 미확정 |

원문 부착(`-st2`) 후 24문항 재시험은 결과 JSONL(`/tmp/fp-answer-24-st2.jsonl`, 임시 파일)을 **직접 열어 새 규칙으로 재채점**했다(2026-11-05): 정답 전부 포함은 하나 10/12 → 8/12, 우리 7/12 → 6/12. 변한 문항을 읽은 결과 hana-02(새 답변이 구간별 한도까지 명시하는데 기대 문구가 글자 그대로 없어 오답 처리), hana-01(거절 패턴 오탐), woori-02(거의 동일한 답)는 판정 오탐이고, hana-12(문서 식별값)는 같은 시드에서 근거 문서 선택이 달라지는 비결정성이다. 따라서 점수 변화는 노이즈 수준으로 판단한다(판단: 사람 확인 아님). 비용은 24문항 약 $0.034(요약 JSON 값), 질문당 프롬프트 토큰 약 10.8k → 12.1k(+12%)를 파일에서 직접 계산했다. 청구 원장 대조는 하지 않았다.

### 골든셋 v1 dev 3회 결과 (2026-11-05)

dev 39문항(하나 19·우리 20)을 `gpt-6-luna`로 3회 실행(회당 약 $0.07)하고, 규칙 매칭 후 남는 사실을 `fact_judge.py`(LLM 판정)로 채점했다. **자동·AI 판정이며 사람 확정 정답률이 아니다.**

| 항목 | 값 |
|---|---|
| 3회 평균 문항 정답률 | 82.9% (97/117) |
| 질문 그룹 30개 기준 95% 구간 | 70~94% (변형은 같은 그룹으로 묶어 부트스트랩) |
| 3회 모두 맞음 / 모두 틀림 / 들쭉날쭉 | 30 / 5 / 4 문항 |
| 정답 없음 4문항 | 3회 모두 거절 4/4 |
| 약한 슬라이스 | 한도 질문(하나 62%, 우리 71%), 우리 card_benefits 50% (n이 작아 참고용) |

3회 모두 틀린 5문항의 원인(직접 읽어 확인): 판정기 오판 1(G-W-B-02: 답변 "월 적립한도는 없습니다"를 기대값 "없음"과 못 맞춤), 추출 실패 청크 1(G-W-B-06: Welfare+ 대한체육회 문서의 두 청크가 `empty_result`·`json_parse_failure` 로 실패해 그래프에 노드가 없고, 질문에 카드명도 없어 수정함), 연회비 노드 미추출 1(G-W-A-11, 우리 그래프에 해당 카드 연회비 노드 0개), 구간 한도 연결·추출 구멍 가능성 2(G-H-A-07 외; 원문 쪽 확인 전). 근거 PDF 가 그래프에 없는 4문항(G-W-B-06 계열: 추출 실패, G-W-B-11 계열: 체크카드라 추출 범위 밖이나 같은 내용이 다른 학교 PDF 에 있어 3회 모두 맞음)을 빼면 평균 83.8%(88/105, 그룹 28개 기준 95% 구간 71~95%)이고, 판정기 오판(G-W-B-02)까지 보정하면 약 86.7%(91/105)로 추정한다. 짧은 기대값(`없음`, `1%`)은 판정기가 놓칠 수 있어 사람 검수 표본으로 판정기 정확도를 함께 재야 한다.

## 6. 오류 유형 및 대응

| 유형 | 사례·상태 | 개선/잔여 위험 |
|---|---|---|
| 발급사 혼동 | `woori-04`에서 하나 전용 노드를 선택했다는 이력 기록 | 후보 이름 목록 자체에 발급사 구분이 없어 질문에 카드사가 생략되면 혼동 가능 |
| 후보 목록 누락 | 이름순 300 상한에서 정답이 잘렸다는 CSV 재현 | 현재 wrapper는 최대 5,000 일치행을 받아 단어 중요도 순으로 최대 500 후보를 구성. 이력 재현 12/12는 DB 실측이 아니며 직접 결과 재검증은 미확인 |
| LLM의 `(Card)` 꼬리표 | 출력 이름에 라벨이 붙는 사례 | wrapper의 라벨 접미사 제거 코드 확인 |
| 범위 한도 답변 | `hana-03` | 원문 부착 전에는 '12,000원과 19,000원이지만 각 한도가 실적 구간과 어떻게 연결되는지 명시되어 있지 않다'고 답했고, 부착 후에는 '30만 원 이상~100만 원 미만이면 월 최대 12,000원, 100만 원 이상이면 월 최대 19,000원'으로 구간 연결까지 답했다(결과 파일 직접 확인; 자동 판정은 두 경우 모두 정답으로 세어 점수에는 안 드러남) |
| 추출 데이터 누락 | `hana-04` 월 횟수 누락 | 그래프가 원천에 없는 값을 복구할 수 없음 |
| 모호한 질문 | `woori-03` | 질문에 발급사·상품·기간 등 구분 정보를 포함하고 골든셋에 모호성 사례를 별도 기록 |
| 문서 식별자 질문 변동 | `hana-12` | 팀 `REACH_SQL`에 정렬이 없다는 코드 사실; 해당 사례와 인과관계는 이력 기재이며 추정 |
| 이미지 문서 누락 | 우리 OCR 대상 | OCR·추출 범위가 확정되기 전 해당 상품에 대한 응답 커버리지 제한 |

후보 제한 수치는 주의가 필요하다. 과거 `order by name limit 300` 설명은 이력의 이전 구현을 가리킨다. 현재 확인한 wrapper는 일치 후보 조회 상한 5,000, 중요도 순 상위 500이며, 보충 후보도 최대 500이다. `src/graphrag_chatbot/rag.py` 기본 구현은 별도로 이름순 500이다.

## 7. 다음 시험과 완료 기준

2026-11-05 갱신: 아래 12문항 계획은 골든셋 v1 80문항(dev 39·final 41)으로 확대됐다. 질문 작성과 원문 위치 자동 대조, dev 3회 반복과 자동 판정은 끝났다. **남은 것은 사람 검수(약 20문항 표본으로 판정기 정확도와 확정 정답률 측정)이고, final 41문항은 dev 에서 개선을 마친 뒤 한 번만 실행한다.**

PDF를 확인한 사람이 골든 질문 12개를 채우고, 질문마다 기대 핵심 사실·카드사·근거 문서/쪽을 기록한다. PDF 원문을 별도 보고서에 복사하지 않고 검수 시트에서 위치를 가리킨다. 같은 그래프 snapshot과 질문 세트로 3회 baseline을 측정하고, 검색 적중과 답변 포함률을 독립 표로 산출한다. 이후 source_text 또는 후보 선택 변경 전후를 동일한 조건으로 비교한다.

완료 기준은 (1) 12문항 모두 근거 쪽과 기대 사실을 사람 검수, (2) 3회 반복 결과와 평균·범위 보존, (3) 실패마다 검색 실패·답변 실패·원천 누락·모호 질문 분류, (4) 자동 점수와 사람 판정을 별도 보고하는 것이다. 현재 골든 질문 작성 및 검수 완료 여부는 미확인이다.
