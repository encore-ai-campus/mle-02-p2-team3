# 카드 혜택 GraphRAG — 공식 PDF 기반 독립 보완 조사

조사일: 2026-10-29. 기존 보고서와 다른 AI의 작업 파일은 수정하지 않았다. 조사 목적은 추천 결론의 유지가 아니라 동일한 크기의 PDF 표본에서 조건과 관계가 성립하는지 확인하는 것이다. 현재 판매·발급 여부, 최신본 및 시행일은 별도 확인하지 못했다. 아래 조건은 지정된 문서 버전의 스냅샷이며 고객정보는 사용하지 않았다.

## 1. 조사 결과와 표본

**A 4종, B 4종 모두 공식 PDF를 열고 텍스트를 확인했다.** A는 하나 4종, B는 하나 2종과 신한 2종이다. 공정한 비교를 위해 STYLE과 PLAY는 양쪽에 의도적으로 중복 포함했다. 따라서 합산 8개 행은 서로 다른 8종이 아니며 고유 상품은 6종이다. B는 3개 발급사가 아니라 요청 범위 내의 2개 발급사다. PDF를 검색·열람 도구로 직접 열고 텍스트를 추출했으며 파일을 저장소에 내려받거나 프로젝트 파이프라인으로 시험한 것은 아니다. 별도의 PDF 페이지 렌더링도 시도했으나 이 환경의 출력은 이미지 내용을 전달하지 않아 시각적 판독 성공으로 집계하지 않는다.

## 3. 조건의 수와 관계 집계

### 범위와 계산 규칙

전체 약관의 모든 조건을 샅샅이 센 수치가 아니다. 재현 가능하게 양쪽에서 동일하게 고른 **5개 원자 조건 유형**만 조사했다. ① 혜택에서 상품권 구매 제외(D상품권), ② 전월실적에서 상품권 구매 제외(P상품권), ③ 전월실적에서 선불카드 충전 제외(P선불), ④ 전월실적에서 국세 제외(P국세), ⑤ 전월실적에서 아파트관리비 제외(P관리비). 각 카드·각 유형의 명시 근거가 있으면 1건, 확인할 수 없으면 0건이다. D상품권은 대표 혜택에 적용되는 제외를 센다. P선불은 충전이라는 **교집합**만 비교하며 H1/H2는 선불카드 충전, S1/S2는 선불카드 구매·충전이어서 전체 문구 또는 전체 범위 동등으로 간주하지 않는다.

이 5개 유형 × 4카드 × 2시나리오 = **40개 카드-조건 확인 셀**을 검토했다. 공유된 H1/H2를 중복 제거하면 6카드 × 5 = 30개 고유 셀이다. `1`은 명시, `0`은 부재 확정이 아닌 본 조사에서 확인하지 못한 경우, `?`는 추출 모호함이라 0으로 계산한다.

| D상품권 | 1 | 1 | 1 | 1 | 1 | 1 | 4 | 4 |
| P상품권 | 1 | 1 | 1 | 1 | ? | 0 | 4 | 2 |

모든 행의 근거는 2절의 카드별 명시 절이다. S1 실적 상품권은 PDF 직접 텍스트가 `상품/선불전자지급수단`으로 읽히는 반면 검색 인덱스는 상품권으로 읽는다. 원문 이미지 판독을 이 환경에서 성공적으로 확인하지 못했으므로 0으로 처리했다. S2의 `0`은 PDF 실적 제외 목록에 해당 항목이 명시되지 않았다는 뜻이다.

고유 6종 기준 명시 셀은 **24개**다(H1/H2 중복 10건 제거). A의 쌍 30은 다섯 유형 각각 6쌍, B의 15는 6+1+6+1+1이다. 이는 개념별 **예상 연결 후보**이지 실제 Neo4j 관계 수, 정책 수 또는 분석 전체의 완전성 지표가 아니다. B의 발급사 간 8건은 동일 정책 8건이 아니다.

### 동일 문구·의미·범위의 구분

- **문구 동일 5개 유형:** H1·H2의 1쪽에서 각 비교 항목에 대응하는 `상품권 및 기프트카드 구매`, `선불카드 및 선불전자지급수단 … 충전 금액`, `국세`, `아파트관리비` 문구가 서비스/실적 해당 항목에 동일하게 등장한다. 공백·줄바꿈은 무시했다. D상품권과 P상품권은 동일 단어라도 적용 단계가 달라 별개 2개 유형이다. 문단 전체는 카드명 등에서 다르므로 문단 전체 동일이 아니다.
- **표현이 다른 동일 교집합 2개 유형:** H1/H2와 S1/S2의 혜택 상품권 **구매** 제외, 실적 선불카드 **충전** 제외. 상대 문서의 구매·충전 전체 또는 다른 결제수단까지 같다는 뜻은 아니다. 위 5개 유형 중 두 유형이 이 교차 발급사 교집합을 갖는다. 이 분류는 동일 문구 5개와 중복 가능하며 합산하지 않는다.
- **유사하지만 범위가 달라 개별 관리:** 하나 공통 서비스 제외 vs H4 대형마트 제외 vs S1 할인서비스 제외 vs S2 포인트 적립 제외, 그리고 상품권 실적 제외 vs 적립 제외. 같은 상품권 개념이지만 서비스·가맹점·거래·발급사 범위가 달라 정책 병합 불가. 위 두 교차사 유형 역시 전체 조건 기준으로 이 분류에 포함된다. **동일 정책으로 입증된 건수는 0**이며 확인 불가와 정책이 다르다는 확정은 다르다.

## 4. 실제 근거 기반 경로와 시연

아래는 아직 추출·적재하거나 Cypher로 검증하지 않은 **시연 가능 예상 경로**다. `C` 카드, `B` 혜택, `R` 카드/혜택 범위별 규칙, `X` 비교 개념, `L` 해당 문서 조항이다. 관계 하나가 1홉이다. 원문이 연결을 뒷받침하지만 그래프 데이터의 자동 추출 정확도는 확인되지 않았다.

| 안 | 홉 | 예상 경로 / 실제 근거 |
|---|---:|---|
| A | 1 | H4 카드 → 대형마트 5% 청구할인; H4 1쪽 일상생활 혜택 표 |
| A | 2 | H4 카드 → 대형마트 할인 → 대형마트 상품권 구매 제외 규칙; H4 1쪽 서비스 제외 |
| A | 3 | H4 카드 → 대형마트 할인 → 상품권 구매 제외 규칙 → H4 1쪽 서비스 제외 조항 |
| A | 4 | H1 카드 → 편의점 ONE PICK 혜택 → **상품권 구매 제외 개념** ← H2 편의점 ONE PICK 혜택 ← H2 카드; H1·H2 각 1쪽 공통 서비스 제외. 개념을 지나는 비교 투영이며 두 규칙·두 출처는 따로 보존 |
| B | 1 | S2 카드 → 네이버 결제 포인트 적립; S2 2쪽 적립 서비스 |
| B | 2 | S2 카드 → 네이버 결제 포인트 적립 → 상품권 구매 적립 제외; S2 2쪽 적립 제외 |
| B | 3 | S2 카드 → 네이버 결제 포인트 적립 → S2 상품권 구매 적립 제외 규칙 → S2 2쪽 적립 제외 조항 |
| B | 4 | H1 카드 → ONE PICK 편의점 캐시백 → **상품권 구매 제외 개념** ← S2 네이버 결제 적립 ← S2 카드; H1 1쪽 서비스 제외, S2 2쪽 적립 제외. 비교 경로이며 적용 범위는 다름 |

4홉의 공유 개념은 동일 정책을 의미하지 않는다. 정확한 저장 모델은 `C→B→R→X←R←B←C`의 **6홉**이며 각 `R→L`로 독립 근거를 연결한다. H1·H2의 동일 문구 역시 실제 공동 관리 정책을 입증하지 않는다. 관리자가 특정 상품권 제외의 변경을 가정하면 동일 개념에 연결된 하나 상품과 혜택을 **검토 후보**로 제시하고 각 규칙·발효일·조항을 사람이 확인해야 한다. 신한 조건은 변경 영향을 받는 대상으로 출력하지 않는다. B에서 하나의 변경은 비교 플랫폼의 해당 하나 상품 콘텐츠 갱신과 신한 등 유사 문서의 **차이 재검토 계기**로만 사용한다.

## 5. 사업 주체와 GraphRAG 가치

| | A 단일 카드사 | B 복수 카드사 |
|---|---|---|
| 도입 주체·실제 사용자 | 가상의 하나카드 상품관리·준법 조직; 상품 기획, 약관 검토, 내부 상담 지식 관리자 | 카드 비교 플랫폼·금융정보 서비스; 콘텐츠 편집, 정보 품질 담당자, 공개 정보 이용자 |
| 해결 문제 | 개정 시 검토 문서·혜택 누락 방지, 내부 상담·상품관리 답변에 원문 제공 | 발급사별 상품 조건·한도·적용 대상과 근거를 공개 정보만으로 비교·갱신 |
| 그래프의 기여 | 조건 개념에서 범위별 규칙과 카드·혜택을 역추적하고 증거를 연결 | 비슷한 개념을 여러 발급사로 탐색하면서 각 규칙·근거를 따로 비교 |
| 제한 | 실제 내부 공동 정책·업무 연동은 가정; 자동 정책 변경 금지 | 회사 간 정책 동일성·변경 전파 금지, 오래된 문서·수집 및 재배포 확인 필요 |

SQL 조인으로도 이 작은 데이터의 고정 경로와 영향 후보를 구현할 수 있다. 벡터 RAG는 원문을 검색해 설명할 수 있으나 적용 대상·역방향 관계를 정형화해 보장하지 않는다. GraphRAG는 명시적 관계, 임의의 다중 홉 경로, 변경 검토 목록과 근거 연결을 묶는 장점이 있으나, 이번 조사에서는 실제 적재·평가가 없어 SQL이나 일반 RAG에 대한 성능 우위는 입증되지 않았다. 그래프가 필요한 업무와 사업의 필요성은 별개다.

## 6. 구현과 시연 범위 재평가

| 관점 | A | B | 절충안 |
|---|---|---|---|
| 실제 데이터 충분성 | 4/4 공식 PDF 텍스트 확인, 같은 사업자 표에서도 구조 차이 | 4/4 공식 PDF 텍스트 확인, 단 신한 문서 최신성과 추출 오류 확인 필요 | 처음부터 둘 중 하나만 검증하면 반대편 실제 조건은 미검증 |
| 다중 홉 유효성 | 5유형·30 조건별 카드쌍 후보; 공동 정책 미입증 | 5유형·15 후보, 그중 교차사 8; 적용범위 차이가 더 선명 | A 변경 검토 및 B 교차사 비교를 분리하면 양쪽 장점 시연 |
| 사업 주체 | 카드사 내부 업무 가정이 핵심 시연과 직접 맞음 | 비교 플랫폼에 자연스러움; 한 카드사 정책 관리로 표현 불가 | 내부 시연과 비교 플랫폼 확장에는 별도 사용자·문제 정의 필요 |
| 2인·3일 난이도 | 4종 추출·검증도 쉽지 않음 | 공급사별 구조·버전과 규칙 차이 부담 증가 | A MVP 2~3종을 우선한 뒤 여력이 있으면 B 1종의 비교 경로만 추가 |
| 시연 가치 | 가상 변경 시 카드·혜택 검토 후보와 근거 경로가 과제 핵심에 직결 | 유사 문구 오병합 위험과 서로 다른 정책의 근거 비교를 더 명확하게 시연 | 주 시연의 완성도를 지키면서 타사 확장 가설을 실증할 수 있으나 작업량 증가 |

M0~M9의 문서 목록과 PDF 전처리·온톨로지·근거 필수 추출·독립 파이프라인·정규화·Neo4j·Cypher·오류 검증·통합 시연을 우선한다. `file_pipeline`과 `db_pipeline`은 동일 문서에 대한 독립 실행 결과를 공통 문서/청크 ID·JSON 계약으로 비교하며 서로를 입력으로 삼지 않는다. DB 방식의 PDF 텍스트 입력과 AI 호출 방식은 기술 확인이 필요하다. MCP는 기존 Cypher의 얇은 조회 도구로 제한하고 과제표의 3일차 오전 M8 미완료 시 1개 도구 컷라인을 따른다. SQL/DDL과 코드는 이번 조사에서 변경하지 않았다.

## 7. 최종 판단

**추천: 절충안 — 하나카드 MVP 후 신한카드 확장 검증.** 이전에 KB PDF를 확보하지 못했다는 이유로 B를 낮게 평가할 근거는 더 이상 충분하지 않다. 신한 PDF 2종을 포함하면 B도 네 상품 모두 원문 텍스트로 조사할 수 있고, 실제 카드사 간 8개 조건별 카드쌍 후보와 S2의 실적·적립 범위 차이는 GraphRAG의 **비교 및 오병합 방지** 가치를 A보다 선명하게 보여준다. 따라서 다중 발급사 분석 자체가 부적합한 것은 아니다.

다만 이번 과제의 핵심은 카드사 내부의 가상 조건 변경에 따른 검토 후보 추적이고 두 사람이 두 독립 추출 경로, M0~M9와 MCP까지 완성해야 한다. 이 목표에서는 A로 2~3종을 먼저 완성하고, 추출·근거 검증이 완료되면 S2 1종을 추가해 B의 교차사 비교를 검증하는 편이 적합하다. 이후 전체 B 4종은 별도의 비교 플랫폼 시나리오로 확장한다. 이것은 조건 변경이 신한에 전파된다는 의미가 아니다. 별도 타사 경로의 구현·검증까지 완료하지 못하면 확장 **계획**으로만 발표한다.

미확인 사항: 각 PDF의 현재 적용 여부 및 실제 시행일, 상품 발급 가능 여부, S1의 손상된 실적 제외 문구의 이미지 판독, S2 PDF와 웹 설명 차이의 원인, KB PDF의 직접 본문 판독, 표 자동 구조화 정확도, 실제 그래프 적재·질의 성능, 문서 이용·재배포 권리, 카드사 내부 정책의 공동 소유 여부. 향후 PDF 이미지 대조와 최신 공식 문서 확인 후 집계와 권고를 갱신해야 한다.
