## 1. V4 작업 목적과 최초 기획 의도

**최초 기획 의도**

> "AI가 카드 혜택을 판단하고 안내할 때, 카드사 담당자가 그 판단의 과정과 근거를 확인할 수 있어야 한다."

담당자가 확인해야 할 6가지:

1. AI가 어떤 카드와 혜택을 선택했는가
2. 어떤 전월실적·할인·적립·제외 조건을 적용했는가
3. 그 조건이 카드 전체에 적용되는가, 특정 혜택에만 적용되는가
4. 어떤 공식 상품설명서 조항을 근거로 판단했는가
5. 잘못된 답변이라면 어느 단계에서 오류가 생겼는가
6. 조건이 바뀌면 어떤 카드·혜택·판단 결과를 다시 검토해야 하는가

**V4의 목표:** V3의 사업적 스토리(AI 채널 확대 → 공통 엔진 → MCP)를 유지하면서, 중심을
"AI 판단 근거의 검증"으로 옮긴다. 발전 순서는 다음과 같다.

판단 근거 검증(핵심) → 오류 원인 추적(확장①) → 조건 변경 영향 분석(확장②) → 공통 엔진·MCP 재사용(확장③)

**결론 메시지(그대로 사용)**

- "AI가 카드 혜택을 판단했다면, 카드사는 그 판단에 사용된 조건과 공식 약관 근거를 확인할 수 있어야 합니다."
- "판단 근거를 검증하고, 오류 원인을 추적하며, 변경 영향을 확인할 수 있는 공통 GraphRAG 엔진을 여러 AI 채널에서 재사용합니다."

원래 지시문 전체는 이 세션의 사용자 요청(“카드 혜택 GraphRAG 발표 PPT V4 개정 지시”, §1~§15)이다.
새 세션에서 지시문이 필요하면 사용자에게 다시 붙여 달라고 요청한다. 핵심 요구는 이 문서 §5·§7에 옮겨 두었다.

### 2-1. ONE PICK STYLE 상품설명서 원문 (15650_20260429, 1쪽) — 시연 ①·②에 쓸 사실

- ONE MORE **대중교통**: 대상 버스·지하철, **5% 캐시백**, 서비스 한도 **월 1천원**, 지난달 실적 **10만원**
- ONE MORE 놀이공원: 에버랜드·롯데월드 50% 현장할인(1인 1매), 월 1회/연 2회, 지난달 실적 20만원, 최초 발급 월 미제공
- 실적 산정 기준: 지난달 1일~말일(승인 시점) **국내외 일시불** 이용금액 10만원/20만원 이상 시 ONE MORE 제공
- 실적 제외 대상: 국세·지방세·공과금·아파트관리비·보험료·등록금 등, **상품권 및 기프트카드 구매**, 선불카드·선불전자지급수단(하나머니) 충전, 부동산 임대료, ATM, 서비스 적용 받은 매출
- 서비스 제외 대상 — 공통: **상품권 및 기프트카드 구매**, 선불 충전, 배달·예약 앱 주문, 대형시설 입점 점포 등 / — 대중교통: **시외버스·고속버스·철도(KTX/SRT/ITX) 제외**
- 실적과 관계없이 제공(예외): ONE MORE 대중교통은 **최초 카드 사용 등록일로부터 다음 달 말일까지** 지난달 실적 10만원 미만이어도 10만원 이상 기준으로 제공
- ONE PICK·STYLE 영역은 "지난달 실적 조건 없는 서비스" (ONE PICK 일1회/월30회 월5천원, STYLE 일1회/월10회 월5천원)
- 모든 서비스는 하나카드 등록 가맹점·업종 기준 (PDF 밖 정보)

**V3 오류 발견:** V3 표지(슬라이드 1)의 AI 답변 "대중교통 5% **할인**돼요"는 원문상 **캐시백**이다. V4에서는 "캐시백"으로 쓸 것.

## 4. 실행 방법 (다른 컴퓨터)

```powershell
git pull
cd src/card_benefit/docs/ppt_build
npm install                       # node_modules는 ppt_build/.gitignore 대상
$env:PPTX_SKILL = "<pptx 스킬 디렉터리>"   # 선택. 지정하면 테마 색 적용(apply_theme.js)
node build_v5.js ..\card_benefit_graphrag_presentation_v5.pptx [노트본문.md]
```

- `build_v4.js`·`build_v4_1.js`·`build_v4_2.js`·`build_v5.js`는 `PPTX_SKILL`이 없어도 실행된다(테마 색 적용만 건너뜀). `build_v2_base.js`는 여전히 `PPTX_SKILL`이 필요하다.
- 두 번째 인자를 주면 슬라이드별 노트 본문(목적·상태·예상 반박·대본)을 Markdown으로 쓴다. 최종 노트 문서는 이 본문 앞뒤에 머리말·자기 검토를 붙인 것이다.
- 기존 V4~V5 파일을 덮어쓰지 않으려면 출력 경로를 새 이름(예: `_v5_1.pptx`)으로 준다.
- Windows에서는 스킬의 `soffice.py`가 `AF_UNIX` 오류로 동작하지 않는다. `"C:\Program Files\LibreOffice\program\soffice.exe" --headless --convert-to pdf <파일>`을 직접 쓴다.

- `PPTX_SKILL`: Claude Code의 `anthropic-skills:pptx` 스킬 폴더. 이 컴퓨터에서는
  `C:\Users\KBJ\.claude\skills\synced\0e4167d7-...\pptx` 였다. 새 컴퓨터에서는 스킬을 로드하면 "Base directory"로 경로가 표시된다.
  스킬이 없으면 `applyTheme` 호출 두 줄을 지워도 동작한다(테마 색만 Office 기본값이 됨 — 슬라이드는 hex 색을 직접 쓰므로 외형 영향은 작음).
- 검증·렌더링 (스킬 스크립트 사용):


## 6. 발견한 오류와 해결할 문제

1. **V3 표지 사실 오류:** "대중교통 5% 할인" → 원문은 "5% 캐시백, 월 1천원 한도". V4에서 수정(V3 파일은 그대로 둠).
2. **V3 전용 생성 스크립트 없음:** V3는 V2 스크립트 결과의 텍스트만 바뀐 상태. V4 스크립트에 V3 문구를 수동 반영해야 한다(`slide_text.py`로 V3 텍스트 추출 후 대조).
3. `build_v2_base.js`는 `process.env.PPTX_SKILL`에 의존 → 새 컴퓨터에서 경로 지정 필요(§4).
4. 프로젝트 `.venv`에 pip 없음 → 렌더/추출용 패키지는 시스템 Python에 설치.
5. 시연 ①의 "판단 불가" 사례는 V3의 '가상 가맹점' 대신 "지난달 실적·사용 등록일 정보 부재"로 바꾸는 안. 가맹점 업종 사례(PDF 밖 정보)는 노트나 부록으로 유지 가능.
7. STYLE 문서 ID가 자료마다 다름: V3는 15650_20260429, 일부 조사 문서는 15650_20260316 링크. V4에서는 V3가 대조한 20260429판을 쓰고 부록 G에 판 차이를 적을 것.
6. 신한 2026-09-09 자료는 "확률적 판단에 의존해 일관성이 부족" 표현 — V3의 "답변 비일관성" 칩은 요약으로 허용 가능.
