# 중복 관계와 근거 연결 검토

## 확인 목적

중복 노드를 합칠 때 관계가 중복되어 제거되면 그 관계를 가리키는 근거가 유효하게 유지되는지 확인한다. 이 문서는 합성 입력에 대한 검토이며 실제 데이터의 손상을 확인한 것은 아니다.

## 확인한 코드

- 수정 전 [`dedupe_subgraph`](../../card_benefit/payment_card/file_pipeline/chat/retrieval/entity_dedupe.py)는 노드 ID를 대표 ID로 바꾸고 중복 관계 중 첫 번째만 남겼지만 근거의 `edge_id`는 바꾸지 않았다. 현재는 관계 근거가 있을 때 식별 가능한 관계 중 안정적인 대표를 선택하고 근거 ID를 재연결한다.
- [챗봇 호출부](../../card_benefit/payment_card/file_pipeline/chat/fp_chat_patch.py)는 `FP_ENTITY_DEDUPE`가 켜지고 연결 CSV가 지정된 경우에만 이 함수를 적용한다.
- [일반 그래프 탐색 결과](../../graphrag_chatbot/rag.py)는 관계의 `source`, `target`, `type`만 반환하며 별도 `evidence` 목록도 반환하지 않는다. 따라서 아래 합성 사례만으로 현재 챗봇에서 같은 문제가 발생한다고 결론 내릴 수 없다.
- [오프라인 중복 진단](../../card_benefit/payment_card/file_pipeline/chat/eval/entity_dup_probe.py)은 관계를 `_fp_id`로 식별하고 관계 근거의 `edge_id`를 별도 목록으로 전달한다. 수정 전에는 근거 행의 개수만 비교했으며, 현재는 끊긴 참조와 별도 보존 건수도 보고한다.

## 합성 재현

저장소 루트에서 실행한다. DB·API·실제 PDF는 사용하지 않는다.

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src:src/card_benefit .venv/bin/python - <<'PY'
from payment_card.file_pipeline.chat.retrieval.entity_dedupe import dedupe_subgraph

graph = {
    'nodes': [{'id': 'a'}, {'id': 'b'}, {'id': 't'}],
    'edges': [
        {'id': 'e1', 'source': 'a', 'target': 't', 'type': 'OFFERS'},
        {'id': 'e2', 'source': 'b', 'target': 't', 'type': 'OFFERS'},
    ],
    'evidence': [
        {'edge_id': 'e1', 'doc_sha256': 'synthetic-a'},
        {'edge_id': 'e2', 'doc_sha256': 'synthetic-b'},
    ],
    'seeds': ['a', 'b'],
}
result = dedupe_subgraph(graph, {'b': 'a'})
edge_ids = {edge['id'] for edge in result['edges']}
print('남은 관계:', sorted(edge_ids))
print('연결 대상이 없는 근거:', [e['edge_id'] for e in result['evidence'] if e['edge_id'] not in edge_ids])
PY
```

수정 전 직접 실행 결과는 남은 관계 `e1`, 연결 대상이 없는 근거 `e2`였다. 수정 후에는 같은 명령에서 남은 관계 `e1`, 연결 대상이 없는 근거 `[]`가 나온다. 재연결한 근거에는 `_dedupe_original_edge_id`가 남는다. 입력 객체는 변경되지 않는다.

수정 전에는 오프라인 진단과 같은 `_fp_id`·`edge_id` 형태에서도 관계는 `e1`만 남고 근거 행은 2개로 유지됐지만 `e2`를 가리키는 근거가 남았다. 행 개수만 비교하는 지표는 이 연결 불일치를 발견하지 못했다. 실제 평가 결과에서 발생했는지는 확인하지 않았다.

## 해석과 다음 확인

- **확인된 사실:** 수정 전 관계 ID와 별도 근거 목록이 함께 전달되는 합성 입력에서 근거가 제거된 관계를 가리켰다. 수정 후 중복 관계 근거를 대표 관계에 재연결하고 원래 ID를 기록한다.
- **자기 연결:** 제거된 자기 연결의 근거는 `unresolved_edge_evidence`에 원래 근거와 `removed_self_loop` 사유로 보존한다. 이는 활성 관계에 연결된 근거가 아니다.
- **모호한 ID:** 관계 근거가 있는 입력에서 같은 ID가 여러 관계를 가리키거나 근거의 원래 ID 보존 필드가 이미 있을 때는 추측하지 않고 오류로 중단한다. 관계 근거가 없는 기존 챗봇 형태는 첫 관계를 유지하는 기존 동작을 따른다.
- **미확인:** 오프라인 진단의 실제 입력이나 사용자에게 보이는 출처에 영향이 있는지는 확인하지 않았다. 일반 챗봇 검색 결과에는 해당 필드가 없으며, 출처 기록은 별도의 DB 조회 경로가 있다.
- **후속:** 실제 입력의 ID 계약과 별도 보존 근거의 소비 방식을 검토한다. 진단 CSV의 `unresolved_edge_evidence_count`, `dangling_edge_evidence_count` 추가 열에 대한 소비자 호환성도 확인한다.
