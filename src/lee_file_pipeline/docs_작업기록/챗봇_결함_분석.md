- 기준: 2026-11-08 로컬 작업 트리, 합성 입력과 코드 확인.
- 범위: 관계·근거 병합, 출처 표시, 진단 결과 호환성, 관계도 표시. 실제 DB·PDF·외부 API는 확인하지 않았다.

## 수정 현황 — 2026-11-08

- 아래 1~3번은 합성 회귀 테스트를 먼저 실패시키고 로컬 코드에서 수정했다. 대표 노드가 없으면 검색된 구성원 중 ID순 첫 노드를 사용하고, 쉼표 쪽 번호를 나누며, 출처별 문장·쪽·잘림 여부를 각각 표시한다.
- 비교표는 카드와 혜택별로 한 행을 사용하도록 수정했다. 혜택이 없는 카드도 자료 없음 행을 유지한다. 조건·한도·제외는 해당 혜택과 연결된 값만 그 행에 표시한다. 과거에 저장된 대화의 비교표를 변환하지는 않는다.
- 비교표 수정 후 사용자 점검·챗봇·관계 병합 관련 테스트: `138 passed in 58.78s`.
- 출처 범위는 아직 필터링하지 않는다. 검색 시작점에는 카드와 직접 선택된 혜택이 모두 포함될 수 있고, 관계가 빠진 경우와 문서 노드의 범위 정책이 확정되지 않았기 때문이다. 현재 표시되는 검색 자료 전체가 선택 카드의 근거임을 보장하지 않는다.
- 관련 선별 테스트: `47 passed in 5.63s`. 실제 DB와 브라우저에서의 효과는 미확인이다. 중복 노드 병합은 기본적으로 꺼져 있다.
- 아래 표의 관찰은 **수정 전** 결과다. 4~5번 및 추가 위험은 이번 수정 범위에서 제외했다.

## 추가 위험과 한계

- **순차 병합:** 이미 원래 관계 ID를 기록한 근거를 두 번째 병합에서 다시 재연결해야 하는 합성 입력은 명시적인 `ValueError`로 중단된다. 현재 충돌 방지 정책의 결과이며 실제로 두 번 호출되는지와 재처리 지원 필요성은 미확인이다.
- **비교표:** 수정 전에는 한 카드의 혜택과 한도를 열별로 합쳐 관계가 모호했다. 로컬 수정 후 혜택별 행으로 구분한다. 실제 브라우저 표시와 과거 저장 대화는 확인하지 않았다.
- **노드 속성:** 공용 검색의 `_node_dict`는 리스트형 속성을 제외한다. 리스트형 쪽 정보가 실제 DB에 있는지는 미확인이다.
- **브라우저:** 생성된 그래프 HTML에 외부 CDN 주소가 들어가는 것을 확인했다. 실제 브라우저·오프라인 환경의 렌더링 성공 여부는 확인하지 않았다.
- **별도 보존 근거:** `unresolved_edge_evidence`는 오프라인 진단과 점검 코드에서 건수를 확인한다. 사용자 화면과 QA 로그가 이 목록을 직접 표시하는 코드는 검색 범위에서 찾지 못했다. 일반 챗봇 검색은 별도 `evidence` 목록을 반환하지 않으므로 실제 화면 영향은 미확인이다.

## 출처 연결 경로 검토 — 2026-11-08

- **화면 안내 보완:** 출처 전체가 검색된 자료이며 선택 대상과의 연결 여부가 확인되지 않았다는 문구를 기존 안내에 추가했다. 출처를 임의로 숨기거나 카드별로 확정하지 않는다. 기존에 저장된 대화의 안내는 자동 갱신되지 않는다.
- **선택 대상:** 검색 시작점은 카드와 혜택 등 여러 종류가 될 수 있다. 숫자 점검에는 선택 혜택과 선택 카드의 직접 `OFFERS` 혜택을 찾는 별도 코드가 있으나, 이름이 같으면 복수 노드가 선택될 수 있고 이 범위가 화면 출처 범위와 같지는 않다.
- **관계의 의미:** [그래프 생성](../../card_benefit/payment_card/file_pipeline/graph/export.py)은 한 문서에 연결된 카드마다 해당 청크에서 추출된 혜택에 `OFFERS`를 만든다. 합성 조건으로 하나의 문서에 카드 A·B가 연결되고 혜택 X가 A에만 적용된다면, 생성된 B→X 관계만으로 실제 B 적용을 증명할 수 없다. 실제 다중 카드 문서 존재와 영향은 미확인이다.
- **문서와 쪽:** [원문 구간 생성](../../card_benefit/payment_card/file_pipeline/graph/source_text.py)은 근거를 문서 해시·쪽별로 모으지만 최종 혜택 속성에는 문서 해시 없이 원문 구간과 쪽을 저장한다. 화면에서 문서별 근거 행을 전달받지 않으면 문서의 쪽은 미확인이며, 혜택 쪽을 특정 문서에 귀속할 수 없다.
- **검증:** 선택 카드 외 혜택이 포함된 합성 그래프에서 자료를 보존하고 연결 미확인 안내를 출력하는 회귀 사례를 추가했다. 화면·관련 테스트 `19 passed in 5.33s`. 실제 DB·PDF·브라우저는 확인하지 않았다.

## 다중 카드 문서 관계 검토 — 2026-11-08

- **합성 확인:** 문서 하나에 카드 A·B를 인덱스로 연결하고 혜택 노드 하나를 추출하면, 내보내기는 A→혜택과 B→혜택 `OFFERS` 두 개를 생성한다. 두 관계 ID에 연결된 근거 행은 없다. [검증 코드](../../card_benefit/payment_card/tests/test_file_pipeline_graph_export.py)에서 합성 CSV를 만들고 실제 내보내기 결과를 확인했다. `14 passed in 0.34s`.
- **의미와 한계:** 인덱스의 문서·카드 연결과 혜택의 문서 내 위치는 알 수 있지만, 그것만으로 해당 혜택이 각 카드에 적용되는지 증명할 수 없다. 합성 입력은 카드별 적용 정답을 포함하지 않으므로 실제 오연결 여부나 빈도는 확인하지 못한다. 단일 카드 문서의 관계도 카드별 적용의 직접 증거가 있는지와는 별개다.
- **검토할 설계:** 문서에서 온 후보 연결과 카드별 적용이 확인된 연결을 구분하고, 확인된 연결에는 판별 근거와 출처를 추적할 수 있어야 한다. 적용 범위 근거가 없거나 문서·청크 관계가 불완전한 경우는 미확인으로 남긴다. 분류의 구체적인 입력 계약과 기존 CSV·뷰·검색·답변 영향은 구현 전에 확인한다.
- **선택지와 위험:** 모든 후보를 제거하면 공통 혜택과 기존 검색 결과가 누락될 수 있다. 반대로 현 `OFFERS`를 검증된 적용으로 표시하면 오연결 가능성을 감춘다. 현재 출력 계약을 임의로 바꾸지 않고 후속 설계와 합성 사례를 먼저 마련한다.

## 관계 상태와 문서 식별자 계약 초안 — 2026-11-08

아래는 **설계 제안**이며 DB·CSV 스키마나 검색에 적용되지 않았다.

**합성 미리보기 구현:** [evidence_audit.py](../evidence_audit.py)의 `preview_offer_reviews(edges, reviews)`는 별도로 제공한 `OFFERS` 관계와 검토 기록을 대조한다. `id`, `source`, `target`, `type`을 가진 관계와 검토 기록의 관계 ID·끝점이 일치하는지, 결정·검토자·시간대가 있는 시각·64자리 문서 해시·양의 정수 쪽이 있는지 확인한다. 같은 관계의 검토가 중복되면 거부한다. 그래프를 바꾸지 않고 `review_recorded`, 명시된 문서 인덱스 출처의 `candidate`, 그 외 `unknown`을 반환한다.

`review_recorded`는 **기록 형식이 맞는다는 뜻**이다. 검토자 권한, 해시와 문서의 실제 일치, 쪽 내용이나 카드 적용을 증명하지 않는다. 기존 생성기는 `origin`을 출력하지 않으므로 실제 출처를 임의로 추가하지 않으면 `unknown`이다. 이 함수는 기존 CSV·DB·검색·화면에 연결하지 않았고 권한 확인이나 저장 기능도 없다. `verified`는 위 조건을 충족하는 향후 운영 계약이 정해진 뒤에만 사용할 제안 상태다.

**문서·쪽 합성 점검:** `group_source_refs(rows)`는 제공된 근거 행을 문서 해시와 쪽의 쌍으로 묶고, 각 노드 또는 관계 ID와 위치 및 원래 행 번호를 보존한다. 문서 해시·쪽·위치·대상이 없거나 잘못되었거나 위치 상태가 불명확한 행은 별도로 반환한다. 원문을 읽지 않으며, 특정 화면 문장이나 카드 적용을 뒷받침한다고 판정하지 않는다. 서로 다른 문서의 같은 쪽을 구분하는 합성 테스트를 포함한다.

이 함수는 기존 `fp_evidence` 형태의 입력을 별도로 받아 확인하는 프로토타입이다. 기존 생성·검색·화면에는 연결되지 않았다. 생성된 텍스트의 글자 단위 출처 연결을 복원하지 않으며, 기존 검색의 `_node_dict`는 리스트·객체 속성을 제외한다. 기존 그래프나 CSV의 검색 동작을 변경하지 않는다.

기존 점검 CLI의 `--source-refs`와 `--source-refs-csv`로 각각 그래프 JSON과 근거 CSV를 읽어 같은 점검을 실행할 수 있다. 합성 내보내기 CSV의 위치 행과 미확인 행을 모두 보존하는 테스트를 포함해 `76 passed in 10.24s`. 실행 예시는 [사용자 폴더 README](../README.md)의 사용자 점검 코드 실행 절에 있다.

**화면 보조 함수 호환 점검:** 합성 근거 그룹을 `collect_sources`에 직접 전달하면 서로 다른 두 문서의 같은 쪽을 각각 표시하고 근거가 없는 문서의 쪽은 미확인으로 남는 것을 확인했다. 혜택의 기존 원문 구간을 어느 문서에 귀속하는지는 추정하지 않는다. 문서 쪽 표시에서 상태가 명시된 행은 `located`만 사용하며 0 이하·불리언 쪽은 무시하도록 수정했다. 상태 필드가 없는 기존 호출은 호환을 위해 유효한 양의 정수 쪽을 계속 받는다. 합성 화면·점검·내보내기 테스트 `72 passed in 3.63s`.

현재 앱은 이 근거 그룹을 `collect_sources`에 전달하지 않는다. 따라서 위 결과는 **직접 전달한 합성 시험**이며 실제 챗봇의 문서별 쪽 표시 연결 완료를 의미하지 않는다.

**화면 연결 경로 추가 확인:** 공용 검색 결과의 관계는 `source`, `target`, `type`만 제공해 원래 관계 ID가 없다. QA 로그 경로는 노드의 `props.fp_id`를 이용해 근거를 별도 조회하지만 `FP_QA_LOG`가 켜졌을 때만 실행되고 최대 1,000행이며, 실패 시 오류를 기록한다. 이 결과를 화면으로 반환하지 않는다. 따라서 단순히 현재 그래프 관계 ID로 근거를 맞추거나 로그 함수를 호출하면 전체 근거가 보장된다고 말할 수 없다. 화면 연결 전에는 원래 ID 대응, 조회 상한·잘림 표시, 실패 상태와 표시 범위를 합성 시험으로 결정해야 한다. 실제 DB 조회는 하지 않았다.

**선택적 화면 연결:** 이후 `FP_SOURCE_EVIDENCE=1`일 때 검색된 노드의 `fp_id`를 이용해 별도 근거 조회를 실행하고 화면 출처 구성에 전달하는 경로를 추가했다. 기본값은 꺼짐이며 최대 1,000행, 조회 실패·결과 없음·식별자 누락·병합 노드·초과에 대한 안내가 있다. 표시되는 문서·쪽은 검색된 자료의 위치이며 답변이나 선택 카드와의 정확한 연결을 증명하지 않는다. 합성 DB 대체 시험만 했고 실제 DB·권한·지연·브라우저는 미확인이다. 위 `앱 미연결` 관찰은 이 변경 전 상태다.

1. **관계 상태:** `OFFERS`의 상태를 `candidate`(문서 인덱스로 생성된 후보), `verified`(카드·혜택 적용을 별도 확인), `unknown`(기존 데이터 등 판단 근거 없음)으로 구분한다. 다른 관계에는 해당하지 않음을 명시한다. 기존 관계를 근거 없이 `verified`로 옮기지 않는다.
2. **검증 입력:** `verified`에는 카드 ID, 혜택 ID, 검증 결과, 검토 주체·시점과 확인 근거를 함께 남긴다. 문서에 카드가 연결됐다는 사실이나 혜택 노드의 위치만으로 관계 적용을 검증했다고 보지 않는다. 검증 주체·원문 접근·상태 변경 권한은 별도 결정이 필요하다.
3. **문서·쪽:** 원문 구간별로 문서 해시, 페이지, 구간과 잘림 여부를 함께 전달하는 별도 구조를 제안한다. 여러 문서의 같은 쪽 번호를 하나로 합쳐 특정 문서에 귀속하지 않는다. 기존 텍스트·쪽 필드는 유지하고 기존 자료의 문서 대응은 미확인으로 둔다.
4. **호환 경로:** 기존 CSV와 새 CSV를 구분해 검증한다. `fp_edges`에 열을 추가한다면 기존 DB에는 별도 마이그레이션이 필요하고, 뷰·검색·Cypher 내보내기·오프라인 평가에도 상태를 전달해야 한다. 기존 입력의 상태 누락은 `unknown`으로 취급한다.
5. **검색·표시:** 후보를 모두 제거하면 검색 누락이 생길 수 있으므로 기존 경로에서 곧바로 필터링하지 않는다. 우선 후보·미확인 상태를 전달하고 표시하는 경로를 검증한 뒤, 확인된 관계만 쓰는 검색은 별도 선택 정책으로 평가한다. 현재 검증 입력 경로가 없으므로 확인된 관계만 사용하는 검색은 결과가 없을 수 있다.
6. **합성 검증 조건:** 단일·다중 카드 문서, 카드 전용·공통 혜택, 동일명 카드·혜택, 관계·근거 누락, 서로 다른 문서의 동일 쪽, 구버전 CSV, 유효하지 않은 상태, 승인 없는 상태 변경, 검색과 화면 전파를 각각 확인한다. 실제 적용률·정확도는 이 테스트로 알 수 없다.

### 후속 위험 점검

- **이전 진단 행:** 현재 `summarize()` 내부 호출은 새 필드를 가진 행을 사용한다. 외부에서 이전 행을 직접 넘기는 사용처는 미확인이다. 누락된 진단값을 0으로 채우면 미측정을 이상 없음으로 오해할 수 있어, 수정한다면 미측정 건수를 별도로 보존하는 계약이 필요하다.
- **순차 병합:** 현재 챗봇 검색 경로는 중복 병합을 한 번 호출한다. 재병합 때 기존 출처 ID가 있으면 예외가 발생하며, 원래 ID만 보존할지 전체 변경 이력을 보존할지 정해지지 않았다. 임의로 덮어쓰지 않는다.
- **관계도 외부 의존:** 공용 그래프 렌더러가 원격 CDN을 참조한다. 실제 오프라인 브라우저는 미검증이며 공용 렌더러 변경은 다른 화면에도 영향을 줄 수 있다.
