# M4 혜택 추출 실행·재현 기록

이 양식은 **실제 M4 실행 1회**를 기록한다. 실행 전 계획 값과 실행 후 관측 값을 구분해 채운다. 현재 문서의 모든 실행 값은 `미기록`이며, 실제 실행을 뜻하지 않는다. 원문·청크 본문·프롬프트 본문·API 키는 기록하지 않는다. 실행 입력, 결과, 검증 산출물, 그래프 CSV는 저장소 바깥에 둔다.

## 실행 식별 및 코드 스냅샷

| 항목 | 기록 |
|---|---|
| 실행 상태 | 미기록 |
| 과제 실행 식별자 (팀이 정한 기록용 ID) | 미기록 |
| 그래프 내보내기 `run_id` (`fp_load_runs.csv`) | 미기록 |
| 시작 시각 (UTC, ISO 8601; 그래프 내보내기 `started_at`과 구분) | 미기록 |
| 코드 커밋 해시 | 미기록 |
| 작업 트리 변경 여부 및 스냅샷 식별자 | 미기록 |
| 실행 코드 경로 / 버전 메모 | 미기록 |

커밋 해시만으로 재현 코드가 특정되지 않는 변경 작업 트리라면, 실행에 사용한 소스 스냅샷을 저장소 밖에 보존하고 그 위치와 해시를 적는다. 키나 환경 파일은 스냅샷에 포함하지 않는다.

## 입력 및 선택 표본

| 항목 | 기록 |
|---|---|
| 문서 인덱스 CSV 경로 (외부) | 미기록 |
| 문서 인덱스 CSV SHA-256 | 미기록 |
| 청크 디렉터리 경로 (외부) | 미기록 |
| 선택 JSON 경로 (외부, 생성 시) | 미기록 |
| 인덱스 행 수 | 미기록 |
| 적격 문서 수 | 미기록 |
| 전체 적격 청크 수 | 미기록 |
| 요청 표본 수 (`count`) | 미기록 |
| 실제 선택 청크 수 | 미기록 |
| 선택 청크의 고유 문서 수 | 미기록 |
| 선택 seed | 미기록 (현재 `pilot-run`은 17 사용) |
| 계획 예상 토큰 수 | 미기록 |
| 인덱싱·청킹 입력 스냅샷 식별자 또는 매니페스트 경로 | 미기록 |

`pilot-run`의 적격 문서는 인덱스에서 `canonical=Y`, `ocr_needed≠Y`, `doc_role`이 `product_guide`, `web_capture`, `brand_service` 중 하나, `card_type`이 `credit`, `common` 중 하나인 행의 `doc_id`로 정해진다. 선택은 seed 17로 섞은 청크 ID 목록의 앞부분이다. CLI는 `count=0`도 허용하지만, 실제 과제 표본을 만들 때에는 양수를 사용한다. 재현 기록에는 기준 입력 파일의 경로와 해시, 실제 선택 수를 남긴다. 문서나 청크의 본문은 복사하지 않는다.

## 모델 및 결과 지문

| 항목 | 기록 |
|---|---|
| Provider | 미기록 |
| 모델명 | 미기록 |
| Temperature | 미기록 |
| 실행 결과 디렉터리 (외부) | 미기록 |
| 처리 결과 JSON 파일 수 | 미기록 |
| `resume_metadata.version` | 미기록 |
| `resume_metadata.prompt_sha256` | 미기록 |
| 프롬프트 지문 집계 범위 | 미기록 (예: 결과별 값 목록 또는 고유 지문 수/총 결과 수) |

`prompt_sha256`은 각 결과 JSON의 `resume_metadata.prompt_sha256` 값에서 기록한다. 다수 결과가 있으면 결과마다 지문을 확인하거나, 지문별 결과 수와 총 결과 수를 함께 적어 혼합된 프롬프트 버전을 숨기지 않는다. 프롬프트 전문이나 입력 원문은 기록하지 않는다.

## 처리 건수와 분모

모든 비율은 `분자 / 분모`로 남긴다. 기본 분모는 **선택된 청크 수**이며, 미시작·미저장 결과가 있으면 완료 결과 기준 수와 선택 수를 각각 표시한다. 집계 값은 결과 폴더의 청크 결과 및 문서별 요약과 대조한다.

| 지표 | 수 / 분모 | 정의·비고 |
|---|---|---|
| 선택 청크 | 미기록 / 미기록 | 선택 목록 기준 |
| 호출 완료 청크 | 미기록 / 미기록 | 전체 선택 수 대비 실제 호출 또는 재사용 완료 결과 수 |
| JSON 파싱 성공 | 미기록 / 미기록 | `json_parse_failure`가 없는 완료 결과 수. 분모는 완료 결과 수; 추출 객체 유효성과 별도 집계 |
| 추출 객체 존재 | 미기록 / 미기록 | 파싱된 `extraction`이 객체인 완료 결과 수. 분모는 완료 결과 수 |
| 스키마 검증 성공 | 미기록 / 미기록 | `schema_validation_failure` 없이 파싱·검증을 통과한 수. 분모는 완료 결과 수 |
| 비어 있지 않은 추출 | 미기록 / 미기록 | 개체·관계 항목이 하나 이상인 결과 수 |
| 결과 실패 청크 (`failed`) | 미기록 / 미기록 | 배치 요약 정의에 따른 hard 실패 1개 이상 또는 extraction 없음 |
| 부분 위치 실패 (`partial`) | 미기록 / 미기록 | 추출은 있으나 실패 코드가 `quote_location_failure`뿐인 청크 수 |
| 검토 필요 청크 | 미기록 / 미기록 | 위치 실패 또는 모호한 위치 경고가 있는 수 |
| 경고 포함 청크 | 미기록 / 미기록 | 배치 요약 `with_warnings` |
| 실패 코드별 건수 | 미기록 | `failures_by_code`; 건수 단위는 실패 항목 |
| 위치 인용 성공 / 실패 / 모호 | 미기록 / 미기록 / 미기록 | `quote_locations`; 단위는 근거 인용 |
| 자동 검증 처리 / 플래그 청크 | 미기록 / 미기록 | verify 요약 `chunks`, `chunks_with_flags` |
| 자동 검증 플래그별 건수 | 미기록 | `flags_by_code`; 의미 정확성 판정이 아님 |
| 그래프 노드 / 엣지 수 | 미기록 / 미기록 | 그래프 내보내기 요약 기준 |

## 검토·그래프 산출물 (모두 저장소 밖)

| 산출물 | 외부 경로 | 확인 메모 |
|---|---|---|
| 자동 검증 디렉터리 및 요약 | 미기록 | 미기록 |
| 그래프 CSV 디렉터리 | 미기록 | 미기록 |
| 그래프 CSV 파일명 및 SHA-256 목록 | 미기록 | 미기록 |
| 그래프 내보내기에 사용한 `run_id` | 미기록 | 미기록 |
| 사람 검토표·검토 기록 경로 (있는 경우) | 미기록 | 미기록 |

자동 점검 신호만으로 혜택 의미의 정확성이나 카드별 적용 사실이 검증되었다고 쓰지 않는다. 사람이 원문 근거를 확인했다면 원문을 이 문서에 옮기지 말고, 접근 통제된 외부 검토 기록의 경로와 검토 범위를 남긴다.

## 재현 명령 템플릿

아래는 입력 변수와 출력 위치를 지정해 실제 실행에 사용할 **템플릿**이다. 실행 전 모든 경로를 외부의 해당 실행 전용 디렉터리로 바꾸고, 비어 있는 새 `WORK_DIR`를 사용한다. 셸 변수 인용은 공백을 포함한 경로를 안전하게 전달한다. API 키 값은 명령행이나 기록에 쓰지 않고 승인된 실행 환경의 `OPENAI_API_KEY`에 제공한다. 아래 명령은 이 문서 작성 중 실행하지 않았다.

```bash
INDEX_CSV="/external/input/documents.csv"
CHUNK_DIR="/external/input/chunks"
WORK_DIR="/tmp/card-benefit-m4-run"  # 반드시 비어 있는 새 경로로 변경
COUNT=10  # 실제 표본 수에 맞춰 양의 정수로 변경
MODEL_NAME="<approved-model-name>"

UV_CACHE_DIR=/tmp/uv-cache PYTHONPATH=src:src/card_benefit uv run --locked --no-sync python -m payment_card.file_pipeline.extraction.cli pilot-run \
  --index-csv "$INDEX_CSV" \
  --chunk-dir "$CHUNK_DIR" \
  --work-dir "$WORK_DIR" \
  --count "$COUNT" \
  --model "$MODEL_NAME" \
  --execute
```

`pilot-run` 실행은 결과 디렉터리의 `plan.json`, `results/`, `verification/`, `graph/`, `summary.json`을 사용한다. CLI가 과제 실행 식별자를 생성하지는 않으므로 팀 기록용 ID를 정한다. 그래프 export는 `fp_load_runs.csv`에 별도의 `run_id`와 `started_at`을 쓴다. 실제 실행은 외부의 승인된 환경에서만 수행한다. 재실행 때 기존 작업 결과를 덮어쓰지 말고 새 `WORK_DIR`를 쓴다.

입력 구조 조건: `CHUNK_DIR` 바로 아래에 `*.chunks.json` 파일이 있어야 한다(발급사별 하위 폴더는 재귀 탐색하지 않음). `INDEX_CSV`가 있는 폴더에는 그래프 export가 요구하는 `product_docs.csv`와 `documents.csv`도 함께 있어야 한다.

## 실행 후 기록 완료 확인

- [ ] 실제 명령과 실행 시각을 기록했다.
- [ ] 코드 커밋 또는 외부 소스 스냅샷을 식별했다.
- [ ] 입력 인덱스·청크 스냅샷, 표본 수, 선택 문서/청크 수를 기록했다.
- [ ] 결과 JSON들의 `resume_metadata.prompt_sha256`을 확인하고, 여러 지문이 있으면 모두 구분해 기록했다.
- [ ] 성공·실패·검토 필요 건수에 분모를 붙였다.
- [ ] 검증 결과와 그래프 CSV의 외부 경로 및 그래프 수를 기록했다.
- [ ] 원문, 청크 본문, 전체 프롬프트, 비밀 값을 문서나 저장소에 넣지 않았다.
