# 카드 혜택 추출 계약

이 문서는 과제 산출물에서 실제 사용하는 카드 혜택 추출 스키마와 실행 경로를 설명한다. 기존 구현을 기준으로 작성했으며, 카드 추출 코드를 새로 만들거나 기존 `file_pipeline`을 수정하지 않는다.

## 적용 범위와 입력

- 입력은 문서 인덱스와 PDF에서 생성한 페이지 추적 JSON 및 청크 JSON이다.
- 청크에는 `doc_id`, `chunk_id`, `page_no`, `start_pos`, `end_pos`, `text`가 연결된다. 페이지 문자 위치는 1부터 시작하고 끝 위치를 포함한다.
- 원문 PDF, 페이지 전문, 청크 본문 및 실제 추출 결과는 저장소에 두지 않는다. 입력·실행 결과 디렉터리는 저장소 밖으로 지정한다.
- 인덱싱과 위치 규약은 `payment_card.file_pipeline.doc_index` 및 `payment_card.file_pipeline.chunking` 구현을 따른다.

## 온톨로지 v1

추출 JSON의 최상위 필드는 `schema_ver`, `benefits`, `conditions`, `limits`, `targets`, `relations`다. 현재 구현의 추출 개체 유형과 핵심 필드는 다음과 같다.

| 유형 | 핵심 필드 | 허용값·규칙 |
|---|---|---|
| Benefit | `id`, `name`, `evidence`; `method`, `rate`, `amount`는 선택 | `method`: `DISCOUNT`, `CASHBACK`, `POINT` 또는 null |
| Condition | `id`, `text`, `kind`, `evidence`; `min_amount`는 선택 | `kind`: `SPEND_REQ`, `EXCLUDE`, `USAGE`, `PAYMENT`, `MERCHANT`, `OTHER` |
| Limit | `id`, `text`, `period`, `evidence`; `amount`, `unlimited`, `shared`는 선택 | `period`: `TXN`, `DAY`, `MONTH`, `YEAR`, `UNKNOWN`; 무제한이면 `amount`는 null |
| Target | `id`, `text`, `kind`, `evidence` | `kind`: `MERCHANT`, `INDUSTRY`, `CHANNEL`, `SERVICE`, `OTHER` |

각 엔티티의 `id`는 필수이며 1~64자의 ASCII 영문자·숫자·밑줄·하이픈으로 제한된다. ID는 청크 안 모든 엔티티에서 유일해야 하고, 그래프 내보내기 때 `chunk_id`가 붙어 전역 ID가 된다. 각 관계도 `source`, `target`, `type`, `evidence`가 필수다. 최상위 `schema_ver`는 `ONTOLOGY_V1`이며, 엔티티·관계의 정의되지 않은 필드는 거부된다. `Benefit.method`, `rate`, `amount`와 `Condition.min_amount`는 생략 가능하며, `Limit.amount`는 기본 null, `unlimited`와 `shared`는 기본 false다.

모든 개체와 관계는 청크 원문을 뒷받침하는 `evidence`를 하나 이상 가져야 한다. 각 관계에도 별도의 근거가 필요하다. 관계는 아래 방향과 끝점 유형만 허용한다.

| 관계 | 방향 |
|---|---|
| `HAS_CONDITION` | Benefit → Condition |
| `HAS_LIMIT` | Benefit → Limit |
| `APPLIES_TO` | Benefit → Target |
| `EXCLUDES` | Benefit → Target |
| `MUTUALLY_EXCLUSIVE` | Benefit → Benefit |

개체 ID는 중복될 수 없고, 관계는 존재하는 개체를 참조해야 한다. 자기 자신을 가리키는 관계, 끝점 유형이 허용 규칙과 다른 관계, 정의되지 않은 필드는 검증에서 거부된다. 위치 숫자는 LLM 출력에서 받지 않고, 검증 단계가 근거 문구를 청크에서 찾아 위치를 부여한다.

**Card 연결:** Card는 추출 응답의 네 개체 유형에 포함되지 않는다. 그래프 내보내기 단계가 `product_docs.csv`의 상품 키와 메타데이터로 Card 노드를 구성하고, 해당 문서 청크에서 추출된 Benefit으로 `OFFERS` 관계를 만든다. 따라서 과제 전체 그래프는 Card → Benefit과 Benefit → Condition/Limit/Target 관계로 표현되며, `OFFERS`는 LLM 추출 관계가 아니라 문서·상품 인덱스 기반 연결이다.

## 실제 프롬프트와 코드 경로

실제 프롬프트의 소스는 [`prompt.py`](../../card_benefit/payment_card/file_pipeline/extraction/prompt.py)의 `build_prompt(chunk)`다. JSON 예시, 허용 관계와 필드, 원문에 없는 사실 금지, 근거 인용 규칙, 출력 형식이 스키마와 함께 정의되어 있다. 프롬프트는 실행 시 청크 메타데이터와 본문을 합쳐 구성된다. 이 문서에는 실제 프롬프트에 삽입된 원문을 복사하지 않는다.

배치 결과의 `resume_metadata.prompt_sha256`은 `build_prompt(chunk)`가 만든 청크별 전체 프롬프트 바이트의 SHA-256이다. 청크 메타데이터와 본문도 포함하므로 이 값 하나만으로 코드 버전이나 실행 전체를 식별하지 못한다. 실행 재현에는 코드 커밋 또는 소스 스냅샷, 입력 지문, 모델 실행 문맥을 함께 기록한다.

| 단계 | 기존 모듈 | 동작 |
|---|---|---|
| 문서 인덱싱·추적 | `doc_index/` | 문서 메타데이터와 페이지 단위 원문 추적 정보를 준비한다. |
| 청킹 | `chunking/` | 페이지 경계·원문 위치를 유지한 청크 JSON을 만든다. |
| 표본·실행 계획 | `extraction/pilot.py`, `extraction/pilot_run.py` | 대상 청크를 정하고 예상 입력 크기를 계산한다. 계획 모드는 LLM을 호출하지 않는다. |
| 프롬프트·호출 | `extraction/prompt.py`, `extraction/llm_adapter.py` | 청크 프롬프트를 만들고, 명시적으로 실행할 때 LangChain OpenAI 어댑터를 호출한다. |
| 파싱·검증·근거 위치화 | `extraction/runner.py`, `extraction/schema.py`, `extraction/evidence.py` | JSON 파싱, Pydantic 스키마·관계 검증, 근거의 페이지 위치 찾기를 수행한다. |
| 배치·결과 점검 | `extraction/batch.py`, `extraction/verify.py` | 청크별 결과와 요약을 저장하고 구조·위치 관련 자동 신호를 만든다. 자동 점검은 의미 정확성의 보증이 아니다. |
| 그래프 변환 | `graph/export.py`, `graph/cypher_export.py` | 결과를 그래프 CSV로 매핑하고 Neo4j Browser용 Cypher를 생성한다. |

## 재현 안내

실행 전 `uv` 환경과 의존성을 준비한다. 문서 인덱스·추적 JSON·청크 결과·추출 결과·그래프 산출물은 모두 저장소 밖의 별도 경로를 사용한다. PDF 원문, API 키, 접속 비밀번호를 명령 인자나 저장소 파일에 넣지 않는다.

### 1. 단계별 명령 옵션 확인

```bash
UV_CACHE_DIR=/tmp/uv-cache PYTHONPATH=src:src/card_benefit uv run --locked --no-sync python -m payment_card.file_pipeline.doc_index.cli --help
UV_CACHE_DIR=/tmp/uv-cache PYTHONPATH=src:src/card_benefit uv run --locked --no-sync python -m payment_card.file_pipeline.doc_index.batch --help
UV_CACHE_DIR=/tmp/uv-cache PYTHONPATH=src:src/card_benefit uv run --locked --no-sync python -m payment_card.file_pipeline.chunking.cli --help
UV_CACHE_DIR=/tmp/uv-cache PYTHONPATH=src:src/card_benefit uv run --locked --no-sync python -m payment_card.file_pipeline.extraction.cli --help
```

### 2. 표본과 실행 계획 만들기

`INDEX_CSV`는 문서 인덱스 CSV, `CHUNK_DIR`은 청크 JSON 디렉터리, `WORK_DIR`은 저장소 밖의 새 작업 디렉터리로 바꾼다. `MODEL_NAME`은 팀 실행 환경에서 정한다. `COUNT`는 양의 정수다.

```bash
INDEX_CSV="/path/to/documents.csv"
CHUNK_DIR="/path/to/chunks"
WORK_DIR="/tmp/card-benefit-assignment-run"
COUNT=10
MODEL_NAME="<MODEL_NAME>"
UV_CACHE_DIR=/tmp/uv-cache PYTHONPATH=src:src/card_benefit uv run --locked --no-sync python -m payment_card.file_pipeline.extraction.cli pilot-run --index-csv "$INDEX_CSV" --chunk-dir "$CHUNK_DIR" --work-dir "$WORK_DIR" --count "$COUNT" --model "$MODEL_NAME"
```

위 명령은 기본적으로 계획 모드이며 LLM을 부르지 않는다. 작업 계획은 `<WORK_DIR>/plan.json`에 기록된다. 실행 전 대상 문서·청크와 예상 입력 크기를 확인한다.

### 3. 추출과 자동 점검 실행

실제 LLM 호출은 팀이 승인한 환경에서만 수행한다. API 키는 기본 환경 변수 이름 `OPENAI_API_KEY`로 프로세스 환경에 제공하며 키 값은 문서화하지 않는다. 기존 작업 폴더를 재사용하지 말고 저장소 밖의 비어 있는 새 `<WORK_DIR>`를 사용한다.

```bash
INDEX_CSV="/path/to/documents.csv"
CHUNK_DIR="/path/to/chunks"
WORK_DIR="/tmp/card-benefit-assignment-run"
COUNT=10
MODEL_NAME="<MODEL_NAME>"
UV_CACHE_DIR=/tmp/uv-cache PYTHONPATH=src:src/card_benefit uv run --locked --no-sync python -m payment_card.file_pipeline.extraction.cli pilot-run --index-csv "$INDEX_CSV" --chunk-dir "$CHUNK_DIR" --work-dir "$WORK_DIR" --count "$COUNT" --model "$MODEL_NAME" --execute
```

실행 시 추출 결과와 요약, 자동 점검 결과, 그래프 CSV가 `<WORK_DIR>` 아래 생성된다. 코드 경로상 그래프 CSV 변환까지 이어지며 Neo4j Browser 접속·Cypher 실행은 별도 작업이다. 이 문서 작성 중에는 위 계획·추출 명령이나 Neo4j 적재를 실행하지 않았다.

### 4. Neo4j용 Cypher 생성 및 시각화

그래프 CSV 디렉터리를 `<WORK_DIR>/graph`로 가정한 생성 명령은 다음과 같다. 출력 파일도 저장소 밖에 둔다.

```bash
WORK_DIR="/tmp/card-benefit-assignment-run"
UV_CACHE_DIR=/tmp/uv-cache PYTHONPATH=src:src/card_benefit uv run --locked --no-sync python -m payment_card.file_pipeline.graph.cypher_export --csv-dir "$WORK_DIR/graph" --output "$WORK_DIR/load.cypher"
```

생성한 Cypher는 `MERGE` 기반 Neo4j Browser 입력용이다. 실제 Browser 연결·적재·시각화는 이 문서 작업에서 수행하지 않았다. 절차와 질의 예시는 [`graph/cypher/README.md`](../../card_benefit/payment_card/file_pipeline/graph/cypher/README.md) 및 [`queries.cypher`](../../card_benefit/payment_card/file_pipeline/graph/cypher/queries.cypher)를 참고한다.

## 현재 확인 상태와 한계

- 이 계약은 현재 저장소 코드와 README의 구조를 설명한다. 이 작업 중 PDF, LLM, DB, Neo4j를 실행하지 않았다.
- 저장소에는 이전 카드 문서 파일럿과 실행 이력이 있으나, 여기서는 해당 결과를 새로 검증하거나 정확도 수치로 일반화하지 않는다.
- `verify`와 집계 보고는 형식·위치·건수 등의 신호다. 원문에 대한 관계의 의미 정확성은 사람이 검토 표본을 정하고 대조 기록을 남겨야 한다.
- 추출 JSON의 엔티티 ID는 청크 안에서 쓰이며, 그래프 내보내기는 청크 ID를 붙여 전역 유일한 노드 ID를 구성한다. 출처 위치는 `doc_sha256`, `page_no`, `start_pos`, `end_pos` 및 근거 상태로 연결한다.
