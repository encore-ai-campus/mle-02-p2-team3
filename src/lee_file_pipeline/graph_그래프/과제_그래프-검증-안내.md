# 카드 혜택 그래프 검증·시연 안내

이 문서는 카드 상품설명서의 개체·관계 추출 결과를 검토하고, Neo4j 적재·조회·시연 결과를 기록하기 위한 제출용 안내와 빈 양식이다. 기존 추출·그래프 코드는 [`payment_card/file_pipeline`](../../card_benefit/payment_card/file_pipeline/README.md)에 있으며, 이 문서는 실행 코드를 복제하거나 기존 경로를 변경하지 않는다.

## 현재 구현과 확인 범위

- 추출 스키마는 `Benefit`, `Condition`, `Limit`, `Target`과 허용 관계를 정의한다. 그래프 내보내기에서 문서 인덱스의 상품 ID로 `Card` 노드를 만들고 `OFFERS`로 혜택에 연결한다.
- 그래프 CSV 내보내기와 Neo4j용 Cypher 생성기는 기존 `graph/export.py`, `graph/cypher_export.py`에 있다. Neo4j 생성 스크립트는 `Fp` 라벨, `FP_` 관계, 고유 제약과 `MERGE`를 사용한다.
- 기존 조회 예시는 [`queries.cypher`](../../card_benefit/payment_card/file_pipeline/graph/cypher/queries.cypher), Browser 적재 안내는 [`graph/cypher/README.md`](../../card_benefit/payment_card/file_pipeline/graph/cypher/README.md)에 있다.
- 작업 이력에는 **2026-11-06 사용자가 실행해 확인한 당시 결과**로 도메인 노드 12,144개, 데이터 관계 15,697개, 근거 노드 23,970개가 기록되어 있다. 같은 이력은 내보낸 근거 24,066행과 Neo4j 근거 노드 사이의 96개 차이를 원인 미확인으로 남긴다. ([적재 이력](../../../docs/작업이력/06-챗봇연결-골든셋/2026-11-06-PPT요구사항대조-Neo4j적재-README3개-laptop.md), [운영 런북](../../../docs/운영/그래프-런북.md#6-로컬-neo4j-시각화-전용))
- 위 수치는 과거 실행 기록이며 현재 DB 상태를 뜻하지 않는다. 이 안내 작성 과정에서 실제 DB·Neo4j Browser 접속, 재적재, Cypher 실행, 원문 대조, 결과 화면 캡처는 하지 않았다.

## M5 — 중복 개체 검토와 대표 ID 결정

먼저 동일 대상을 합칠지 사람이 검토한다. 대소문자나 띄어쓰기만으로 자동 병합하지 않는다. 특히 카드·혜택·대상은 이름이 비슷해도 별도 대상일 수 있으므로 문맥과 출처를 함께 확인한다. 승인된 연결만 대표 ID 매핑에 반영하고, 그래프 재적재·검색 적용 여부는 별도로 기록한다.

현재 `graph/entity_links.sql`은 초안이고, `entity_links_loader.py`는 연결 CSV 검증을 제공한다. 챗봇 서브그래프 병합은 검증된 연결을 사용하는 별도 기능이다. 이것만으로 추출 전체의 Entity Resolution 실행이나 과제 표본 검토가 끝났다고 보지 않는다.

승인된 판정 CSV를 Neo4j exporter 입력으로 적용하는 별도 도구 [`entity_resolution.py`](entity_resolution.py)를 준비했다. 이 도구는 표준 라이브러리만 사용하고 DB·LLM에 접속하지 않는다. 이 문서 작성 시점에는 실행하지 않았으며, 판정 결과도 만들지 않았다. 입력은 기존 그래프 CSV 네 개와 사람이 작성한 mapping CSV이고, 출력 CSV와 audit 폴더는 저장소 밖의 새 경로에 둔다.

mapping CSV 열은 아래 순서와 정확히 일치해야 한다. `merge`는 `within_card` + `SAME_AS_STRONG`만 허용하며, 같은 `group_id` 안에 canonical 행을 포함해 모든 member 행을 둔다. 예를 들어 canonical A와 alias B를 합치려면 A→A와 B→A 두 행을 만들고, 두 행에 같은 카드 범위·사유·근거 참조·검토자·일자를 기록한다. `keep`과 `defer`도 판정 이력으로 보존하며 ID를 바꾸지 않는다. `across_cards` + `SIMILAR`는 `card_scope_id=across_cards`로 관계 제안만 기록하고 병합하지 않는다. 모든 판정 행에는 사유·근거 참조·검토자·일자가 필요하다. `evidence_ref`에는 원문 인용 대신 문서/청크/페이지/위치 식별자만 적는다.

```csv
group_id,decision,scope,link_type,card_scope_id,canonical_node_id,member_node_id,reason_code,evidence_ref,reviewer,reviewed_at
example_01,merge,within_card,SAME_AS_STRONG,card:sample:001,node:A,node:A,표기변형,doc01/chunk03/p2/pos10-20,reviewer1,2026-11-09
example_01,merge,within_card,SAME_AS_STRONG,card:sample:001,node:A,node:B,표기변형,doc01/chunk03/p2/pos10-20,reviewer1,2026-11-09
```

이 예시는 형식 설명용이며 실제 개체 판정이 아니다. 도구는 동일 유형·카드 연결 집합·속성 호환성·endpoint·근거 대상을 확인하고, 중복 edge를 접으면 edge ID 대응표와 함께 관계 근거를 대표 edge로 다시 연결한다. 허용한 이름/표기 속성 외에 속성 차이가 있으면 병합을 거부한다. 이 검사만으로 사람의 의미 판정을 대체하지 않는다.

실행 시에는 입력 CSV 폴더와 mapping CSV를 보존하고, 새롭고 비어 있는 형제 출력/audit 경로 및 원본과 다른 M6 run ID를 지정한다. 현재 도구는 출력 경로를 저장소 밖으로 제한한다. 실행 후 audit의 `summary.csv`, `mapping_decisions.csv`, `node_mapping.csv`, `edge_mapping.csv`, `aliases.csv`, `output_manifest.csv`를 검토하고, 실제 M6 적재 전에 네 개 출력 CSV를 별도로 정적 검증한다.

```bash
INPUT_DIR="/tmp/card-benefit-run/graph"
MAPPING_CSV="/tmp/card-benefit-run/entity-mapping.csv"
OUTPUT_DIR="/tmp/card-benefit-run/normalized-graph"
AUDIT_DIR="/tmp/card-benefit-run/normalized-graph_audit"
M6_RUN_ID="card-benefit-m6-example-001"
PYTHONPATH=src:src/card_benefit .venv/bin/python -m lee_file_pipeline.graph_그래프.entity_resolution \
  --csv-dir "$INPUT_DIR" --mapping-csv "$MAPPING_CSV" \
  --output-dir "$OUTPUT_DIR" --audit-dir "$AUDIT_DIR" --m6-run-id "$M6_RUN_ID"
```

위 경로와 run ID는 명령 형식 예시다. 실제 실행 전에는 해당 외부 경로에 입력·판정 CSV가 있고 출력 경로가 비어 있는지 확인한다. `fp_load_runs.csv`의 `started_at`은 입력 exporter 시각을 보존하고, 변환 시각은 audit `summary.csv`의 `transformed_at_utc`에 기록한다.

|---|---|---|---|---|---|---|---|---|

## M6 — Neo4j 매핑과 적재

기존 그래프 계약을 사용한다. 카드 ID는 `card:<issuer>:<product_key>`이며, 상품 키는 인덱스의 `CD_ID`, `PC_SEQ`, `디자인코드`, `모바일_CD_NO`, `product_code` 중 값이 비어 있지 않은 첫 키 값이다. 추출 개체 ID는 `<chunk_id>:<추출 id>`, 추출 관계 ID는 `<chunk_id>:rel-<관계 순번>`, 카드 제공 관계 ID는 `<chunk_id>:offers-<product_key>:<혜택 id>` 형식이다. 관계 endpoint에는 개체 ID를 그대로 쓴다. 근거 CSV는 노드 근거에 `node_id`, 관계 근거에 `edge_id`를 하나씩 기록하고 문서 해시·쪽·위치·상태를 담는다. `quote_status`는 `located`, `ambiguous`, `missing`이며, 위치가 모호하거나 없으면 쪽·시작·끝 위치는 비어 있다. 아래 매핑과 규칙은 소스 코드에서 확인한 계약이다. 결과 칸의 `미확인`은 생성된 CSV·Cypher나 실제 DB에서 해당 항목을 검사하지 않았다는 뜻이다. 인용문 본문과 원문 청크는 저장소나 이 보고서에 복사하지 않는다.

| 개체/관계 | Neo4j 라벨/유형 | 방향 또는 식별 규칙 | 확인 결과 |
|---|---|---|---|
| Issuer | 현재 exporter가 발급사 노드를 생성하지 않음 (`cypher_export.py` importer 지원과 구분) | 현 파일 파이프라인 출력에는 미포함 | 해당 없음 |
| Card | `FpCard` | 상품 키 기반 ID | 미확인 |
| Benefit | `FpBenefit` | 청크 ID + 추출 ID | 미확인 |
| Condition | `FpCondition` | 청크 ID + 추출 ID | 미확인 |
| Limit | `FpLimit` | 청크 ID + 추출 ID | 미확인 |
| Target | `FpTarget` | 청크 ID + 추출 ID | 미확인 |
| Card → Benefit | `FP_OFFERS` | 카드가 혜택을 제공 | 미확인 |
| Benefit → Condition | `FP_HAS_CONDITION` | 혜택의 조건 | 미확인 |
| Benefit → Limit | `FP_HAS_LIMIT` | 혜택의 한도 | 미확인 |
| Benefit → Target | `FP_APPLIES_TO`, `FP_EXCLUDES` | 적용 또는 제외 대상 | 미확인 |
| Benefit → Benefit | `FP_MUTUALLY_EXCLUSIVE` | CSV source에서 target으로 생성. 의미상 대칭 관계로 탐색할 때는 기존 질의처럼 무방향 패턴 사용 | 미확인 |
| 노드 근거 | `FpEvidence` + `FP_HAS_EVIDENCE` | `node_id` 대상에서 Evidence 노드로 연결 (`(n)-[:FP_HAS_EVIDENCE]->(e)`) | 미확인 |
| 관계 근거 | `FpEvidence` | Evidence 노드의 `edge_id` 속성으로 관계 ID 기록; 관계에 `FP_HAS_EVIDENCE`를 붙이지 않음 | 미확인 |

### 실행 시 기록할 것

기존 안내에 따라 CSV와 생성 Cypher는 저장소 밖의 빈 출력 폴더에 둔다. 적재 전 로컬 Neo4j 대상과 기존 `Fp` 라벨을 확인하고, 결과를 새로 조회해 기록한다. `.env`, 비밀번호, 원문, 청크 본문은 출력·화면 캡처·제출 문서에 포함하지 않는다. 아래는 **실행 지침을 가리키는 예시 명령**이며 여기서 실행한 명령이 아니다.

```bash
CSV_DIR="/tmp/card-benefit-assignment-run/graph"
OUTPUT_CYPHER="/tmp/card-benefit-assignment-run/load.cypher"
UV_CACHE_DIR=/tmp/uv-cache PYTHONPATH=src:src/card_benefit \
  uv run --locked --no-sync python -m payment_card.file_pipeline.graph.cypher_export \
  --csv-dir "$CSV_DIR" --output "$OUTPUT_CYPHER" --lang ko
```

## M7 — Cypher 조회와 시각화

기존 질의 파일에는 라벨별 건수, 카드의 혜택·조건·한도·대상, 특정 대상에 적용되는 혜택, 모호한 근거, 관계 경로 탐색 예시가 있다. 아래 표에는 발표에서 선택한 질의만 적고, **실제로 실행한 결과와 화면 캡처 위치를 채운다.** 질의 파일에 예시가 있다는 사실은 현재 그래프에서 결과가 확인됐다는 뜻이 아니다.

매개변수 기반 Q1 카드→혜택, Q2 대상→혜택/카드, Q3 근거 위치 템플릿은 [`M7 질의 템플릿`](M7_질의-템플릿.cypher)을 참조한다. 템플릿은 예시이며 Neo4j에서 실행한 결과가 아니다. 실제 실행 시 각 노드·관계의 `run_id`가 선택한 M6 import ID와 일치하는지 확인한다. 단, 현재 exporter는 `FpEvidence` 노드에 `run_id`를 저장하지 않는다. 따라서 Q3는 endpoint가 선택 run에 속하는지는 검사하지만 evidence 자체를 run별로 완전히 격리하지 못하며, 서로 다른 run에서 재사용되는 ID가 있으면 과거 evidence가 함께 반환될 가능성이 있다. M7 결과를 M8 근거로 쓰기 전에 외부 CSV/audit의 문서 해시·위치와 대조한다.

| run ID | 실행 시각·시간대 | 질문 | Cypher 파일의 절/질의 | 실행 결과 요약(원문 문구 없이) | 관계·방향 해석 | 화면 캡처 위치 | 실행 여부 |
|---|---|---|---|---|---|---|---|
|  |  | 카드의 혜택과 연결된 조건·한도·대상은 무엇인가? | `M7_질의-템플릿.cypher` Q1 |  |  |  | 미실행 |
|  |  | 특정 대상과 연결되거나 제외되는 혜택은 무엇인가? | `M7_질의-템플릿.cypher` Q2 |  |  |  | 미실행 |
|  |  | 개체 또는 관계의 근거 위치는 무엇인가? | `M7_질의-템플릿.cypher` Q3a/Q3b |  |  |  | 미실행 |

기존 `queries.cypher` 5번은 모호한 근거 예시이며 위치 필드를 반환하지 않는다. 위치 추적 시에는 `M7_질의-템플릿.cypher`의 Q3a/Q3b를 사용한다. 이 템플릿도 실제 Neo4j에서 실행한 결과는 아니다.

캡처 전에는 Browser의 이전 결과가 화면에 남아 있지 않은지 확인하고, 질의를 다시 실행해 결과를 갱신한다. 캡처에는 비밀번호, 접속 주소의 비밀 부분, 원문 인용문, 청크 본문을 넣지 않는다.

## M8 — 원문·트리플·그래프 수동 대조
