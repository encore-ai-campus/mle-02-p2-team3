# 카드 혜택 개체·관계 추출 과제: 산출물 현황과 진행계획

작성 기준: 2026-11-09 저장소 로컬 작업 트리와 기존 문서·코드 검토. 팀이 확인한 카드 상품 설명서 도메인을 사용한다. 기존 실행 코드는 `src/card_benefit/payment_card/file_pipeline/`에 유지하고, 이 폴더에는 강사 제출용 설명·검토표·합성 예시만 추가한다.

## 범위와 근거 원칙

- 개체 모델은 기존 혜택·조건·한도·대상 추출 스키마를 사용한다. 카드 개체와 카드-혜택 `OFFERS`는 그래프 조립 단계에서 추가된다.
- 출처 코드와 기존 문서는 링크로 참조한다. 기존 `file_pipeline` 파일을 복사·이동·수정하지 않는다.
- 원문 PDF, 청크 텍스트, 근거 인용문, 실제 추출 결과 파일은 저장소에 넣지 않는다. 공유 가능한 문서 메타데이터, 건수, 합성 예시, 빈 검토 양식만 보관한다.
- 실제 LLM 실행, DB 접속, Neo4j Browser 확인, 브라우저 시연을 하지 않은 경우 결과를 만들어내지 않고 미확인으로 표시한다.
- 작업 대상은 이 폴더 안의 새 산출물이다. 기존 README·STATUS 및 다른 작업 파일의 미커밋 변경을 덮어쓰지 않는다.

## 작업 순서와 담당

세부 실행 순서·담당·선행조건·완료 증거는 [`부분 완료 전환 실행계획`](부분완료_완료전환_실행계획.md)을 따른다.

1. **산출물 지도와 상태 기록** — 이 문서. 완료/부분/미확인을 증거 위치와 함께 구분한다.
2. **M0–M4 추출 계약 설명** — [`extraction_혜택추출/과제_추출-계약.md`](extraction_혜택추출/과제_추출-계약.md). 기존 스키마와 실행 코드를 참조하고 제출에 필요한 입력·출력·근거 계약을 설명한다.
   - M1 합성 전처리 예시와 팀 기록란: [`과제_전처리-예시.md`](extraction_혜택추출/과제_전처리-예시.md)
   - M4 실제 실행 재현·집계 기록란: [`과제_실행-재현-기록.md`](extraction_혜택추출/과제_실행-재현-기록.md)
3. **M5–M9 그래프·검증 안내** — [`graph_그래프/과제_그래프-검증-안내.md`](graph_그래프/과제_그래프-검증-안내.md). 정규화 검토, Neo4j 적재, 대표 질의, 원문 대조, 시연·회고를 위한 빈 양식을 제공한다.
4. **사람 실행 항목 채우기** — 실제 문서 메타데이터와 팀 검토 결과, Neo4j 실행 결과·캡처, 팀 역할·KPT는 실제 담당자가 확인한 사실로 작성한다.

## 완료 조건

- 필수 산출물 ① 실제 프롬프트·추출 코드·출력 예시·실행 안내가 서로 연결되어 있다.
- 필수 산출물 ② 스키마·정규화 사례·Neo4j 매핑/적재 절차·Cypher·시각화·원문 대조 기록이 연결되어 있다.
- 각 M0–M9 행에 제출물 링크와 근거 수준이 있으며 미확인 항목은 완료로 표시하지 않는다.
- 추출 정확도 수치는 정답 표본, 분모, 판정 기준과 계산 방법이 기록된 경우에만 제시한다.

## 현재 진행 제한

이 실행에서 테스트, LLM 호출, 실제 DB/Neo4j 접속, Streamlit/브라우저 실행을 하지 않았다. 따라서 실제 문서 추출, 사람의 정규화 판정, 그래프 적재·시각화 캡처, 팀 KPT는 이후 실행자가 채워야 한다. 저장소의 기존 테스트 기록과 과거 적재 기록은 참고 근거이지 현재 환경 재실행 결과가 아니다.
