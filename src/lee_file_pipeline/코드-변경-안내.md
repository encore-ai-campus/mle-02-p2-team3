# 코드 변경 안내

강사 검토용 **대표 변경 선별 지도**다. [README](README.md)는 전체 흐름과 소유 범위, [STATUS](STATUS.md)는 시점별 현황을 맡는다. 아래의 “테스트”는 연결된 검사 위치를 뜻하며, **이 안내를 작성하면서 테스트를 실행했다는 뜻은 아니다.** 현재 폴더는 Git 미추적 상태다.

바로가기: [작성한 점검 도구](#1-이-폴더에서-작성한-점검-도구) · [기존 경로 수정](#2-기존-파이프라인-경로의-로컬-수정) · [관찰·제안·참고 경로](#3-관찰된-동작과-아직-제안인-것). 표의 테스트 이름은 대표 항목만 골랐다.

## 먼저 볼 대표 변경

아래 다섯 항목은 강사 검토를 시작하기 위한 선택 사례다. 각 테스트 이름은 검사 위치이며, 실행 결과는 [현황판](STATUS.md#강사-검토용-현재-검증-요약) 또는 연결한 작업 기록에서 확인한다. 이 문서의 코드·테스트 설명만으로 테스트 실행이나 실제 서비스 정확성을 주장하지 않는다.

1. **추출 이어하기와 저장 보호:** [`extraction/batch.py`](../card_benefit/payment_card/file_pipeline/extraction/batch.py)의 `_resume_metadata`, `_result_digest`, `_locked_output`이 잘못된 재사용·동시 쓰기·부분 저장을 막도록 보강됐다. [`test_file_pipeline_extraction_batch.py`](../card_benefit/payment_card/tests/test_file_pipeline_extraction_batch.py)의 `test_resume_rejects_changed_result_contents_and_preserves_file`, `test_output_directory_lock_prevents_concurrent_batch`를 본다. 기록된 `478 passed + 4 subtests`는 넓은 과거 선택 범위이며 이 변경만의 결과는 아니다.
2. **관계 병합 뒤 근거 재연결:** [`entity_dedupe.py`](../card_benefit/payment_card/file_pipeline/chat/retrieval/entity_dedupe.py)의 `dedupe_subgraph`가 제거되는 관계의 근거를 대표 ID에 연결하고 자기 연결 근거는 별도 보존한다. [`test_evidence_audit.py`](tests_테스트/test_evidence_audit.py)의 `test_duplicate_edge_evidence_should_reference_surviving_edge`, `test_self_loop_evidence_should_be_retained_separately`와 [합성 전후 기록](docs_작업기록/관계-근거-연결-검토.md)을 확인한다. 기록된 `20 passed`, `500 passed + 4 subtests`는 당시의 합성·선택 테스트 범위다.
3. **챗봇 자료와 화면 표시:** [`app_v2.py`](../card_benefit/payment_card/file_pipeline/chat/ui/app_v2.py)의 `_display_evidence`와 [`ui_v2.py`](../card_benefit/payment_card/file_pipeline/chat/ui/ui_v2.py)의 `collect_sources`, `build_compare_table`이 선택적 문서·쪽 표시와 카드별 혜택 표를 구성한다. [`test_chat_graph_display.py`](tests_테스트/test_chat_graph_display.py)의 `test_chat_ui_displays_document_pages_from_opt_in_evidence_query`, `test_two_cards_with_same_benefit_name_keep_their_conditions_separate`를 확인한다. [자료 표시 검토 기록](docs_작업기록/챗봇_자료_관계도_검토.md)과 기록된 `29 passed`, `509 passed + 4 subtests`, UI 질문 카드 `17 passed`를 참고한다. 이 시험은 합성·모의 범위이며 실제 DB·브라우저 답변 검증이 아니다.
4. **그래프 CSV 내보내기:** [`graph/export.py`](../card_benefit/payment_card/file_pipeline/graph/export.py)의 `export_files`는 문서 인덱스에 카드가 둘 이상 연결되면 추출 혜택에 카드별 `OFFERS` 후보를 만든다. [`test_file_pipeline_graph_export.py`](../card_benefit/payment_card/tests/test_file_pipeline_graph_export.py)의 `test_shared_document_creates_offers_for_each_indexed_card_without_edge_evidence`와 [다중 카드 문서 관계 검토](docs_작업기록/챗봇_결함_분석.md)를 확인한다. 이 검사는 합성 입력의 동작을 보여주며, 생성된 후보 관계가 실제 카드별 혜택 적용을 증명하지는 않는다.
5. **추가 점검 도구:** [`evidence_audit.py`](evidence_audit.py)의 `audit_graph`, `group_source_refs`, `preview_offer_reviews`와 [`defect_repro.py`](defect_repro.py)의 합성 관찰을 본다. [테스트](tests_테스트/test_evidence_audit.py)는 ID 참조와 위치 필드 모양을 검사한다. 도구의 `review_recorded`는 기록 형식이 맞다는 뜻이지 카드별 적용 확인이 아니다.

테스트 수치는 날짜와 실행 범위가 다른 과거 기록이라 서로 합산하지 않는다. 기준 커밋과 현재 작업 트리의 전달 문제는 [현황판](STATUS.md)의 Git 인계 상태를 참고한다.

## 2. 기존 파이프라인 경로의 로컬 수정

아래 구현은 `lee_file_pipeline` 안으로 옮긴 코드가 아니다. 링크의 기존 경로에서 확인할 수 있다.

### 추출 실행과 결과 파일 보호

- [`extraction/batch.py`](../card_benefit/payment_card/file_pipeline/extraction/batch.py): 이어하기 전에 문서·청크 위치, 프롬프트·모델 문맥, 저장 결과 지문과 필드 모양을 확인한다. 검증할 수 없는 구형·손상 결과는 덮어쓰지 않고 중단한다. 배치·요약 파일에는 잠금과 임시 파일 교체를 적용한다. 관련 회귀 검사는 [`test_file_pipeline_extraction_batch.py`](../card_benefit/payment_card/tests/test_file_pipeline_extraction_batch.py)의 `test_resume_rejects_changed_result_contents_and_preserves_file`, `test_resume_rejects_changed_model_or_prompt_without_overwriting`, `test_output_directory_lock_prevents_concurrent_batch`, `test_failed_replace_preserves_existing_summary` 등이다. 기존 메타데이터가 없는 결과는 이어하기가 거부될 수 있고, 잠금에 참여하지 않는 다른 프로그램의 쓰기까지 막지는 않는다.
- [`extraction/llm_adapter.py`](../card_benefit/payment_card/file_pipeline/extraction/llm_adapter.py)와 [`extraction/parallel.py`](../card_benefit/payment_card/file_pipeline/extraction/parallel.py): 기본 LLM 호출에 60초 제한과 추가 재시도 0회를 전달하고, 재시도 불가 오류를 더 시도하지 않도록 한다. 기본 호출 경로의 비밀값 없는 재개 문맥은 [`test_file_pipeline_extraction_cli.py`](../card_benefit/payment_card/tests/test_file_pipeline_extraction_cli.py)의 `test_default_adapter_exposes_nonsecret_resume_context`로 확인하도록 했다. 주입된 호출 팩터리에는 재개 문맥이 없을 수 있고, `retryable` 분기를 직접 고정하는 전용 회귀 검사는 diff에서 확인하지 못했다.
- [`extraction/pilot_run.py`](../card_benefit/payment_card/file_pipeline/extraction/pilot_run.py): 파일럿 시작 전에 기존 그래프 출력 폴더가 비어 있는지 검사해, 출력 충돌을 모델 클라이언트 생성이나 추출보다 먼저 알린다. [`test_file_pipeline_extraction_parallel_verify.py`](../card_benefit/payment_card/tests/test_file_pipeline_extraction_parallel_verify.py)의 `test_execute_rejects_existing_graph_before_client_or_result_changes`가 이 순서를 검사한다. 검사 뒤 다른 프로세스가 폴더를 바꾸는 경쟁 상황까지 해결하지는 않는다.
- [`extraction/prompt.py`](../card_benefit/payment_card/file_pipeline/extraction/prompt.py): `EXCLUDE` 의미를 지난달 실적 제외 조건과 혜택 제외 가맹점 구분이 분명하도록 보완했다. 이번 diff에서는 이 규칙을 직접 검사하는 전용 테스트를 확인하지 못했다.

**근거 해석:** 위 테스트는 합성 입력·모의 DB·모의 Streamlit 범위다. 직접 테스트가 없는 변경은 코드 확인으로 표시했다. 실제 PDF 정확도, DB/API 연결, 브라우저 화면, 카드별 혜택 적용은 이 안내의 근거로 판정하지 않는다.
